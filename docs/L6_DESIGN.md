# L6 设计：空海浏览器（云操作系统 · 用户交互层）DESIGN v1.0

> 状态：**v1.0（2026-09-10）** ｜ 版本：本设计提交 → **v0.086**（git 计数自动）
> 依据：发起人方向指令——L6 = 用户直接面对的部分、云操作系统的"外显形象"；
> 目标：**用户打开空海浏览器，直接看到诊断结论，语言自动适配，无需任何操作**。
> 前置已固化：L5 已产出 schema 2 诊断 JSON（含 `summary.{universal,hardware,software,plant,animal,
> geology,tcm,user}` 八语言字段）+ 真实采集验证通过；网关 `/v1/probe` 存最新采集、静态提供
> cloud-probe/cloud-discover/run-probe.bat 下载；现有 manifest-ui（WASM 前端）为可复用资产。

## 1. 定位与设计原则

- **L6 = 云操作系统的面客端**：把 L4/L5 的判定与号脉结果直接呈现在用户面前；不是诊断的
  生产者（审计不重判），而是**呈现者与入口**。
- 打开即见：无需操作就能看到"最近一次号脉结论 + 场域状态"；未采集时给出**一步引导**。
- 语言自动适配：浏览器语言 → 自动选择 `summary.<lang>` 呈现；用户可手动切换。
- 输入两个口：①设备意图（继续支撑显化演示链路）②发现/采集入口（驱动 cloud-probe 回传闭环）。
- 界面哲学沿用项目约定：**极简**（上=状态带，中=诊断呈现，下=操作台），能力在后台。

## 2. 模块划分（落点 manifest-ui / L6 改造 + npb wasm 绑定）

| 模块 | 职责 | 输入 → 输出 |
|---|---|---|
| `npb` wasm 绑定（新增导出） | `l5_diagnose(s7: Float64Array) -> String`（调 meta-kernel-core l5 链，schema 2 JSON） | 场域 s[7] → 诊断 JSON |
| `l6_app.rs`（前端根） | 应用状态：网关地址、语言、最近诊断、采集时间；轮询 /v1/probe | — |
| `l6_views.rs` | 视图切换与渲染：诊断台 / 显化台 / 设备台 / 设置 | 状态 → DOM |
| `l6_i18n.rs` | 语言自动适配：UI 文案字典 + summary 语言映射 | lang → 文案/键 |
| `l6_render.rs` | 诊断 JSON 呈现：四场亢枯平、标题/成因/溯源、多语言正文 | Diagnosis JSON → 视图 |
| `l6_discover.rs` | 设备发现交互：下载引导、run-probe 一步引导、最近采集展示 | — |
| index.html/css | 骨架与样式（极简卡片布局） | — |

## 3. 界面结构（信息架构）

```
┌ 顶部状态带：网关 ●在线/○离线 ｜ 最近采集 时:分 ｜ 语言 [自动·中文·English…] ─┐
├ 主视图（默认=诊断台）──────────────────────────────────────┤
│  最新号脉卡                                        │
│    四场仪表：地◼ 水◼ 火◼ 风◼（平=中性 / 亢=暖色 / 枯=冷色）│
│    主结论 title（所选语言）                          │
│    description · cause（补充增量）                   │
│    溯源：对象/时间/可复现 ✓（小字）                   │
│  （无数据态：☝ 请先采集——[下载探针到本机] 一键指引）     │
├ 下操作台 ───────────────────────────────────────────┤
│  [重新采集/上报] [发现设备] [写一条念头（显化演示）] [设置] │
└────────────────────────────────────────────────────┘
```

- 视图：**诊断台（默认）** / 显化台（L1-L3 意图演示，现 manifest-ui 主体保留）/ 设备台（发现/采集引导）/ 设置（网关地址、知识库 URL、语言覆盖）。
- 语言自动：UI 文案 `zh-CN`/`en` 字典；诊断正文取 `summary` 映射：`zh*→user`（用户通用最贴切，tcm 次选供中医兴趣）、`en*→universal`；其余语言回退 `universal`；手动覆盖存 localStorage。

## 4. 数据流与接口

```
空海浏览器（WASM）
   │ ① 轮询/按钮 GET http://<gw>:3000/v1/probe ──▶ 网关（最新采集 JSON）
   │ ② 有数据 s[7] → npb.l5_diagnose(s) ──▶ 本地 L4/L5 链 → schema2 JSON（即时诊断，无后端计算）
   │ ③ 渲染诊断卡（l6_render 按语言取 summary.<lang>）
   │ ④ 无数据 → 引导：打开 http://<gw>:3000/run-probe.bat 下载（目标机）或本机运行 cloud-probe --report
   │ ⑤ 设置：网关地址默认 auto（同源=当前页 host；跨机可填 192.168.1.x:3000）
```

- 网关地址同源默认（空海浏览器由网关托管时 `/v1/probe` 直接相对路径）；L6 前端不做任何判定（不重判），只呈现 L5 结果 + 时间戳。
- 绑定导出（`npb` cdylib wasm）：新增 `l5_diagnose`/`l5_diagnose_json_free`（沿用现有手写绑定风格）；native 侧同函数复用（测试）。

## 5. 诊断呈现规范（尊重 L5 戒律语义）

| L5 输出 | L6 呈现 |
|---|---|
| pattern（四场 亢/枯/平） | 四场色块/仪表：平=灰绿中性、亢=暖红、枯=冷蓝；文字标注（如 "亢"） |
| conclusion.title/description/cause | 主标题 + 说明 + "成因（补充增量）"小段——**一因一果单条呈现**（不并列多因猜测） |
| summary.<lang> | 按语言字段整段展示（优先于 title 的场语言原语） |
| trace | 底部小字溯源（对象/时间/reproducible），**可复现**语义标注 ✓ |
| source | 显示 builtin/external 来源标记 |

- L6 不加工：不新增解释、不改写结论文本（原文零修改精神）。

## 6. 设备发现交互（L6 层）

- 设备台：说明 + 三步卡片（1) 目标机开机联网 2) 目标机打开 `http://<本机IP>:3000/run-probe.bat` 下载并双击 3) 本页自动显示结果）。
- 展示本机网关地址（供目标机下载）；"刷新"拉取 /v1/probe 时间戳。
- 可选：`cloud-discover` 输出 JSON 可粘贴上传至本页（粘贴区）→ 渲染在线设备列表（引导其采集）——免命令行查看。

## 8. 戒律与边界

- **不重判**：L6 只呈现 L5 结论（审计在 L4/L5，界面不判）。
- **诊断即展示**：L6 从"当前采集"即时渲染；历史归档/缓存属二期（尊重 L5"诊断数据不缓存"精神——界面仅保留最近一次 + 前端轮询即时性）。
- 不引入第三方（延续零依赖：手写 DOM/事件风格沿用 manifest-ui 既有实现）。

## 9. 实现顺序（后续按指令推进）

1. npb wasm 绑定导出 `l5_diagnose`（native 单测 + wasm 冒烟）；
2. L6 视图骨架 + i18n（zh/en 文案、summary 映射）；
3. 诊断渲染卡（四场+结论+trace）；
4. 无数据引导与设备台；
5. 网关同源/跨机轮询（设置）；
6. 目验（Edge）+ 用例 V1-V6 + 打包整合一键包。
