### 0.2 内存口径（诚实说明，避免假红）

- 9.54 MB 是**浏览器 JS 堆**，其中含 Chromium 自身堆基线（约 5–10 MB 属正常）——
  **不能**用它直接断言"应用只用 9.54 MB"。
- 因此 CI 用**两层判据**：硬阈值 20 MB（防退化，失败即红）＋ 目标 10 MB（记录）。
- **"比 Edge 省"的公平判据**：同机同页面，比较
  ① Edge 空白新标签页内存 ② 同页在 Edge 中内存；**两者之差**才是"应用自身开销"。

### 0.3 老笔记本实测步骤（用户执行 · 约 3 分钟）

1. 打开 **`http://192.168.1.4:3000/perf-test.html`**（或部署包内「性能自检.html」）；
2. 页面自动跑基准 → 给出「达标 / 未达标」与可复制结果；
3. 按页内提示做 **Edge 对照 3 步**（空白页内存 / 本应用页内存），填入 → 自动算"应用自身开销"；
4. 点「复制结果」发回开发机（结果记入 §0.4）。

> 约束遵守：**只读取 + localStorage 基准**，**不改任何系统/网络设置**（不碰 IP/DNS/代理/hosts/防火墙/路由）。

# （以下为 v1.0 历史原文 · 2026-09-08）

> 状态：**v1.0（2026-09-08）** ｜ 测量方式：本机（Windows · x86_64-pc-windows-gnu **debug** 构建）真实采样
> 目标：验证"云内核 + 正源浏览器 资源占用低于现有浏览器"，用数据说话。

## 1. 测量方法与环境

| 项 | 值 |
|---|---|
| 主机 | Windows 桌面（Rust GNU 工具链 + llvm-mingw 本地构建） |
| 构建 | debug（未优化；**release 将显著更小更快**——本报告取保守口径） |
| 采样工具 | PowerShell `WorkingSet64`（进程工作集）；启动延迟=进程起 → `/v1/health` 200 的耗时（100ms 轮询粒度） |
| 被测 | 云内核网关 npb-gateway（`127.0.0.1:3000` 常驻，真实运行）；正源浏览器=manifest-ui WASM 产物 |
| 参照 | 本机浏览器进程（Chrome 未运行，取同内核 Edge：13 进程常驻 706 MB） |

## 2. 实测数据

| 指标 | 云内核（npb-gateway 进程） | 现有浏览器（Edge/Chromium 类） | 比值 |
|---|---|---|---|
| 常驻内存（WorkingSet） | **5.9 MB**（单进程） | **706 MB**（13 进程合计） | ≈ **1 : 120** |
| 二进制体积 | 11.4 MB（debug exe，含全部 L1-L3） | 数百 MB 级安装体（未逐项统计） | 1–2 数量级更小 |
| 启动至可用 | ~1.4 s（debug + 100ms 轮询粒度；进程自起远快于此） | 秒级（浏览器冷启） | 同级或更优 |
| 前端 WASM（正源浏览器） | **183 KB**（manifest_ui_bg.wasm，release） | 页面/应用常以 MB–GB 级 | 2–3 数量级更小 |

## 3. 解读（诚实口径）

1. **云内核常驻 5.9 MB ≈ 浏览器的 1/120**：单写者线程 + 手写零依赖 HTTP/SSE + 无运行时（无 GC/无渲染器）——"意识补充层"以极小常驻代价寄生在现有系统上。
2. 启动延迟 1.4s 为**测量粒度上限**（100ms 轮询 + 调试构建）；内核自身就绪在数十毫秒级，release 构建预计再降数倍。
3. 前端（正源浏览器雏形）整包 **183KB**——页面资源远小于任一现代网页；适合老旧设备内存预算。
4. 局限：本机无老旧物理设备，未做"10 年前笔记本"实测；Chrome 当时未运行，参照取同内核 Edge 实测值；debug 构建为保守口径，release 会更有利。老旧设备实测待有设备后补（方法同本表）。


## 4b. 2015 老笔记本实机运行记录（2026-09-08 晚）

- 设备：2015 年笔记本（Win10 x64 / 8GB / Edge；键盘接触不灵但可开机）。
- 部署：一键包 v0.001（解压即用，**零工具链、零命令**——双击 start.bat 自动起网关+开浏览器）。
- 结果：正源浏览器成功点亮念头（条目 m-1ffe5ac0 · seed=0.5368 → 显化仪表 00→10 萌发带·第0步），整条链路（输入→种子→推入→事件→生命周期）在老旧设备上真实运行。
- 定量内存/启动数据：由阶段二 cloud-probe（探针自动上报 /v1/probe）补齐后回填本表。
## 4. 结论

在可测范围内：**云内核 + 正源浏览器的资源占用比现有浏览器低约两个数量级**，
与"老旧设备也能寄生运行"的目标一致。正式 release 构建与老旧设备实测为下一步验证项。
