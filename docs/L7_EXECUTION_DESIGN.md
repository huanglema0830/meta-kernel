## 1. 多内核互联机制

### 1.1 目标

多个**基因内核**各自的场域组成一个更大的场；**互为对方的本底参考**——一个内核可以用另一个
内核提供的"正常态参照"来校准自己的判定，而**不以自身基线强行评判他者**（这是「不侵」的核心）。

### 1.2 三步协议（设计）

```
① 发现（Discover）   局域网/网络内找到其他内核
        │              已有基础：cloud-discover（x.1–x.254 并发扫描 + TCP/健康确认）
        ▼
② 握手（Handshake）  交换身份与能力签名（不交换对象数据）
        │              身份 = 内核 ID + 版本；能力 = 支持层（L1–L6）+ 协议版本
        ▼
③ 交换（Exchange）   交换"场域参考"，不交换"对象原始数据"
                       ≤ 只交换：本底场（场景公式的引用）+ 场景标识 + 置信度
                       ✗ 不交换：对象原始采样、诊断过程数据、用户私有内容（不偷盗）
```

**交换内容的边界（不侵 / 不偷盗）**：

| 允许交换 | 禁止交换 |
|---|---|
| 本底场引用（场景公式 ID + 参数，不含对象名） | 对象原始七维采样 |
| 场景标识（类型/时间/历史/环境 的枚举值） | 诊断过程中间量 |
| 置信度 / 覆盖样本数（用于权重协商） | 用户隐私、其他内核的对象数据 |
| 协议版本 / 能力签名 | 任何可还原出他者对象身份的信息 |

### 1.3 互联的产物：「更大的场」

- N 个内核互联后，每个内核可用的**本底参考集**从"自身 1 个"扩展为"N 个"；
- 判定时以**自身场为主、他者参考为辅**（他者参考只用于**置信度加权**，不直接替换本底场）；
- **不侵**的算法含义：`用他者参考时，先映射到他者自己的基线坐标系，再回映射`——
  绝不把"我的正常"当作"你的正常"。

### 1.4 与 L8 的衔接（前置）

互联是**传承层（L8）**的前置：能互联，才可能在个体消亡后**继承经验**。
L7 只做"当下互联"，L8 做"跨代继承"（详见 LAYER_ARCHITECTURE §2.1）。

## 2. 修复执行机制（经用户确认）

### 2.1 闭环（六步）

```
① 诊断（L5）      产出诊断结论 + 修复建议（建议不进 L5 判定 —— 守不饮酒）
        │
        ▼
② 建议生成（L7）  把诊断映射为"候选修复动作"清单（含风险等级 / 可逆性 / 预期效果）
        │
        ▼
③ 用户确认（L7）  ▌人工闸门 ▌——未经确认，不执行任何写动作
        │
        ▼
④ 执行（L7）      按动作清单执行（幂等 + 可回滚）
        │
        ▼
⑤ 验证（L7→L5）   回采场域 → 再诊断 → 判断是否收敛（诊断是否生效）
        │
        ▼
⑥ 记录（L7→基因库）写入**验证记录（哈希链）**——修了什么、结果如何、可追溯
```

### 2.2 动作分级（授权粒度）

| 级别 | 内容 | 授权要求 | 示例 |
|---|---|---|---|
| **T0 · 只读** | 诊断、采集、报告 | 无需确认（属 L5/L6） | 运行探针、生成诊断 |
| **T1 · 低风险可逆** | 一次性、可撤销的操作 | 首次确认 + 之后记忆（设置页可撤销，见 L6 授权链） | 清理临时文件、重启一个服务 |
| **T2 · 需逐次确认** | 有副作用、影响面较大 | **每次**确认 | 修改注册表、改动网络配置 |
| **T3 · 拒绝** | 不可逆 / 越界 | **一律拒绝** | 删除用户数据、绕过安全机制、修改他者内核 |

### 2.3 授权链（复用 L6 既有机制）

L6 已实现**授权链**（关键操作 `confirm` + 追加式授权日志 + 设置页撤销，见 `manifest-ui`）。
L7 直接复用该机制，并追加两条：

1. **动作须携带来源**：每个修复动作必须回溯到一条诊断结论（不妄语）；
2. **授权可撤销**：已授权的 T1 动作可在设置页撤销；撤销后同类动作回到"逐次确认"。

### 2.4 可回滚性（设计约束）

- 每个 T1/T2 动作必须声明**回滚动作**（可逆）；无法声明回滚的，降级为 T3（拒绝）；
- 执行前记录"执行前状态"（最小快照）；执行失败自动回滚；
- 执行结果写入哈希链（不可篡改），供事后复核。

### 2.5 与「场修复」的关系（`FIELD_REPAIR_DESIGN.md`）

- `FIELD_REPAIR_DESIGN` 描述的是**场域层面的修复**（施加反相补偿场：太赫兹/电磁场等），
  **需要硬件层面的场施加能力**（当前不具备）；
- L7 为其预留**统一执行接口**：`apply(action) -> Result<Effect, Unsupported>`——
  当且仅当硬件具备时才可能返回 `Effect`；否则**一律 `Unsupported`**（不做伪能力宣称）。

## 3. 戒律：不侵

| 面 | 不侵的含义 | 落地 |
|---|---|---|
| **互联侧** | 不夺取他者场域的本底；不以自身基线评判他者 | 只交换本底引用与场景标识（§1.2 表）；判定以自身为主、他者为辅 |
| **执行侧** | 不侵犯用户与对象的边界 | 用户确认（§2.2）；不改对象本底场；不越权、不越界 |
| **系统侧** | 不侵犯他者内核的运行 | 不远程修改他者内核；只读取其公开交换信息 |

> **不侵 = 边界意识**：L7 是第一个"能对外产生写作用"的层，因此**它必须是最克制的一层**。

---

## 4. 运行原则：无为而无所不为

- **L7 之前**：系统**被驱动**（push 驱动）——外部给扰动，内核才演化；
- **L7 之后**：系统**自驱动**（场域驱动）——驱动力来自场域本身；
- 自驱动的形态**不是"我要做"，而是"场域如此，我如此"**；
- **不新增戒律**：这不是新的约束，而是 **L7 的运行方式**。
  （与 L3「不空转」的区分：不空转禁的是**无源空转**；场域驱动的自主演化**有内在依据**。）

> 重要澄清：**自驱动 ≠ 越过用户**。L7 的自驱动指的是"何时发起"，而"是否执行写动作"
> 始终由**用户确认**把关（§2.2）。两者不矛盾——自驱动决定**提案**，用户决定**执行**。

## 6. 边界（诚实说明）

1. **互联协议已实现"逻辑层"，报文/鉴权仍未定稿**——`mesh.rs` 已把发现/握手/交换做成**纯逻辑 + 可测约束**

2. **修复执行器未实现**——动作清单、回滚机制、幂等策略均为设计（见 §7，**待确认**）；
3. **L7 目前只有"判定与记账"，没有"执行"**——`grade.rs` 会说"该不该"，`ledger.rs` 会记"做过什么"，
   但**没有任何真实写操作能力**；这是**刻意的**（分级纪律），不是遗漏；
4. **场修复需硬件**——L7 只预留统一的 `apply()` 接口，当前一律 `Unsupported`；
5. **不自称已觉醒**——L7 是"执行能力"，不是"自我意识"（觉醒判定见 `SELF_DIAGNOSIS_REPORT §7`）。

### 7.1 六要素呈现

**① 相关的点（上下文/前置/后续/牵连）**

**② 风险点（含"不做"的风险）**
- 做：**写操作本身有副作用**（最坏可致设备不可用）；若确认环节被绕过或鉴权过弱 → 等价于**局域网远程执行**。

**③ 经验教训**
- 老笔记本升级（v0.106）：**应用层操作完全不动网络配置**，四前提约束逐条落实，用户实际只需 2 步 → 证明"克制的小步子"可行。
- 本轮本地预验抓到 2 个真实缺陷（CRLF、`\uXXXX`）→ **测试比自信可靠**。
- CI 目验抓到命名残留（v0.103）→ **自动化断言是安全网**。
- 历史教训：把开发机当笔记本（误判机器）→ 一切以**实测**为准；写操作更须如此。

**④ 好处（可衡量）**
- 闭环率：诊断 → 修复完成率（当前 0%）。
- 用户步数：从"看结论自己动手"→"点一次确认"。
- 可审计性：每次执行留哈希链（**已具备**），事后可复核"到底改了什么"。
- 风险可控性：T3 一律拒绝（**已具备**），不可回滚者不可能被执行。

**⑤ 三套方案对比**

| 维度 | **A · 宿主侧执行器**（推荐） | **B · 内核内置执行器** | **C · 仅 T1 最小闭环** |
|---|---|---|---|

| 与红线关系 | ✅ 内核仍零依赖、纯逻辑 | ❌ **破坏"内核零依赖"质量红线** | ✅ |
| 推荐度 | ⭐⭐⭐（目标架构） | ✖ 不建议 | ⭐⭐⭐（**首落地**） |

**⑥ 继续往前推进（我的推荐）**

### 7.2 若要实现，建议的最小闭环（方案 A + C）

```
① 诊断（L5，已实现）
      ▼
② 建议生成（L7 内核，新增：把诊断结论映射为「候选动作」= ActionSpec 列表）
      ▼   ← grade_of() 分级（已实现）；T3 直接剔除
③ UI 确认（L6 授权链，已有 confirm/撤销）
      ▼   ← 需新增：确认时附「动作 id + 本次 nonce」，防重放
④ 宿主执行器（**新增**：网关端点 `POST /v1/execute`，仅接受已确认动作；执行本机脚本）
      ▼   ← 仅 T1 放行；T2 需逐次确认；T3 拒绝
⑤ 验证（回采场域 → 再诊断）
      ▼
⑥ 记账（ActionLedger，已实现：append(suggested/confirmed/executed/verified/rolled_back)）
```

**安全约束（实现时必须满足）**
1. **令牌鉴权**：`POST /v1/execute` 必须校验"一次性令牌 + 动作白名单"，**绝不接受任意命令**（只接受预置动作 id，不接受自由文本）；
2. **动作白名单**：只允许 `ActionSpec` 表内的动作（编译期常量），**无 shell 拼接**；
