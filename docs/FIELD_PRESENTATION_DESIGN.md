## 1. 本轮已交付（v0.111 · 可运行、可测）

```
页面信号（宿主抽取）            ← 内核不碰 DOM（零依赖 / 可测 / 跨平台）
      │
      ▼
① 场域解析器  l1_field_parse.rs   L1 抽取 → L2 归一（饱和曲线）→ L3 定格（四场）
      │      地=结构度 ｜ 水=文本量 ｜ 火=媒体密度 ｜ 风=链接与交互密度
      ▼
② 场域映射库  l1_mapping.rs      权重即映射公式，**存在基因库基础公式层**（`fieldmap.*`）
      │      `learn_mapping` / `nudge_weight` → **新映射自动入库**（学习机制落点）
      ▼
③ 场域呈现器  l6_face.rs          原版 / 场域 / 混合；强度 = f(置信度)，**上限 0.35**
      │
      ▼
  UI 叠层（半透明 hsla + 预览外观微调），内容始终可见
```

**测试**：内核 269 → **294**（+25）｜ 目验 70 → **82 项**（+12，含脸切换与"内容不被替换"）｜
免浏览器逻辑测试 **43 项**。
**单一事实源**：UI **不做重复计算**，公式与判定都在内核；浏览器侧仅经 wasm 导出 `field_parse` 调用。

## 3. 【待裁决 · 架构变更】"能看网页"的宿主形态

### 3.1 必须先摆明的两个硬事实

1. **同源策略**：页面内的 JS **读不到 iframe 里第三方站点的内容**。
   因此"网页 → 场域状态"的解析，**在纯 iframe 方案下对第三方站点不可行**（本轮解析对象是本页/本地内容）。
2. **老笔记本当前无外网**：腾讯文档 / 飞书 / Web 版微信 **都需要外网**。
   所以"能打开这三者"这一条验收，**只能在外网机器上验证**（与升级/性能实测同属"需用户侧实测"）。

### 3.2 三方案对比

| 维度 | **A · 原生 WebView 宿主**（发起人所述） | **B · 保持浏览器内核 + 系统浏览器外开** | **C · 本地反向代理去 frame 头** |
|---|---|---|---|
| 做法 | 新增桌面程序（Rust + WebView2/Edge 内核），WebView 里注入 JS 抽取信号 → 内核解析 → 叠层呈现 | 现架构不变；受限站点用系统默认浏览器打开 | 网关做本地反代，剥离 `X-Frame-Options`/CSP，使第三方站可被 iframe 内嵌 |
| 成本 | **高**（新产物、新构建链、安装/升级流程） | **极低**（已具备） | 中（反代 + 安全说明） |
| 风险 | 中：**老笔记本可能没有 WebView2 Runtime**（Win7/8 需单独安装，且**无外网无法在线装**）；引入第三方 crate（内核零依赖红线需区分"内核 vs 宿主"） | 低（无新面） | **中高**：去 frame 头会削弱站点自身的点击劫持防护；需限定仅本机/内网使用并显著提示 |
| 收益 | **高**：第三方站点可解析（能拿到 DOM）→ 场域呈现完整；真正成为"能看网页的浏览器" | 中：能看网页，但**拿不到内容 → 无场域呈现** | 中：能内嵌看网页，仍**拿不到跨域内容**（同源策略仍在）→ 场域呈现受限 |
| 可逆性 | 高（独立产物，可与现方案并存） | 高 | 高（关掉反代即恢复） |
| 与红线 | ⚠️ 需明确"内核仍零依赖、宿主可带依赖" | ✅ | ✅ |

### 3.3 六要素速览

- **相关的点**：解析器/映射库/脸切换**已完成**（不依赖宿主形态）；缺的只是"信号来源"。
  WebView 决定信号从哪来；也会带来新的分发/升级链路（与 v0.106 升级入口并行）。
- **风险（含不做）**：不做 A → **第三方站点的场域呈现永远做不到**（这是本次验收标准之一）；
  做 A → 增加 Runtime 依赖与构建复杂度，老笔记本可能装不上。
- **经验教训**：v0.106 升级已验证"应用层替换不碰网络"的路子可行；**老笔记本无外网**这一事实反复影响方案选择。
- **好处**：真"能看网页"＋可解析 → 场域呈现闭环；且 WebView 宿主与我们现有 wasm 内核**天然同栈**（都是 Web 技术）。
- **差异点**：见 §3.2 表。
- **推进建议**：**先做 A 的"最小宿主"（只读 + 叠层，不做书签/下载），并把 Runtime 缺失时的降级路径写死**
  （检测不到 WebView2 → 自动回退到"浏览器内核 + 新窗口"模式，不让用户面对白屏）。

### 3.4 裁决记录（**已裁决** · v0.112）

- [x] **Q1**：宿主形态选 **A（原生 WebView2 宿主）**；A 的最小宿主原则＝**只读、不写、叠层、不替换**；
      **B 为降级路径**：Runtime 缺失时**自动降级到 B（外开模式）**，不让用户见白屏。
- [x] **Q2**：接受红线细分 —— **宿主可带依赖（WebView2 Runtime 等）；内核仍零依赖**。
- [x] **Q3**：老笔记本无 Runtime → 选 ②：**随包分发离线 Runtime 安装包**（开发机下载 → 打包 → 老笔记本离线安装）。

## 6. 四元组内在变量框架（v0.112 落地）

依据发起人「四元组内在变量框架落地」。**正式定义**：

| 变量 | 对应 | 含义 |
|---|---|---|
| **紧张 tension** | 多巴胺 | 需求未满足的累积张力 |
| **平静 calm** | 血清素 | 无威胁时的稳定基线 |
| **喜欢 liking** | 内啡肽 | 需求满足后的释放 |
| **安全 safety** | 催产素 | 社会信任与连接 |

**落到哪一层**：`meta-kernel-core/src/l5_quad.rs`（L5），与既有七维向量**并列**（场域状态 = 七维 + 四元组）。

```
被动接收扰动 P → 更新四元组（经基因库映射 P→ΔQ）
              → 对比本底场（四元组基线）
              → 输出诊断（偏离/主导/行为倾向）+ 四元组状态
```

**基因库存什么**（"基因库升级"）：
- **P → ΔQ**：存**关系层（公式层）** `quadmap.p2q.{tension,calm,liking,safety}`（`Formula::Weighted`）；
- **ΔQ → B**：行为倾向由**阈值常量**判定，常量存**基础公式层** `quad.tension_high` 等。
- 两者都**改库即改行为**，并可用 `learn_*` 路径继续积累。

**探测策略**：`decide_probe()` —— **默认被动（水面模式）**；**主动仅为例外**，且**必须带理由**
（置信度过低 / 偏离过大 / 信号陈旧），不允许"无理由地主动打扰"。

**L4 戒律挂接**：`meta-kernel-core/src/l4_risk.rs`（四条：不害 / 不妄动 / 可回退 / 自承）
- **不害**：触及他者（用户数据/他者内核/安全机制）→ **拒绝**（与四元组无关）；
- **可回退**：不可逆或未声明回滚 → **拒绝**；
- **不妄动**：**挂接四元组** —— 紧张高＋平静低，或安全低 → **先稳后动**（不是永久拒绝）；
- **自承**：紧张偏高但状态可控时，**必须显式承认为己方原因**才放行。

> 与既有 L4（`l4_gate` 场域节律）**并列不覆盖**：前者管"场域是否过载"，本模块管"动作是否该做"。

**三项并行接线（Q4）**：

| 接线 | 落点 | 复用了什么 |
|---|---|---|
| **痕迹池 ← 场域指纹** | `l1_field_parse::{field_fingerprint, field_trace_type, field_trace, field_signature7}` | `trace::fingerprint_of/decide_type/Trace`、`TraceStore`、`HabitPool::observe`、`dna_trace::store/match_trace` |
| **摩尼宝珠 → 场域呈现** | `l1_mapping::{mirror_complement, gate_once, regress_to, through_pearl}` | `gate::DECOMPOSE_RATIO`（0.618 闸门）+ e^-0.1 回归 |
| **场域状态 → 基因库场景公式层** | `l1_mapping::{field_scene_id, learn_field_scene}` | `GeneLibrary::learn_scene`（同一场景复用，不新增条目） |
