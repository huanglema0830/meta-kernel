> 依赖：L4 框架（docs/L4_APPLICATION_FRAMEWORK_DESIGN.md）｜L3 网关已发布（main=6cd9d45）
> 目标：给 L4 框架一个**具体可落地的参考应用**，同时展示 ①生命周期仪表 ②命名/语言组织 ③"念头→显化"的外显闭环。

## 1. 选型

**推荐参考应用 = 「显化工作台 Manifest Journal」**：用户把一条原始念头/事务（一段话）交给系统 → 系统将其确定性映射为内核扰动（种子）→ 内核点亮并演化 → 应用跟踪该"显化条目"的生命周期（10→99→0）→ 语言层把内核事件翻成可读"显化日志"与建议动作。

选型理由：
- **最小但完整**地走通"点亮→外显"全链路（输入文本→种子→内核→事件→生命周期→命名语句→日志/建议）；
- 展示 §L4-4 的命名与语言组织（每条日志都是命名+陈述+意图三层产物）；
- 与发起人生态（想法/注意力管理类工具）气质一致，易演化出真实用途；
- 备选：A) 禅境示波器 L5 客户端（现 UI 走 L3 网关而非直连 wasm，弱"语言组织"展示）；B) 冥想/仪式伴侣（展示面窄）。**推荐 Manifest Journal，备选 A**。

## 2. 应用轮廓

```
┌────────────────────────────────────────────────┐
│ Manifest Journal（Web 客户端 + 本地常驻网关）          │
│                                                │
│  [写一条念头]  ──► 种子映射(§4) ──► POST /v1/push   │
│                                                │
│  GET /v1/events (SSE) ─► EventPipe ─► Lifecycle  │
│                    └────────► Speaker（日志句）    │
│                                                │
│  UI：条目卡片（显化仪表 0/10…99）＋显化日志流          │
│       ＋"下一步"意图（suggest_next 模板）           │
│  /v1/state 每帧投影；/v1/persist 存档恢复          │
└────────────────────────────────────────────────┘
```

## 3. 数据模型

```json
// 显化条目（应用侧，非内核）
{ "id": "m-0001",
  "raw": "把 A4/A5 复核结论写进正式档案",
  "seed": 0.47,                 // 确定性种子（§4）
  "lifecycle": 12,              // 由 LifecycleEngine 维护（10..99/0）
  "rounds": 1,                  // 已完成的 99→0 回融轮次
  "log": [                       // 显化日志（语言层产物，只增）
    { "t": 1024, "at": "10:02:11",
      "lifecycle": 12,
      "statement": "内核正从萌发带推进；化合生成 0.42",
      "source": "instruction#compound|state_change" }
  ],
  "intent": { "kind": "suggest_next",
              "text": "储备尚足：可再注入一条补充扰动以延续显化",
              "source": "low_energy|state_change" } }
```

持久化：条目表存 localStorage/文件（复用 L3 persist 语义：内核快照 + 应用条目分开存，条目 seed 可重放）。

## 4. 文本 → 种子（外部知识匹配的第一步：稳定指称）

规则（一期确定性、非语义深度解析——注明边界）：
1. 取文本 UTF-8 字节，跑 **FNV-1a / 现有 fingerprint 风格哈希**（trace 指纹已有先例）得 64 位 fp；
2. `seed = (fp >> 8) 归一化到 [0.25, 0.95]`（**避开 0 附近**，防止种子过小被内核判"静默"；负值域永不产生）；
3. 同一文本 → 同一 seed（可重放、可跨会话一致）；不同文本几乎必不同；
4. 词义相似度不做（一期）；二期可经"孪生指纹"（心流凿空 `!fp` 配对）让"互补念头"天然共振——**这正是 L4 语言组织与内核孪生机制的衔接点**（文档化，实现轮再挂）。

> 边界声明：种子只携带"这是第几条念头/文本指纹"，不携带语义打分；内核照旧以其内部语义（熵窗口/波形）回应——**外显的"意义"由显化日志的翻译层赋予，内核只做真实演化**。

## 5. UI 面（最小可用）

- **条目卡片**：raw 原文（零修改展示）＋显化仪表（0→10→…→99 圆环，99 后闪示"回融"回 0）＋轮次徽标。
- **显化日志流**：最新 3 条 statement（时间+圈层色标），每条可点开看 source 溯源。
- **下一步建议**：intent 区（来自 Speaker 意图层），按钮「注入补充扰动」（再 push 该条 seed 变体 seed'=clamp(seed+0.05)）或「归档本轮」（显式 reset → 回融 0）。
- 界面哲学沿用项目：上思考区（原文+命名圈层）下执行区（推进/归档按钮）；一切数值来自 L3/L4，不另造动画（守 R1 投影）。

## 6. 与部署形态的接法

- 一期（L4 结论 A）：本地常驻 npb-gateway（127.0.0.1:3000 等）+ Manifest Journal Web 客户端经 SSE/HTTP 接入；curl 级联调与 L3 CI 活体步骤一致。
- 客户端可先后台无头模式（Node 跑 EventPipe+LifecycleEngine 写日志文件），Web UI 后加——**两条路都只依赖 L4 契约**。

## 7. 验收准则（草案）

参考应用"可用"当且仅当：
1. 输入一条文本 → 生成稳定种子 → push 被接受（accepted:true）；
2. 订阅流出现 state_change/instruction → 生命周期仪表从 0→10 并随正向事件递增，99 后（静默窗）回 0 并记轮次；
3. 显化日志每条 = 命名+陈述且可溯源到事件字段（抽查 5 条人工比对）；
4. 注入扰动按钮可再推进；归档可早退回融；
5. 刷新/重启后条目与显化日志恢复（persist+localStorage），seed 重放后生命周期趋势一致。
