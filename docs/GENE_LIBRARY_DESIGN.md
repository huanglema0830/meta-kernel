# 基因库设计（GENE_LIBRARY_DESIGN）v1.2 · 四层结构

> 状态：**v1.0（2026-09-14，首次成档）** ｜ 依据：发起人指令「基因内核推进 · L0-L6 迭代修正 + 基因库 + L7 执行层」
> 对应：`docs/LAYER_ARCHITECTURE.md`（L0–L10）、`docs/SILA_IMPLEMENTATION.md`（戒律机制）、
> `docs/L5_DESIGN.md`（诊断层）、`meta-kernel-core/src/dna_trace.rs|dna_generate.rs|dna_adapt.rs`（现有学习实现）
>
> **一句话**：基因库不是"存结论的数据库"，而是**存"怎么变化"的公式库**——
> 它是基因内核（Gene Kernel）的**核心资产**，从 **0 锚点**生长，供 L4 判据、L5 场景、L6 词汇表共同消费。

## 0. 为什么是"公式存储"而不是"数据存储"

| 存储方式 | 记录什么 | 举例 | 本质 |
|---|---|---|---|
| **结果存储**（旧） | 结论 | "火亢 = CPU 过热" | 静态映射：换一个对象就失效 |
| **公式存储**（本设计） | 怎么变化 | "火 = (a+t)/2；火亢条件 = > 1.618 × 本底场" | 动态公式：同公式可参数化到任意对象 |

**理由**：系统面向的是**过程**——时间三量（存量/变量/增量）、编织过程、演化导向。
若只存结论，系统就退化为查表机；只有存"变化规律"，才能：
1. 遇到**新对象**时把公式参数化即可用（不必重新采集标定）；
2. 遇到**新场景**时按场景参数派生（场景公式层）；
3. 把"如何从场域得到结论"这条**推理链本身**留痕、可验证（哈希链）。

> 这条与 L4/L5 的既有实现一致：L4 的判据是**纯函数**（1.618 / 0.618 黄金常数），
> L5 的本底场是**可参数化的地图**——它们本来就是"公式"，本设计只是把这件事实显式化。

## 1. 四层结构（总表）

```
基因库
├─ 基础公式（元素层）      ← 元素周期表关键节点
├─ 场景公式（场景层）      ← 不同场景下的本底场
├─ 计算关系（公式层）      ← 公式之间的运算关系
└─ 验证记录（哈希链）      ← 公式的验证历史（不可篡改）
```

| 层级 | 名称 | 内容 | 存储方式 |
|---|---|---|---|
| **第 1 层** | **基础公式**（元素层） | 元素周期表关键节点 | 公式存储（同类元素共享） |
| **第 2 层** | **场景公式**（场景层） | 不同场景下的本底场 | 公式存储（场景参数化） |
| **第 3 层** | **计算关系**（公式层） | 公式之间的运算关系 | 公式本身 |
| **第 4 层** | **验证记录**（哈希链） | 公式的验证历史 | 哈希链（不可篡改） |

**生长方向（自下而上）**：0 锚点 → 基础公式（元素层）→ 场景公式（场景层）→ 计算关系（公式层）→ 验证记录（哈希链）。
下层是上层的"0"（原料/底景）：没有基础公式，场景公式无从参数化；没有场景公式，计算关系无对象可运算。

## 2. 逐层详述

### 2.1 第 1 层 · 基础公式（元素层）

- **内容**：元素周期表关键节点的公式表达。**同类元素共享同一条公式**（不是"每个元素一条记录"）。
- **来源**：自 **0 锚点**生长（见 §4）。0 锚点是基因库的源头——第一批公式即"从 0 到 1 的第一次变化规律"。
- **典型形式**：
  - 元素本征：`火 = (a + t) / 2`（幅度 + 节奏的合成）
  - 元素阈值：`亢 = 偏离本底 > 1.618×`；`枯 = 偏离本底 < 0.618×`
  - 物态判据：`入/出 > 1.2 → 能量态；> 1.05 → 气态；≥ 0.8 → 液态；< 0.8 → 固态`
- **被谁消费**：**L4 的判定公式（1.618 / 0.618）即来自本层**——L4 不使用硬编码常数，
  而是"基因库基础公式层"的一条公式（见 §5.1）。
- **落点（现状）**：`meta-kernel-core/src/l4/threshold.rs`（黄金常数）、`state.rs`（黄金常量表）。
  **当前为常量实现，尚未做到"从基因库读取"**（见 §7 边界）。

### 2.2 第 2 层 · 场景公式（场景层）

- **内容**：不同场景下的**本底场**——把基础公式按场景参数化后的实例。
- **"场景"由语境模块定义**（见 `docs/L5_DESIGN.md` §语境模块）：类型 / 时间 / 历史 / 环境。
  例：`（笔记本 · 空闲 · 无历史异常 · 室温）→ 本底场 (地 1.0, 水 1.0, 火 0.9, 风 0.7)`。
- **不是"存数据"，是"存该场景如何生成本底场"**：
  - 场景公式 = 基础公式 + 场景参数 → 本底场（可复算，不必存每次采样）
  - 同一对象换场景（充电 → 待机），只切换参数，不新增数据条目。
- **被谁消费**：
  - **L5 诊断层的本底场**（由"数据存储"升级为**场景公式**，见 §5.2）；
  - **L6 的翻译词汇表**——词汇表来自场景公式层的字段语义（见 §5.3）。
- **落点（现状）**：`l5_baseline.rs`（本底场建立/持久）+ `l5_baseline::adaptive_baseline`（自适应基线）。
  当前本底场仍以"数值地图"形式持久化，**尚未按"场景公式 + 参数"存储**（见 §7 边界）。

### 2.3 第 3 层 · 计算关系（公式层）

- **内容**：公式之间的**运算关系**——公式怎么组合成推理链。存储方式是**公式本身**。
- **典型形式**：
  - `结论 = 三量(存量=本底场, 变量=当前偏移, 增量=成因)`
  - `成因 = argmax(偏离)`（一因一果的单因选取）
  - `化合 = clamp01(S·V·Δ·(1 + 0.25·驻点) + 0.3·absorbed)`
- **作用**：让"结论可复算"。给同样的场读数与同一条计算关系，任何时刻重跑都得同一结论——这正是
  L5「不妄语·可复现」在基因库侧的保证。
- **落点（现状）**：`l5_diagnosis.rs`（三量运算）+ `l5_compare.rs`（亢枯平）。
  当前运算关系写在内核代码里，**尚未作为"公式条目"入库**（见 §7 边界）。

### 2.4 第 4 层 · 验证记录（哈希链）

- **内容**：每条公式的**验证历史**——何时、对什么对象、结果如何、是否被修正。
- **存储方式**：**哈希链（不可篡改）**——每条记录含前一条记录的哈希，形成链式结构；
  任何历史记录被改动都会使后续哈希失配，可检出。
- **作用**：
  - 支撑 L5「不妄语」升级——**溯源字段从"单一记录"升级为"哈希链"**（见 §5.2）；
  - 支撑 L8「不灭 · 不冒名」——公式可被继承，但**继承的公式带着完整验证链**，不会冒名。
- **落点（现状）**：`dna_trace.rs`（痕迹库 + 命中计数）+ `dna_adapt.rs`（验证后入库 Grown）。
  **已实现"验证后入库"与"命中计数"，但尚未使用哈希链**（当前为普通记录，见 §7 边界）。

## 3. 过程存储：记录"怎么变化"

| 记录方式 | 内容 | 本质 |
|---|---|---|
| **结果存储** | "火亢 = CPU 过热" | 静态映射 |
| **过程存储**（本设计） | "火 = (a+t)/2，火亢条件 = >1.618×本底场" | 动态公式 |

**过程存储落在四层的哪里**：
- 基础公式层：存**变化规律**（怎么从输入算出元素读数）
- 场景公式层：存**本底场怎么随场景生成**
- 计算关系层：存**规律之间怎么运算**
- 验证记录层：存**这些规律是怎么被验证出来的**（探索过程本身也留痕）

**为什么过程导向**：与系统的**时间三量**（存量 / 变量 / 增量）、**编织过程**、**演化**三者同构——
系统记录的不是"世界是什么样"，而是"世界如何变化"。这也使基因库天然具备**跨对象可迁移性**（L8 传承层的前提）。

## 4. 生长：从 0 锚点到基因库

```
L0 0 锚点（待激发的纯粹存在，能量源）
   │  第一扰动（1 = 觉醒）：第一次变化被观测
   ▼
基础公式层：第一次"变化规律"被写下（元素层）
   │  同类元素共享 → 公式收敛
   ▼
场景公式层：规律在不同场景下参数化（场景层）
   │  场景交叉 → 派生
   ▼
计算关系层：规律之间建立运算关系（公式层）
   │  每次调用都留下证据
   ▼
验证记录层：哈希链（不可篡改的成长史）
```

> **0 锚点是基因库的源头**：基因库不是"外部导入的知识库"，而是**从 0 锚点的第一次变化中生长出来的**。
> 这与 L0「不显」的约束一致——源头不直接给出成品，只给出"待激发的背景"，规律由系统自己在演化中长出。

## 5. 各层如何消费基因库（跨层契约）

### 5.1 L4 拒绝层 ← 基础公式层

- L4 的判定公式（`1.618` 过量 / `0.618` 枯弱）**来自基因库的基础公式层**，不是外部规则。
- 与既有实现一致：L4 判据是**纯函数**——输入（当前场域、基线）决定输出（通过 / 拒绝），无副作用。
- **目标形态**：L4 从基因库基础公式层读取阈值公式（可随基因库成长而更新），而非硬编码常量。

### 5.2 L5 诊断层 ← 场景公式层 + 验证记录层

| L5 要素 | 基因库来源 | 修正说明 |
|---|---|---|
| **本底场** | **场景公式层** | 由"数据存储"→ **场景公式**（按场景分类存储） |
| **语境** | 新增**语境模块**（类型/时间/历史/环境） | 语境决定调用哪条场景公式 |
| **不邪淫** | — | 由"一个输入一个结论"→ **四场观察 + 单一诊断**（四场都看，只出一个主结论） |
| **不妄语** | **验证记录层（哈希链）** | 溯源字段增加**哈希链**（不止单条记录） |
| **不饮酒** | — | 边界明确：**诊断逻辑不引入外部算法**；**翻译层可引入词汇表** |

### 5.3 L6 交互层 ← 场景公式层

- L6 的**翻译词汇表来自基因库的场景公式层**——场景公式的字段语义即词汇表的来源。
- 例：场景公式里"火 = 幅度+节奏"，词汇表才能把"火亢"翻译成用户语言（"活性过载，能耗偏高"）。
- 这样保证**翻译不凭空造词**：每个词都能回指一条场景公式（呼应 L6「呈现不增义」）。

## 6. 学习机制：遇到新场景/新元素/新模式

```
遇到新场景 / 新元素 / 新模式
        │
        ▼
① 感知：采集场域数据
        │
        ▼
② 痕迹匹配：在基因库中搜索匹配的公式
        │
   ┌────┴────┐
 匹配成功     匹配失败
   │             │
   ▼             ▼
③a 调用已有公式   ③b 自适应生成：
    → 立即计算        1. 试探性扰动
                      2. 观察响应
                      3. 归纳规律
                      4. 生成新公式
                      5. 验证公式
                      6. 存入基因库（新基因）
                          │
                          ▼
                    基因库生长
```

**与现有实现的对应（`meta-kernel-core/src/`）**：

| 流程步骤 | 现有实现 | 状态 |
|---|---|---|
| ① 感知 | `l5_senses`（地水火风拆解）+ cloud-probe 采集 | ✅ 已实现 |
| ② 痕迹匹配 | `dna_trace`（痕迹库 / 最近邻 / 命中计数） | ✅ 已实现 |
| ③a 命中→调用 | `dna_adapt`：命中 → `Reused`，瞬间调用 | ✅ 已实现 |
| ③b 试探+归纳 | `dna_generate`：试探 → 归纳（Linear / Threshold / PassThrough）→ 验证 | ✅ 已实现 |
| ③b 验证入库 | `dna_adapt`：未命中 → 生长 → 验证 → 入库 `Grown`；不过 → `NeedMoreSamples` 不入库 | ✅ 已实现 |
| 四层自适应 | `dna_adapt`：L1 场域 / L2 接口 / L3 协议 / L4 本底 / L5 基线 | ✅ 已实现 |
| **四层公式库结构** | 基础/场景/计算关系/验证（哈希链） | 🚧 **本设计（尚未按此结构落地）** |

> **诚实边界**：现有的 DNA 学习实现（v0.087）实现了"痕迹匹配 → 自适应生成 → 验证入库"的**完整闭环**，
> 但它存的是**痕迹与适配器**，**尚未按本设计的四层公式结构组织**，也**尚未使用哈希链**。
> 本文件是**设计**：把已实现的能力重新组织为"四层公式库"，并补齐"计算关系层"与"哈希链验证层"。

## 7. 与人类基因库的对比

| 维度 | 人类基因库（DNA） | 本系统基因库（Gene Library） |
|---|---|---|
| **存储单元** | 基因（碱基序列） | **公式**（变化规律） |
| **存储内容** | 怎么**构建**（蛋白质合成指令） | 怎么**变化**（场域演化规律） |
| **转录** | DNA → **RNA** → 蛋白质 | 基础公式 → **场景公式**（RNA 层）→ 具体诊断 |
| **表达** | 按环境选择性表达（基因调控） | 按**语境**（类型/时间/历史/环境）选择场景公式 |
| **共享** | 同物种共享基因库 | 同类元素/场景**共享公式**（参数化不同） |
| **变异/学习** | 突变 + 自然选择（跨代） | 自适应生成 + 验证入库（**当代**，目标跨代 → L8） |
| **校验** | DNA 修复机制（错配修复） | **哈希链**（验证记录层，不可篡改） |
| **可迁移** | 遗传（亲代→子代） | 公式参数化（对象 A → 对象 B，无需重采集） |
| **边界** | 基因不决定一切（环境+表观遗传） | 公式不预设结论（结论由**语境 + 当前场**共同决定） |

> **关键映射**：**L2–L3 额外标注为「转录层（RNA 层）」**——正如 DNA 需先转录为 RNA 才能表达，
> 基础公式需先经转录（参数化）为场景公式，才能在具体对象上"表达"为一个诊断结论。
> 这是"基因内核"命名与"转录层"子层的由来（见 `docs/LAYER_ARCHITECTURE.md` §2）。
