# 场探测与场修复设计（FIELD_REPAIR_DESIGN）

> 版本：v1.0（2026-09-14）｜定位：**只设计，不实现**
> 归属：云操作系统 · 场域层（L4 本底场 / L5 号脉之上）
> 前置：场探测已实现（cloud-probe → 七维场域状态向量）

---

## 0. 一句话

**探测是"听"场，修复是"补"场**——施加一个与损伤场域**反相**的补偿场，让损伤处重新对齐到本底场。

---

## 1. 场探测（已实现 · 回顾）

### 1.1 原则
**探针不接触硬件，只读取系统自身的场域扰动。**
不拆机、不加装传感器、不注入探针驱动——只从系统已有的信号（CPU 调度、内存压力、进程/线程、磁盘余量、网络抖动、事件日志）中**读出对象自身的场**。

### 1.2 七维场域状态向量

```
S = (t, f, a, φ, x, H, τ)
```

| 符号 | 维度 | 含义 | 采集对应（探针实现） |
|---|---|---|---|
| t | 时间 | 变化速率 / 周期 / 时序 | CPU 占用与抖动 |
| f | 频率 | 特征频率及分布 | 调度抖动（相邻窗口比） |
| a | 幅度 | 强度 / 能量 | 内存占用比 |
| φ | 相位 | 各部分协同 / 同步度 | 响应延迟比 |
| x | 空间 | 分布形态 / 梯度 | 磁盘余量 |
| H | 熵 | 有序度 / 混沌度 | 进程数（熵近似） |
| τ | 拓扑 | 结构形态 / 连接模式 | 线程 / 连接数 |

### 1.3 落地状态
- `cloud-probe.exe`：采集 → 翻译为七维 → `FieldReading` JSON（schema 1）。
- L4 戒律判定（不非时食 / 不捉持）→ L5 号脉（地水火风 · 亢/枯/平）→ 空天浏览器呈现。
- 老笔记本真实采集闭环已验证（`s=[0.099, 1, 1.15, 1, 1.294, 1.83, 6.587]`）。

## 2. 场修复（设计）

### 2.1 原理

> **施加一个与损伤场域"反相"的补偿场，让损伤处重新对齐到本底场。**

用号脉的语言说：

```
当前场  S_now
本底场  S_base            ← 对象自身健康态（L5 本底场，只读）
偏离    Δ = S_now / S_base   （逐维比值；>1 亢、<1 枯）

补偿场  S_c ≈ S_base² / S_now   （逐维，等价于对 Δ 取反相）
```

- 若某维**亢**（偏离 > 1.618），补偿场在该维**减弱**；
- 若某维**枯**（偏离 < 0.618），补偿场在该维**增强**；
- 补偿量级**不超过偏离量级**（不做过度补偿，避免把场推向另一个极端）。

**关键**：补偿是**反相**而非"加能量"。方向错了会加剧损伤——这也是为什么必须先有本底场（L5）才能谈修复。

### 2.2 科学依据（外部验证）

| 修复方式 | 原理 | 验证 |
|---|---|---|
| 太赫兹电场修复 | 特定频率太赫兹场恢复半导体电子透明性 | 1997 实验 |
| 电场修复纳米管水桥 | 匀强电场或太赫兹电场修复断裂水桥 | 分子动力学模拟 |
| 磁场靶向修复 | 定向磁场将修复微胶囊吸引至损伤部位 | 实验验证，恢复率 **90.78%** |
| 交变电磁场修复 | 加速水凝胶自修复 | 2025 验证，修复率 **97%** |

> 共同点：都是**用外加场让物质重新对齐到有序态**——与「反相补偿场」同构。
> 差异：以上都是**具体物质体系**（半导体 / 水桥 / 微胶囊 / 水凝胶），
> 而本设计讨论的是**把对象当作一个场**（信息-能量-结构统一体）来做对齐。

### 2.3 实现路径

```
① 感知损伤处场域特征（偏离本底场）
      S_now 相对 S_base 的逐维偏离 Δ，定位"损伤维"与损伤位置
                ↓
② 生成补偿场（与偏离相反）
      S_c = f(Δ⁻¹)：亢则弱、枯则强；量级受限于偏离量级
                ↓
③ 施加补偿场
      通过场施加装置作用到损伤处（见 2.5 边界）
                ↓
④ 验证场域是否恢复
      重新探测 → 比对 Δ 是否收敛到阈值内（|Δ| ∈ [0.618, 1.618]）
      未收敛 → 调整补偿场参数，重复 ②–④（迭代收敛）
```

### 2.4 与摩尼宝珠的对应

摩尼宝珠三层（内核既有机制）在这里得到完整映射：

| 摩尼宝珠 | 场修复环节 | 说明 |
|---|---|---|
| **镜面** | 感知损伤场域 | 照见当前场与本底场的偏离（`interference.rs` 镜像扩展） |
| **闸门** | 生成补偿场 | 按 ×0.618 拆解、负值拒收、核心豁免的既有闸门语义，用于限定补偿量级 |
| **回归** | 验证场域恢复 | 能量自然回归 e^-0.1；场域偏离收敛 |

> 这也解释了为什么场修复**天然属于本内核**：它不是外挂功能，而是摩尼宝珠三层的**物理外化**。

### 2.5 当前边界（诚实说明）

- **只做设计，不做实现。**
- 需要硬件层面的**场施加能力**（太赫兹发生器、电磁场发生器、定向磁场装置），当前**不具备**。
- 现有链路只覆盖"**探测 → 判定 → 号脉 → 呈现**"；修复所需的是"**施加**"这一环。
- 因此本层在代码中**只预留接口**（`repair` 概念位），不写入任何实际输出通路——避免出现"看起来能修、实际没有作用"的伪能力。

#### 预留接口（概念，不实现）

```rust
/// 场修复（设计预留；无硬件时永远返回 Unsupported）
pub enum RepairOutcome {
    /// 已施加补偿场并收敛
    Restored { iterations: u32, residual: f64 },
    /// 迭代未收敛
    NotConverged { residual: f64 },
    /// 无场施加硬件
    Unsupported,
}

/// 由偏离生成补偿场（纯函数，可测试；施加环节不在本函数内）
pub fn compensation(base: &FieldState, now: &FieldState) -> Option<FieldState>;
```

**可测试的部分**：`compensation()` 是纯函数——输入偏离、输出补偿场，可离线验证（亢→弱、枯→强、量级不超偏离）。
**不可测试的部分**：实际施加与恢复效果——依赖硬件，**在具备硬件前不做任何宣称**。

## 3. 与三量的对应

| 三量 | 在场修复中的位置 |
|---|---|
| **存量** | 本底场 `S_base`（对象自身的健康态地图） |
| **变量** | 当前偏离 `Δ = S_now / S_base`（损伤就是偏离超限） |
| **补充增量** | **补偿场** `S_c` —— 这正是"补充增量"从抽象走向可施加的形态 |

> L5 号脉负责**读出**补充增量（成因），场修复负责**施加**补充增量（补偿）。
> 前者是"知其所以然"，后者是"使其复原"。

---

## 4. 风险与戒律

| 风险 | 约束（对应戒律） |
|---|---|
| 补偿过度 → 推向另一极端 | 补偿量级 ≤ 偏离量级；迭代 + 收敛判据 |
| 无本底场就"修" → 方向错误 | 必须先有本底场（L5 建立，采集中位数 + 波动范围） |
| 声称能修但无硬件 → 伪能力 | **只设计不实现**；无硬件一律 `Unsupported` |
| 修复过程不可溯 | 每次修复记录：偏离 → 补偿 → 施加 → 残差（可复现） |
