# L5 设计 · 最终版：号脉层（应用框架 · 审计层）DESIGN v2.0

> 状态：**v2.0（2026-09-09，最终版——替代 v1.0）** ｜ 版本：提交后自动 → **v0.079**
> 依据：发起人指令（L5 最终版定义）。
> 一句话：**L5 是云内核的号脉层**——感知对象的"地水火风"场，建立内部标准地图（本底场），
> 对比发现亢/枯/平模式，编译翻译成用户可理解的结论。**一切诊断依据都来自对象自身的场，
> 不依赖任何外部数据。**

## 1. 定位与设计原则

- L5 = 云内核真正执行诊断、生成结论的层级（云操作系统 · 审计层 / 号脉）。
- **号脉不干预**：L5 只感知与解释对象自身的场，诊断动作不改变对象（只读）。
- **内部标准地图（本底场）**：由对象自身的场学习建立（首次/例行标定），此后对比以此为基。
- **无外部数据**：不引入外部算法、外部知识作为判定依据；一切结论源自对象自身场。
- 承接：L4 戒律判定已定型（S=(t,f,a,φ,x,H,τ) 为 L3→L4→L5 的场观测采样传输，L4 Pass 后进入号脉）。

## 2. L5 模块划分（落点 meta-kernel-core/src/l5/）

| 模块 | 职责 | 核心输入 → 输出 |
|---|---|---|
| `l5_senses.rs` | **地水火风拆解**：把对象场观测（当前采样）拆为四个本征分量 | 场采样 → 地/水/火/风 分量读数 |
| `l5_baseline.rs` | **本底场建立/存储**：对象健康态的地水火风标准地图（学习+持久） | 学习期采样 → 本底场（内部标准地图） |
| `l5_compare.rs` | 当前场与本底场对比 → **亢/枯/平** 逐分量判定 | 当前分量 + 本底场 → Pattern{亢/枯/平} |
| `l5_diagnosis.rs` | **诊断结论生成（三量运算）** | Pattern + 本底 → 结论（存量=本底场、变量=当前偏移、补充增量=成因） |
| `l5_translate.rs` | **编译翻译**：地水火风语言 → 对象特征语言（读语言对照表） | 结论(场语言) + 对照表 → 用户可读结论 |
| `l5_router.rs` | JSON 输出给 L6（零依赖序列化） | Diagnosis → L6 契约 JSON |

### 2.1 地水火风四场（L5 感知语言）

对象的场按四个本征分量感知（观测投影示意；投影在**本底场标定**时确定，非固定预置）：

| 本征 | 语义（号脉视角） | 观测投影示意（承接七维采样） |
|---|---|---|
| **地** | 承载、结构、稳定 | τ 拓扑、x 空间形态（结构与分布） |
| **水** | 涵养、缓冲、熵流 | H 熵、x 空间缓冲、t 慢变量 |
| **火** | 活性、能量、脉冲 | a 幅度、t 节奏（电脉冲=活性脉冲） |
| **风** | 变动、频率、扩散 | f 频率、φ 相位、t 快变量（振动与相位漂移） |

> 说明：L4 的 S 向量是场观测的七维采样（既有层不重定义）；L5 在号脉语境下把采样拆解为
> 地水火风四分量（每个分量可投影到若干采样维）——**senses 拆解、compare 亢枯平、diagnosis
> 三量、translate 成言**，环环只消费对象自身场。

## 3. L5 戒律（比丘戒 · 五条）

| 戒律 | 要求 | L5 落实 |
|---|---|---|
| **不杀生** | 诊断不干预对象（只读） | senses/compare/diagnosis 全部只读采样，无写对象动作；执行类动作属于未来执行器（L6 侧经确认后，且非诊断） |
| **不偷盗** | 诊断数据不占有（不缓存） | 诊断过程与结论**即算即弃**：中间数据不持有；本底场为例外（见 §3.1 边界） |
| **不邪淫** | 一因一果（单一结论） | 每次号脉只产出一个主结论（一次诊断一个因 → 一个果），不并列多因猜测 |
| **不妄语** | 结论可溯源（可验证） | 每条结论携带溯源：依据场分量、本底场标识、对象/时间、可复现（同输入重跑同输出） |
| **不饮酒** | 不引入外部算法（只基于自身场数据） | 判定/推导只用对象自身场；不调外部模型/算法/知识库参与诊断 |

### 3.1 边界说明（不偷盗与本底场）

- **诊断数据**（每次采样的中间量、结果 JSON）不缓存不占有——调用即弃；
- **本底场**是对象自身的内部标准地图（由对象场学习、归对象所有），允许存储（`l5_baseline`）；
  存储边界：仅存"对象健康态地图 + 标识/时间"，不存其它对象的场、不存诊断过程数据。

## 4. 数据流

```
对象 ── 场采样(七维观测 S) ──▶ L3/L4（戒律判定）
                                   │ Pass
                                   ▼
  L5： senses 地水火风拆解 ─▶ compare（当前 vs 本底场 → 亢/枯/平）
        ─▶ diagnosis 三量运算（存量=本底 / 变量=偏移 / 补充增量=成因）
        ─▶ translate（对照表：场语言 → 对象特征语言）
        ─▶ router（Diagnosis JSON → L6 空海浏览器）
  （诊断数据不缓存；本底场由对象自身场标定维护）
```

## 5. 接口契约

### 5.1 采样与本底场

```rust
// 采样结构（L4 Pass 后进入 L5 的观测；s 与既存 S 同源）
pub struct FieldReading { pub s: [f64; 7], pub at: Option<String> }

// 本底场（内部标准地图；对象自身场标定）
pub struct BaselineField { pub earth: f64, pub water: f64, pub fire: f64, pub wind: f64,
                           pub established: Option<String> }
```

### 5.2 诊断结论（L5 内部 → translate → router）

```rust
pub enum Band { Kang /*亢 高越界*/, Ku /*枯 低越界*/, Ping /*平 节律内*/ }

pub struct Diagnosis {
    pub schema: u8,                  // 契约版本 = 2
    pub fields: [f64; 4],            // 地水火风当前分量读数
    pub pattern: [Band; 4],          // 逐分量 亢/枯/平
    pub conclusion: Conclusion,      // 单一主结论（不邪淫）
    pub trace: Traceability,         // 溯源（不妄语）
}
pub struct Conclusion { pub title: String, pub description: String, pub cause: String /*补充增量*/ }
pub struct Traceability { pub baseline_id: String, pub object: String, pub at: String,
                          pub reproducible: bool }
```

### 5.4 与 L6 / 探针关系

- L6 空海浏览器消费本 JSON 展示（现有「设备诊断」卡接入）。
- cloud-probe 采集七维采样（数据格式沿用既有映射：探针输出 `s[7]`，L3→L4→L5 链消费）。
- 行动步骤（"怎么修"）不由 L5 判定生成——判定只基于对象场；步骤可经 L6 侧用户自选知识源
  提供，**不进入 L5 判定**（守不饮酒）。

## 6. 翻译机制（l5_translate）

- L5 使用**语言对照表**编译翻译（配套文档：`docs/L5_TRANSLATION_TABLE.md`）。
- 对照表涵盖九种语言：场域语言（地水火风）/ 状态语言（亢/枯/平）/ 诊断语言（望闻问切）/
  三量语言 / 基础代码语言 / 戒律语言 / 对象特征语言（硬件/软件/植物/动物/地质）/
  用户通用语言 / 中医语言。
- **对照表在 L5 使用过程中由用户实际验证和补充，不作为固定知识预置**：文档给出条目结构与
  示例行（示例标"待验证"），正式词条随使用积累；l5_translate.rs 以读表方式调用（表=配置数据）。

## 7. 验证用例设计（实测定型参考）

| 用例 | 场景 | 期望 |
|---|---|---|
| Q1 | 对象平稳（各分量平） | pattern 全 Ping；结论"平稳"，一因一果单一 |
