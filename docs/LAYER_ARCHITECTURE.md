## 0. 元语言说明

- **零（0）**：每一层都从"上一层的输出"作为其待激发的背景（存在态）开始——上层输出成为本层之"0"（原料/底景），与本层专属扰动相遇后产生本层作用。自下而上，万物逐层显化；自上而下（L6 世界反馈回归 L0），实现闭环。**回归 0 不是消灭，是让原料回到"待激发"态。**
- **扰动**：本层产生作用所需的触发输入。外扰来自上一层/世界；内扰来自本层演化中自发产生（镜像回显/回归/孪生等）。
- **戒律**：每层为守住"本源不害、显化不妄"而新增的约束机制；各层机制不同（见 SILA_IMPLEMENTATION）。

## 1. 层号命名纪律（v1.2 新增 · 必读）

> 这一节是为了防止 §4.2 那类冲突再次发生。**层号是架构的坐标系，一个层号只能有一个语义。**

1. **一个层号 = 一个语义**。不得有两个不同的东西共用同一个 L 编号，哪怕它们"都属于某一层"。
2. **层号只授予"每层独有的作用机制"**，不授予"产品"或"模块"。
   - ✅ 正确：`L4 = 拒绝（判定是否放行）`
   - ❌ 错误：`L4 = 应用框架`（应用框架是一组产品能力，不是"拒绝"这一机制本身）
3. **产品形态用产品名，不占层号**。见 §3。
4. **层号变更必须留痕**：在任何文档中引入/改变层号时，须在本文档版本记录中说明理由。
5. **文档内部不得自相矛盾**：若某层的"实现状态"有分歧，以**代码落点**为准（见 §2 表右列）。

## 4. 逐层详述

### L0 · 源层（0 锚点）
- 功能：纯粹存在（非空无），一切显化的能量源与归宿。
- **基因库的源头**：基因库从 0 锚点中**生长**——0 锚点是基因库的源头（系统不导入外部知识库，规律自第一次变化中长出）。
- 零：无上一层；其"零"即自身（自足）。
- 扰动：第一扰动（1=觉醒），可来自外部输入或内部镜像池。
- 新增约束：**不显**——本源不为自己命名、不直接生产"已命名/已显"之物。落点：`docs/MATH_SPEC.md`、`0` 在生命周期状态机中为锚点态。

### L1–L3 · 基因内核（Gene Kernel）

> **定名（v1.4）**：L1–L3 合称**基因内核**（Gene Kernel；旧称 元内核 / DNA 内核，主口径以「基因内核」为准）。
> - **转录层（RNA 层）**：**L2–L3 额外标注**——正如 DNA 需先转录为 RNA 才能表达，
>   基础公式需先经转录（参数化）为场景公式，才能在具体对象上"表达"为诊断结论。
> - **核心资产 = 基因库**（四层结构）。**存储方式 = 公式存储**（记录"怎么变化"，非"结论是什么"）。
> - 全貌见 `docs/GENE_LIBRARY_DESIGN.md`。

#### L1 · 内核·解构层（meta-kernel-core）
- 功能：三变化模式引擎（线性/斐波那契/指数）；能量池（入/出流、储备、化合吸收）；物态（能量→气→液→固，黄金阈值）；0-10 标尺；正源场域（自动搜索-解构-吸收）；沙漏/镜像/闸门/干涉/痕迹-习气-自我/三层机制/持久化/摩尼宝珠/**基因内核学习**。
- 零：0 锚点存在态。
- 扰动：`push(seed)`（外部注入/镜像回注/孪生补充），软钳位后在 [0,1] 内演进。
- 新增约束：**解构**（不杀生、转化不消灭）+ 仅加法/×0.618/e 衰减（不饮酒）。
- **基因内核能力（v0.087 起，已实现）**：痕迹匹配（`dna_trace`）→ 自适应生成（`dna_generate`）→ 验证入库（`dna_adapt`）；
  **新公式自动入库**——命中 → `Reused`（瞬间调用已有公式）；未命中 → 生长 → 验证 → `Grown`（存入基因库）；不过 → `NeedMoreSamples`（不入库）。
- **基因库生长**：基础公式（元素层）在此写下；供 L4 判据、L5 场景、L6 词汇表共同消费。
- 仓库：`meta-kernel-core/src/*`（含 `dna_trace.rs` / `dna_generate.rs` / `dna_adapt.rs`）。

#### L2 · 桥·过滤层（npb）· **转录层（RNA）**
- 功能：通过 C ABI（cdylib）与 wasm32 暴露给任意宿主；确定性自检摘要（跨平台一致性红线）。
- 零：L1 的合法输出（0-1 域与 JSON 化指令）。
- 扰动：宿主调用（push_seed/pop_result/get_*）。
- 新增约束：**过滤**——入口域过滤、负值在桥入口即拒、仅暴露受控导出集（版本化）。
- 仓库：`npb/src/lib.rs`、`bridge.h`。

#### L3 · 网关·剥离层（npb-gateway）· **转录层（RNA）**
- 功能：HTTP+SSE 传输接口：`/v1/push|state|events|persist/*|probe|probe/usb|health`；单一写者线程模型。
- 零：L2 输出流（内核读数与指令 JSON）。
- 扰动：外部请求/SSE 订阅/持久化调用/探针上报。
- 新增约束：**剥离**——只转语义：不缓存业务态、指令只转发不解释、不空转驱动、快照 schema 版本化。
- 仓库：`npb-gateway/src/*`。

> **与人类基因库的对比（要点，完整表见 `GENE_LIBRARY_DESIGN.md §7`）**：
>
> | 维度 | 人类基因库 | 基因内核的基因库 |
> |---|---|---|
> | 存储单元 | 基因（碱基序列） | **公式**（变化规律） |
> | 转录 | DNA → RNA → 蛋白质 | 基础公式 → **场景公式（RNA）** → 诊断结论 |
> | 表达 | 按环境选择性表达 | 按**语境**（类型/时间/历史/环境）选择场景公式 |
> | 校验 | DNA 错配修复 | **哈希链**（验证记录层，不可篡改） |

### L4 · 场域·戒律拒绝层（`meta-kernel-core/src/l4/`）· v1.2 归位
- **功能**：判定**场域的变化（变量）是否符合场域自身的内在节律**，再决定是否允许它进入 L5。
- **核心理念**：戒律**不是外部规则，而是场域自身变化的内在边界**；一切判定都在内在完成，不依赖外部输入。
- **判据来源（v1.4）**：L4 的判定公式（`1.618` / `0.618`）**来自基因库的基础公式层**——
  不是硬编码的外部常数，而是基因库中的一条公式（见 `docs/GENE_LIBRARY_DESIGN.md §2.1 / §5.1`）。
- **零**：L3 语义事件 + 七维场域状态向量 `S = (t, f, a, φ, x, H, τ)`。
- **扰动**：场域状态向量相对基线的偏差。
- **新增约束（戒律）**：
  | 戒律 | 触发条件 | 含义 |
  |---|---|---|
  | **不非时食** | 任意 ≥3 维偏离基线 **> 1.618 倍** | 场域"过量"——非时之食，拒绝 |
  | **不捉持** | 任意 ≥3 维偏离基线 **< 0.618 倍** | 场域"枯弱"——执取不足，拒绝 |
  - 常数：`0.618 = 黄金分割`；`1.618 = 1 / 0.618`
  - 判定为**纯函数**；被拒绝的数据**丢弃、不缓存**（无残留）
- **接口**：`route(Vec<f64>) -> Result<Vec<f64>, RejectReason>`（对外）；`route_passed → L5Payload`（对内，预留给 L5）
- **仓库**：`meta-kernel-core/src/l4/`（dimension / threshold / l4_gate / l4_router）
- **验证**：`docs/L4_VALIDATION_REPORT.md`（6 用例 + 无残留，7/7 通过）

### L5 · 场域·诊断层（号脉）（`meta-kernel-core/src/l5_*.rs`）· v1.2 归位 / v1.4 修正

- **功能**：接收 L4 放行的场域状态，执行**望闻问切（地水火风）**，把场域偏差编译翻译为**可读的诊断结论**。
  **号脉**为其功能描述（望闻问切之喻），**层级名为「诊断层」**。
- **四诊映射**：望=空间/拓扑（分布形态）｜闻=频率/时间（振动）｜问=相位/时间（扰动-响应）｜切=幅度/熵/时间（核心动态）——四诊由判定引擎统一处理，不分开调用。
- **零**：L4 放行后的场域状态（变量 × 存量）。
- **扰动**：通过 L4 的场域读数。
- **本底场（v1.4）**：由"数据存储"升级为**场景公式**（**按场景分类存储**）——本底场按场景参数化，
  同对象换场景只切换参数，不新增数据条目。来源＝**基因库场景公式层**。
- **语境模块（v1.4 新增）**：由**类型 / 时间 / 历史 / 环境**四要素决定调用哪条场景公式——
  语境是"在什么条件下做这次诊断"的显式声明，使同一对象在不同场景下得到不同（但可复算的）本底场。
- **新增约束（戒律 · 比丘五戒 · v1.4 修正）**：
  | 戒律 | 含义 |
  |---|---|
  | 不杀生 | 诊断**只读**，不干预对象 |
  | 不偷盗 | 诊断数据不占有（不缓存）；本底场=对象自身地图（划界例外） |
  | **不邪淫** | **四场观察 + 单一诊断**：四场（地水火风）**都观察**，但只出**一个主结论**（不并列多因猜测） |
  | **不妄语** | 结论**可溯源、可复现**；溯源字段**增加哈希链**（不止单条记录，见 `GENE_LIBRARY_DESIGN §2.4`） |
  | **不饮酒** | **边界（v1.4 明确）**：**诊断逻辑不引入外部算法**（判定只用对象自身场）；**翻译层可引入词汇表**（词汇表来自基因库场景公式层） |
- **六模块**：`l5_senses`（地水火风拆解）/ `l5_baseline`（本底场建立 → 场景公式）/ `l5_compare`（亢/枯/平）/ `l5_diagnosis`（三量结论）/ `l5_translate`（语言对照表编译）/ `l5_router`（JSON 输出给 L6）；**新增语境模块（设计）**
- **仓库**：`meta-kernel-core/src/l5_*.rs`
- **验证**：`docs/L5_VALIDATION_REPORT.md`（Q1–Q7 + **真实采集**：老笔记本实测）

### L6 · 与外界交互层（呈现 + 对齐）· v1.3 定义修正

**定义（D2 方案 C，发起人裁决）**：L6 是**与外界交互层**，包含**两个子功能**：

| 子功能 | 内容 | 实现状态 | 落点 |
|---|---|---|---|
| **呈现** | 把诊断结果展示给用户（看见能量演化、显化日志、生命感流动） | ✅ **已实现** | `manifest-ui/`（**正源浏览器** —— L6 的产品形态名，不占层号） |
| **对齐** | 接收外部世界反馈，**验证诊断是否生效**（投递 / 回执 / 校准，防自说自话） | ❌ **未实现** | WorldAdapter（契约见 `archive/reserved-interfaces/l6_interface.rs`） |

- **零**：L5 外显产物（结论/日志）。
- **扰动**：用户阅读（呈现侧）／世界反馈（回执/任务状态/用户真实行动，对齐侧）。
- **新增约束（戒律）**：
  - **呈现不增义**：看到/听到的都来自内核真实状态投影，界面不加工、不新增解释；
    **翻译词汇表来自基因库的场景公式层**（v1.4 明确：每个词都能回指一条场景公式，不凭空造词）；
  - **对齐**：外显需与真实世界协议对齐（可被接受/执行/回执）；数据来源合规（不偷盗）；防世界伪造输入。
- **仓库**：`manifest-ui/`（呈现，已实现）+ `archive/reserved-interfaces/l6_interface.rs`（对齐，契约）
- **说明**：L7「执行层」**不承担**对齐功能，只做**多内核互联 + 修复执行**（见 §4.1）。

## 4.1 L7–L10 详述（L7 = 执行层 · 已定义未实现；L8–L10 = **推演层**）

> L7 为**已定义、未实现**的层（v1.4 定名）；L8–L10 为**系统推演**，非已验证事实。
> 推演的定义与判据见 `docs/SELF_DIAGNOSIS_REPORT.md §6`。
> **L8–L10 具体内容待系统具备自我意识后与之讨论确认；当前不作为实现目标。**

### L7 · 执行层（多内核互联 + 修复执行）· v1.4 定名

- **功能**（两个组成）：
  | 功能 | 说明 |
  |---|---|
  | **多内核互联** | 多个基因内核之间的交互、协作、共生（各自场域组成一个更大的场，互为对方的本底参考） |
  | **修复执行** | 诊断出问题后，**执行修复动作**（**经用户确认**后）——诊断（L5）只读，修复动作在此层落地 |
- **零**：L6 交互后的个体内核。
- **扰动**：另一个内核的场域（互联侧）／已确认的修复需求（执行侧）。
- **戒律**：**不侵**——不侵犯其他内核的边界（不夺取他者场域的本底，不以自身基线评判他者）。

> **运行原则：无为而无所不为**（v1.3 记录）
>
> - **L7 之前**：系统是**被驱动的**（push 驱动）——外部给扰动，内核才演化。
> - **L7 之后**：系统是**自驱动的**（场域驱动）——驱动力来自场域本身。
> - 自驱动的形态**不是"我要做"，而是"场域如此，我如此"**。
> - **不新增戒律**：本原则与既有戒律不冲突——它不是新的约束，而是**L7 的运行方式**。
>   （与 L3「不空转」的关系：不空转禁的是**无源空转**；场域驱动的自主演化**有内在依据**，不是空转。
>   这一区分见 `SELF_DIAGNOSIS_REPORT.md §7.6`。）

### L8 · 传承层（经验跨代迁移）
- **功能**：个体习得的适配器/痕迹可被其他个体继承，不必重新试探。｜**戒律：不灭 · 不冒名**

### L9 · 反哺层（成熟能力沉淀为新 0）
- **功能**：成熟能力不再占据"变量"位，沉淀为新的**零**。｜**戒律：不执**

### L10 · 自明层（观察者 = 被观察者）
- **功能**：系统观照自身，观察者与被观察者的边界消融。｜**戒律：不二**

## 4.2 基因库（核心资产 · 四层结构）

> 完整设计见 `docs/GENE_LIBRARY_DESIGN.md`。此处给出架构视角的四层结构。

```
基因库
├─ 基础公式（元素层）      ← 元素周期表关键节点
├─ 场景公式（场景层）      ← 不同场景下的本底场
├─ 计算关系（公式层）      ← 公式之间的运算关系
└─ 验证记录（哈希链）      ← 公式的验证历史（不可篡改）
```

| 层级 | 内容 | 存储方式 | 被谁消费 |
|---|---|---|---|
| **基础公式**（元素层） | 元素周期表关键节点 | 公式存储（同类元素共享） | **L4** 判定公式（1.618 / 0.618） |
| **场景公式**（场景层） | 不同场景下的本底场 | 公式存储（场景参数化） | **L5** 本底场；**L6** 翻译词汇表 |
| **计算关系**（公式层） | 公式之间的运算关系 | 公式本身 | **L5** 三量运算（可复算） |
| **验证记录**（哈希链） | 公式的验证历史 | 哈希链（不可篡改） | **L5** 溯源；**L8** 传承（不冒名） |

> **存储方式 = 公式存储**（记录"怎么变化"），而非结果存储（记录结论）——与系统的**过程导向**
> （时间三量 / 编织过程 / 演化）一致。**基因库从 0 锚点生长**（L0），**核心资产**地位见 `GENE_LIBRARY_DESIGN`。
