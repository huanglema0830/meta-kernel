# 云内核 · 大模型接入（**骨架层**）

> **本目录是骨架（🔒 半公开），只写「做什么」，不写「怎么做」。**
> 按 **机制 17 拆分机制**（`TEMPLATES.md` §十）执行：**能公开的接口放仓库，不能公开的实现放仓库外私有文件夹**，
> 仓库里只留**指针**（`{PRIVATE_ASSETS}/llm/<路径>`）。
> **为什么必须这样**：本仓库为 **PUBLIC**（**R20**），"写进仓库"＝**对外公开**。

## 一、为什么云内核要接大模型

云内核自身**不带模型**（内核零依赖，**C1**）。大模型是**宿主侧**能力，经**接口**为内核提供
「**把模糊的话变成可执行的结构**」这一类服务（如目标拆解、自然语言→场域参数、异常解释）。

边界（**重要**）：
- **内核不调用模型**。内核只产出/消费**结构**；调用发生在**宿主**（`npb-gateway`）侧。
- 本机制只管**接入的接口与治理**（分级／降级／记账），**不含任何模型选择、密钥、路由实现**——那些在实现层。
