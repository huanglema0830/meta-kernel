# 接口 ③：成本记录（**骨架**｜🔒 半公开）

> **本文件只写「做什么」。** **价格、折扣时段、预算额度、汇总口径的具体取值**见实现层：
> `{PRIVATE_ASSETS}/llm/03_cost_tracking_impl.md`
> 归口：**机制 17 拆分机制**｜保密级别：🔒 半公开（C12）

## 一、职责（做什么）

**每一次**模型调用（含**分档**与**降级**这两类"元调用"）都留**一条账**；
账可**按日汇总**，产出**晨报**里的一段成本说明。

## 二、接口（形态）

```
记录  CallRecord {
        at:          调用时间
        stage:       调用发生在哪一步（分档 / 降级 / 正式调用 / 其它）
        grade:       本次实际用的档
        degraded:    是否降级（来自接口 ②）
        usage:       用量（token 或等价计量；**具体单位属实现层**）
        cost:        折算成本
        outcome:     成功 / 失败（含失败原因类别）
        task_ref:    关联到哪个任务（可回溯）
      }
查询  汇总(from, to) -> {
        total_cost, by_grade, by_stage,
        degrade_count,        // 降级次数
        degrade_loss,         // 因降级"少用了高档"的次数（质量损失的可观测代理）
        failed_count
      }
```

## 三、四条硬要求

| 要求 | 内容 | 为什么 |
|---|---|---|
| **① 无条件记账** | **成功要记，失败也要记**；降级的**每一步**都要记 | 只记成功会**系统性低估成本**（失败也花钱/也耗时） |
| **② 可回溯到任务** | 每条账带 `task_ref` | 否则无法回答"**哪个任务最贵**" |
| **③ 成本是"记录"不是"拦截"** | 本接口**只记账**，**不做预算拦截**（拦截属接口 ② 的"主动收缩"类） | 职责单一；且**拦截规则会变**，记账要能长期累积 |
| **④ 不得模糊化计量** | 用量与成本必须**逐条**给值，**不得**只给"大约""有调用" | 否则汇总出的数**不可用于决策** |

## 四、边界（**不做什么**）

| 不做 | 为什么 |
|---|---|
| **不存 Key／不存请求正文** | ⛔（C12）；账只存**计量与元信息**，不存内容 —— 也符合"**只存对象自身地图 + 标识**"的既有戒律精神 |
| **不在此文件写价格表** | 价格与折扣时段属 ⛔（实现层） |
| **不做对外发送** | 晨报是**本机产出**；任何对外动作须过 **C10** |

## 五、验收（可判定）

| 标准 | 判据 |
|---|---|
| **失败也留账** | 构造一次失败调用 ⇒ 账里**有**该条且 `outcome=失败` |
| **降级留痕完整** | 一次两步降级 ⇒ 账里**恰好两条**降级记录（不是一条汇总） |
| **可回溯** | 任取一条账，其 `task_ref` 能定位到任务 |
| **汇总守恒** | `汇总().total_cost` **等于**区间内逐条 `cost` **之和**（不得四舍五入失真） |
| **无内容泄漏** | 账内**不含**请求正文、Key、本机路径（C12 自查） |

## 六、与晨报的关系

晨报里呈现成本时，**必须同时给出**：
① **总额** ② **分档分布** ③ **降级次数与其代理损失** ④ **失败次数**
—— 只给总额 ⇒ **看不出"降级正在悄悄吃掉质量"**。
