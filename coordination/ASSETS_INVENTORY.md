# 云内核项目 · 私有资产盘点（指针）

> **本文件只是指针，不含资产内容。**
> **为什么**：本仓库当前为 **PUBLIC**（匿名 `curl` 可读取仓库内文件，实测 HTTP 200）。
> 若把**资产清单、保密分级、换壳对照表**写进仓库 = 把项目最核心的私有资产一次性公开，
> 与"盘点"的目的正好相反 ⇒ **全量清单存放于仓库之外的本地目录**（该目录不在 git 内，路径属 ⛔ 不入库）。

## 一、这份机制做什么

| 项 | 内容 |
|---|---|
| **机制名** | 私有资产盘点机制（`CHARTER.md` §三 机制 **16**） |
| **全量清单位置** | **私有文件夹**（仓库外）＝ **`{PRIVATE_ASSETS}/ASSETS_INVENTORY.md`**；路径真实值按 C12 属 ⛔，不入库、不外发、不拷给顾问 |
| **清单位置怎么找** | 环境变量 **`PRIVATE_ASSETS`** 指向私有文件夹（约定见 `TEMPLATES.md` **§十 拆分机制**） |
| **清单内容** | 五类独创资产（**模式 / 机制 / 流程 / 算法 / 术语**）× 四级别分级 ＋ **原术语↔物理语言对照表** |
| **触发词** | 「**资产盘点**」（复核资产增减与分级）｜「**语言替换**」（按已定档位执行换壳） |
| **变更留痕** | 本文件的**机制登记**写在此处；**资产内容**的变更写在清单文件自己的「更新记录」表里 |

## 二、三条边界（防止把"盘点"做成"泄密"）

1. **清单本体永不入库** —— 资产名、分级结论、换壳对照表都属 ⛔（按 C12）。
2. **语言替换不擅自执行** —— 先出对照表，**用户审核后再定替换范围**；且替换**不是一次性**的。
3. **执行换壳前先确认仓库可见性** —— 仓库仍为 PUBLIC 期间，"写进仓库"即等于"对外可见"；
   在可见性未定之前谈替换范围，属**假安全**（详见清单文件 §四 暴露面取证）。

## 二·补、与拆分机制（机制 17）的关系

本文件是**拆分机制的第一个落地实例**：**骨架（本文件，公开）+ 实现（`{PRIVATE_ASSETS}/ASSETS_INVENTORY.md`，保密）**。

| 层 | 在哪 | 写什么 |
|---|---|---|
| 骨架 | **本文件**（公开仓库） | 机制存在、清单在哪、三条边界 |
| 实现 | **`{PRIVATE_ASSETS}/ASSETS_INVENTORY.md`** | 39 项资产、分级、原术语↔物理语言对照表、替换四档 |

> **同一套做法已推广到通用工作流**：`coordination/workflows/sub/01..08` 的"实现层"节
> 由"[占位]"改为 **`{PRIVATE_ASSETS}/workflows/sub/0N_*_impl.md` 指针**（**模式**：`0N` 指 01–08 八个实现文件，骨架-实现一一对应；故此处按"模式"豁免存在性校验）。
> 规范与检查清单见 `TEMPLATES.md` **§十**。

| 机制 | 关系 |
