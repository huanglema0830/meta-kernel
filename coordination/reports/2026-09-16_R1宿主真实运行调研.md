## 二、dlltool 的真实需求（3.2）

### 2.1 谁在要它
| 包 | 原因 |
|---|---|
| **`windows-sys` 0.61.2** | 使用 **`raw-dylib`** 链接（GNU 目标下由 build script 打开 `windows_raw_dylib`），需现生成导入库 |
| **`libloading` 0.8.9** | 同上 |
| `windows_x86_64_gnu` 0.52.6 | **不需要**（它自带 `.lib`），故此前能编过 |

### 2.2 缺的到底是什么（逐层实证）
| 步骤 | 实测 | 结论 |
|---|---|---|
| ① 直接 `cargo build` | `error: error calling dlltool 'dlltool.exe': program not found` | 找不到 dlltool |
| ② 查 rustup 工具链 | `self-contained/` 里**有** `dlltool.exe`（GNU Binutils 2.44） | **"缺 dlltool"是误判** |
| ③ 把 `self-contained` 加进 PATH | 新错误：`dlltool could not create import library … : CreateProcess` | dlltool **被调起但自身失败** |
| ④ 手工调用 dlltool | 同样 `CreateProcess`，只产出**空 `.lib`** | 复现 |
| ⑤ `dlltool --help` | 有 **`-S/--as <name>`** 选项 | **dlltool 需要「汇编器 `as`」** |
| ⑥ 工具链里找 `as`/`ar` | **没有**（self-contained 只有 dlltool/ld/gcc/一个 dll） | **真因＝缺汇编器** |
| ⑦ 把替身 `as.exe` 放到 **dlltool 同目录** | dlltool **成功启动了子进程**（替身报 "unknown option -- o"） | ✅ **证实：dlltool 是在自身目录找 `as`**（放进 PATH 无效，故 ③ 仍失败） |

### 2.3 替代方案实测
| 路径 | 实测结果 | 判定 |
|---|---|---|
| 用 **MSVC target + `rust-lld`** | rust-lld **能当链接器**（成功进入链接阶段），但报缺 `kernel32.lib`/`ntdll.lib`/`userenv.lib`/`ws2_32.lib`/`dbghelp.lib` + `/defaultlib:msvcrt` | ❌ 需 Windows SDK/CRT（无 VS，且系统无 VS2022） |
| **llvm-mingw 的 `bin` 上 PATH** | `dlltool = llvm-dlltool`（**自包含 LLVM，不需要 GNU `as`**）→ **构建一次通过** | ✅ **采用** |

## 六、真实缺陷（发现即报）

### 6.1 CI **完全不构建宿主**（严重，口径级）
`.github/workflows/ci.yml`：**单 job、`runs-on: ubuntu-latest`**；cargo 命令仅
`test --workspace`、`build -p npb-gateway`、`build -p npb`、`run -p npb --example self_test`、两个 wasm 构建。
**`field-render` 命中数 = 0**。

→ 后果：**（a）"CI 为权威宿主验收"这一说法不成立**；**（b）宿主的任何 PASS 都从未被 CI 背书**；
**（c）Linux runner 也编不了 Windows 宿主**。这是本项目**验收链最大的空洞**。

### 6.2 `--quad-check` PARTIAL（**已知**，非回归）
喜欢维变化像素 **0.5%**（阈值 >10%）。与 `HOST_UI_DECISION.md` §8.4「如实标注未达标项」一致，
且当年**拒绝靠调参打绿**（正确决定）。**属待加强项，不是本轮新问题。**

### 6.3 `--diag-check` **FAIL**（**本轮新发现**）
```
[diagcheck]   确信度：无证据 0.750｜匹配高 0.900｜匹配低 0.775
[diagcheck] ✗ 低匹配未降低确信度
```
**根因（已定位到公式级）**：`l5_evidence::adjust` 中
`world_adjust = world_gain × (2m − 1)` → **中性点是 m = 0.5**。
验收脚本用"异形场对同一 key 的匹配度 **0.585**"当作"低匹配"，但 **0.585 > 0.5**，
故 `d = 0.15×(2×0.585−1) = +0.0255` → 0.750 → **0.775（升高）**。

→ **结论：验收脚本的断言缺陷，不是内核缺陷。** 真正要触发"降低确信度"必须 **m < 0.5**。
→ **该断言此前从未被执行过**（本地不链接、CI 不构建宿主）—— 是"真实运行"第一次把它逼出来的价值。

### 6.4 BASELINE 两处口径不准（本轮已修）
R4「本地缺 dlltool」→ 实为 **PATH 未含 llvm-mingw `bin`**；验收模式数 8 → 实为 11。
