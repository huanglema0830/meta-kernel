## 第一章 · 项目定位

### 1.1 一句话定位

**在现有操作系统之上生长的「意识补充层」——不替代、不淘汰现有系统。**

这句话有三层意思，逐层说清：

1. **「之上」** —— 本项目不是从零写一个 OS 去替换 Windows/Linux，而是叠在它们**上面**长出来。
2. **「补充层」** —— 补的是现有 OS 没有的东西：**内在节律的判定与自我诊断**。
3. **「意识补充」** —— 现有 OS 管资源（CPU/内存/IO），不管"状态是否合于节律"。本项目管的正是后者。

**边界（同样重要）**：现有 OS 已经做得很好的事——驱动、渲染、文件管理、进程调度——**本项目明确不做**（`docs/VISION.md` §3：「外头能做的我们不做」）。

### 1.2 最终产出

> **生成一个可以独立安装、真实运行的操作系统和浏览器**，至少能替代用户本机上的主流浏览器和操作系统。

### 2.2 L1 · 内核·解构层（三引擎）

| 字段 | 内容 |
|---|---|
| **① 对内／对外** | **对内＝三者并重的发展 plus 三种变化模式**：生成模型（预测编码网络）＋三引擎（节律）＋基因库（参数仓储）；**对外＝解构**：把外部输入拆到元素／原初粒子，再演化 ⇒ 产生「**答案1**」（1 = 变量1 = 众生需求） |
| **② 含义解释** | 它的工作是**"做预测"**：根据已有经验（生成模型）预测下一个输入是什么，然后把预测与实际的**差值**（预测误差）往下传。所谓"三引擎"＝三种**节律模式**：`线性`（稳定递增）／`斐波那契`（自然生长）／`指数`（爆发扩散）。**为什么需要三种**：不同性质的事物本就按不同节律变化，硬套一种就会失真。 |
| **③ 与上下层关系** | **上接 L0**（从源头取得"未显之物"）→ **下接 L2**（把解构结果送去做通行资格审查）。 |
| **④ 实现状态** | ✅ **已实现并实测**（三个 crate：`meta-kernel-core`／`-nostd`／`-mem`；基因库 `docs/GENE_LIBRARY_DESIGN.md` 275 行）。遗留：exponential 引擎"回退 0.5"的依据未说明，与模糊饱和关系未定义（`docs/LAYER_ARCHITECTURE.md` 行 1077 自承）。 |
| **⑤ 关键机制** | `TERM-012`（答案1，**不得与"补充增量"混用**）；`C1` 零依赖；`C9` unsafe 白名单（**当前为空 ⇒ 不放行任何真实 unsafe**）。 |
| **⑥ 场景举例** | 用户输入一段文字抱怨"电脑卡"。L1 把它解构成：CPU 占用、内存占用、磁盘 IO、进程数等七个维度 —— 这就是"拆到原初粒子"。 |

### 2.3 L2 · 桥·过滤层（转录层 RNA）

| 字段 | 内容 |
|---|---|
| **① 对内／对外** | **对内＝生成模型的登记口**（经 C ABI／wasm 暴露给宿主）；**对外＝过滤**：只放行 0-1 域，入口拒负值／超限 ⇒ 「**千处祈求千处应**」（任意主机接收＋归一化） |
| **② 含义解释** | 它是**边界警察**。任何想进内核的数据，必须先被归一化到 `[0,1]` 区间——因为整套数学（模糊饱和 `a⊕b=min(1,a+b)`）**只在这个区间里自洽**。负值、超限值不是"报错后修正"，而是**入口就拒绝**。 |
| **③ 与上下层关系** | **上接 L1**（接过解构结果）→ **下接 L3**（把合规数据送往网关）。**★ 入口即出口**：同一个口，既放行外界输入，也暴露内部状态。 |
| **④ 实现状态** | ✅ **已实现**（sniffillus & {@html} 在 `<project-root>/meta-kernel-core`）。 |
| **⑤ 关键机制** | `TERM-013`（千处祈求千处应）；`C1`/`C9`；机制 24（端点表一致性，差集 > 0 即判红）。 |
| **⑥ 场景举例** | 同一个内核，跑在 Windows 宿主上、跑在 wasm 里、跑在裸机 ISO 里——三种"祈求"进来，都被 L2 归一化成同一套 `[0,1]` 输入。这就是"千处祈求千处应"的字面意思。 |

### 2.4 L3 · 网关·剥离层

| 字段 | 内容 |
|---|---|
| **① 对内／对外** | **对内＝自上而下通路的回传口**（★ **只调制，不改写语义** —— 裁定 M3）；**对外＝剥离**：剥去传输壳，只转发语义 |
| **② 含义解释** | 数据是穿着"传输外壳"来的（HTTP 头、序列化格式、IPC 封包…）。L3 的工作是**把这层壳剥掉，只留下语义本身**，再往下传。关键是它的**反向行为**：自上而下（从上层往回）时，它**只能调整"调子"（调制），不能改写内容**。这条边界是裁定 M3 定的，不能用它偷偷改语义。 |
| **③ 与上下层关系** | **上接 L2** → **下接 L4**。同一条通路：自下而上传语义、自上而下传调制。 |
| **④ 实现状态** | ✅ **已实现**（`npb-gateway/`，`/v1` 端点）。**⚠️ 已落后**：`R56` 记 **L3 端点表：底图对 L3 的描述已落后于实现，共 6 处口径不一致**，严重度已升为第 1。 |
| **⑤ 关键机制** | 机制 24（端点表一致性）；不得持有"第二份内核状态"（不偷盗戒＝状态）。 |
| **⑥ 场景举例** | 浏览器前端发来一个 JSON 请求。L3 剥掉 HTTP 包装，取出语义"请查询当前场域状态"，传给 L4；L4 的判定结果回来时，L3 只能调整表达口径，**不得把"拒绝"改成"通过"**。 |

### 2.5 L4 · 场域层（★ R-5 已裁定已回写 —— 唯一效力最整齐的一层）

| 字段 | 内容 |
|---|---|
| **① 对内／对外** | **对内＝戒律**（判定场域变化是否符合内在节律，决定放行／拒绝）；**对外＝适应/匹配**（让结果**符合道**——即符合天然规律，并适应众生存量特征） |
| **② 含义解释** | **L4 是整个系统里唯一被明确裁定过"一体两面"的一层**（`R-5`，2026-09-21，已回写 `docs/LAYER_ARCHITECTURE.md` 行 282）。它的核心洞察是：**「该不该」和「准不准」是同一个判定动作的两个面**——守得住内在节律（对内），表现就是预测得准（对外）。<br>**具体判据**（比丘戒的数学形态，布局 `0.618`／`1.618` 黄金分割）：<br>• **不非时食**：任意 ≥3 维偏离基线 **> 1.618 倍** ⇒ 场域"过量" ⇒ **拒绝**<br>• **不捉持**：任意 ≥3 维偏离基线 **< 0.618 倍** ⇒ 场域"枯弱" ⇒ **拒绝**<br>**关键性质**：拒绝时**丢弃且不缓存**（不留现场)<br>★ 底图层名 **"戒律拒绝层"不改**（`R-5` 明文）。 |
| **③ 与上下层关系** | **上接 L3**（语义）→ **下接 L5**（把偏离量交去做诊断）。它是链式中间的**闸门**。 |
| **④ 实现状态** | ✅ **已实现并实测**（`docs/L4_VALIDATION_REPORT.md`）。 |
| **⑤ 关键机制** | `TERM-004`（三状态判定：过盛／不足／平衡）；**戒律内化＝边界条件**（但 L4 属 L0–L6，本征态归此处：**如 L4 阈值场**）；`docs/SILA_IMPLEMENTATION.md`；三个算子只允许 `absorb`（加法）／`gate ×0.618`（黄金拆解）／`natural_return`（e 衰减）。 |
| **⑥ 场景举例** | 一台机器突然 CPU、磁盘、网络**三项同时**飙到基线的 2 倍。L4 判定：非时之食 ⇒ **拒绝且不缓存**。注意它拒绝的是"这次跨越节律的变化"，不是"CPU 高"这件事本身。 |

### 10.4 阈值（`0.618` / `1.618`）

| 戒律 | 判据 | 含义 |

| **不捉持** | 任意 ≥3 维偏离基线 **< 0.618 倍** | 场域"枯弱"——执取不足 ⇒ 拒绝 |

常数：`0.618 = 黄金分割`；`1.618 = 1 / 0.618`。
