## 三、可证伪判据（**已实测**）

**问题**：口径差能否被**一条命令**检出？**答：能**（且不依赖构建产物）。

**实测命令与输出**（本机，`v0.259` 检出时点）：

```
$ python -c "
import re,subprocess
v=re.search(r'^version\s*=\s*\"([^\"]+)\"',open('Cargo.toml',encoding='utf-8').read(),re.M).group(1)
c=subprocess.check_output(['git','rev-list','--count','HEAD']).decode().strip()
print('banner 自报(pkg) =',v,' | 机制27(count) =',c,' =>', 'MISMATCH' if v!=c else 'OK')
"
banner 自报(pkg) = 0.2.0  | 机制27(count) = 261  => MISMATCH
```

**⇒ 判据可用性**：该命令**只读**（读 `Cargo.toml` ＋ 跑 `git`），**无需编译**，**正反可辨**（把 `Cargo.toml` 版本改成与 count 相同 ⇒ 输出 `OK`）。**可作为长期判据的骨架**。

**⚠️ 但它有已知盲区（须写明，否则会成假绿）**：
1. 它验的是「**源码声明的版本** vs count」，**不是「运行期 banner 实际打印的文本」**。若 ⑤/④ 链路被改动而 `Cargo.toml` 未动，本命令**不报警**。
2. **CI 侧会失效**（见 §四 风险 R-1）：CI 为**浅克隆**，`git rev-list --count HEAD` **不等于**真实版本号。
