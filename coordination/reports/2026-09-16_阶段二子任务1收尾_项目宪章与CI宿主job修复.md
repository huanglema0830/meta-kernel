## 三、真实缺陷（本轮新发现，均已修）

1. **R12 · 本地存在"伪装库"，本机长期靠它才能构建**
   本机 `llvm-mingw/…/x86_64-w64-mingw32/lib/` 里的 `libgcc.a` 与 `libgcc_eh.a`
   **内容是 `libunwind.a` 的拷贝**（两文件 md5 相同、成员名 `libunwind.cpp.obj`；时间戳 Sep 8，非官方包内容）。
   ⇒ 本机"能构建"**不可复现**，且"名字与内容不符"会污染诊断。
   **正解＝语义映射**：`libgcc.a ← lib/clang/<ver>/lib/windows/libclang_rt.builtins-x86_64.a`、
   `libgcc_eh.a ← x86_64-w64-mingw32/lib/libunwind.a`（LLVM 的真实现放到 GNU 命名上）。
   官方 **20260908 干净包**实测 `cargo build` → **exit=0**（1m51s，exe **180 MB**）。
   ✅ 本机 sysroot 已同步修正（原文件留 `.hackbak`）；CI 同法并在映射前断言映射源存在。
   ⇒ 顺带**解除**"钉住 llvm-mingw 版本"的错误约束（官方任何版本都不带 libgcc）。

2. **R13 · 断言步骤"哑失败"**
   GitHub 的 `shell: bash` 展开为 `bash --noprofile --norc -e -o pipefail {0}` —— **外层已带 `-e`**；
   步骤内 `set -uo pipefail` 只是再设置一次，**关不掉它**。
   ⇒ 被测程序一非零退出，脚本立即终止，`CODE=$?` 与 `cat 日志` 全被跳过（只见 `exit=101`、日志空白）。
   ✅ 验收①/②/③ 显式 `set +e` + `RUST_BACKTRACE=1`（与验收④对齐）。

3. **R14 · Dx12 后端下宿主根本起不来（真实用户会中招，不只是 CI）**
   `sort.wgsl` 的 `Splat2D.cov2d: mat2x2<f32>`：naga 的 **HLSL 后端**在把"整结构体赋值"
   （`dst[i] = src[i]`）降级为 HLSL 时，对矩阵成员生成的代码被 FXC 拒绝 ——
   `error X3018: invalid subscript 'cov2d'`（D3DCompile 0x80004005）→ `create_compute_pipeline` panic。
   本机走 Vulkan、不经 FXC，故长期未暴露；**而 Windows 用户的默认后端正是 Dx12**。
   ✅ 改为 `array<vec2<f32>, 2>`（与 `mat2x2<f32>` **布局完全相同**：对齐 8、16 字节，64 字节结构体不变）。
   ✅ 并给 `init_gpu` 加 `FIELD_RENDER_BACKEND=dx12|vulkan|gl|metal`（默认 `all`，行为不变），
   **使本机能在本地复现别处的后端差异** —— 不再"推上去碰运气"。
   ✅ 双后端实测（本机）：**Dx12 exit=0**（方差 84.0/600.2/876.8，157.8 FPS）／
   **Vulkan exit=0**（290.3 FPS），两后端**方差与 pHash 逐位一致**。

4. **R15 · 帧率断言的软件适配器识别不准**
   Dx12 的 WARP 是软件光栅器，但 wgpu 报的 `device_type` 是 `IntegratedGpu`
   ⇒ 只按 device_type 判，会把"软件渲染 28 FPS"当成"硬件不达标"。
   ✅ 改为**名字关键词优先**（`basic render driver|warp|software|llvmpipe|lavapipe|swiftshader`）。
   ✅ **反向验证（证明没放宽）**：真硬件 + 25 FPS 仍判**不通过**；WARP 28 FPS 判通过并如实标注。
