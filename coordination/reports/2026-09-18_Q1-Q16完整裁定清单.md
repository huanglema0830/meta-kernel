# P0 · 阻塞级（7 条）

## Q1 · L4 基线来源选取规则（甲／乙／丙）　`P0`

- **所属稿**：问题1 裁定稿 §1.1 三方案对比（行65–74）
- **问题**：L4 判定需要"基线/本底场"，而本底场是 **L5** 的产物 ⇒ 冷启动时 L4 用什么做基线？
- **选项**：**甲** 空基线（七维全 1.0 单位基线）启动，L5 产出后回填｜**乙** 基线独立前置（外部配置/场景声明提供，L5 不生产基线）｜**丙** L4 只判变量（改判变化率，绕开基线）
- **评估**：上轮定性为"循环依赖"是**过重的**——底图里"基线"有 ≥3 个已存在来源（`L4_VALIDATION` 行5 单位基线／`LAYER` 行200-201 基因库基础公式／`LAYER` 行222-223 L5 本底场）。**真问题不是"有没有基线"，是"什么时候用哪个"**——缺的是**选取规则**。
- **优势**：甲＝零改动即可生效、与既有验证口径一致｜乙＝语义最干净（L4/L5 解耦）、基线可审计｜丙＝从根上消除循环
- **劣势**：甲＝冷启动期"本底天然偏离 1.0"的对象易误拒｜乙＝需新增基线供给方（配置格式+场景声明+默认档）｜丙＝L4 全部 7 个测试要重写
- **风险**：甲＝**中**（老笔记本实测 high=2/7，**只差 1 维就越线**，**被拒数据丢弃不缓存 ⇒ 误拒不可恢复**）｜乙＝**低**｜丙＝**高**（与 `SILA` 行66–67「偏离基线 >1.618/<0.618」**直接冲突**，属改判据）
- **机会**：甲可挂"本底场成熟度"门槛；乙顺带解决 L7 多内核互联的基线来源（`L7 §1.2` 行65 交换的正是本底场引用）；丙让 L4 更像异常检测器
- **建议**：⭐⭐⭐ **采纳甲，但必须补"切换条件"**（见 Q2）
- **等待决策**：甲 / 乙 / 丙 三选一（或组合）

## Q2 · 甲 是否加"成熟度门槛"　`P0`

- **所属稿**：问题1 裁定稿 §1.1 第 4 条（行84）
- **问题**：本底场样本数不足时，L4 用单位基线判定，会不会误杀？要不要加降级保护？
- **选项**：加 / 不加
- **评估**：**这是 Q1 选甲后的必答题**。老笔记本实测：**七维中 high=2、判定阈值为 ≥3**，**只差 1 维就越线**。冷启动期本底场未建立，判定结果对本底天然偏离 1.0 的对象**极不稳定**。
- **优势**：加 ⇒ 冷启动期不误杀；被拒数据**丢弃不缓存**，误拒不可恢复 ⇒ 保护价值高
- **劣势**：加 ⇒ 判定规则多一条分支，实现与测试都要覆盖
- **风险**：**不加** ⇒ 冷启动期真实用户数据被拒且**不可恢复**；**加** ⇒ 可能漏掉真实的越界（降级为 Pass 并标记 `baseline_immature`，**可追溯**）
- **机会**：标记 `baseline_immature` 本身成为**可观测指标**——能统计"冷启动期降级次数"，反过来校准 N 的取值
- **建议**：**加**。具体规则：本底场样本数 < N 时，若判定为"拒绝"且 high/low 计数**恰好等于 3**（只差 1 维），则**降级为 Pass 并标记 `baseline_immature`**
- **等待决策**：加 / 不加

## Q5 · 人工确认能否算 WorldReceipt（路径 A）　`P0`

- **所属稿**：问题2 查证稿 §2.2（行177–181）
- **问题**：发起人的方案是"让用户确认一次"。**用户确认能否成为一份合法的 WorldReceipt？**
- **选项**：可（标 `source="human"`）／ 不可
- **评估**：⚠️ **发起人的方向对，但不能直接解**——因为 ① `WorldReceipt.status` 四态中"用户在自家 UI 点确认"最接近 `accepted`，但 `accepted` 的语义是"**真实世界**接受"，而自家 UI **不是真实世界**（是自家呈现层，`l6_interface.rs` 行15）；② 确认若发生在 manifest-ui，**不经 `deliver()`/`verify_receipt()`**，且正落在 `SILA` 行89「**拒绝伪造反馈输入**」的射程内。**所以不是"不用改底图"，而是"必须补一条映射规则"**。
- **优势**：可 ⇒ 一条定义即可让状态**诚实可判**（当前按 `SILA` 行89 判据，系统处于「未显化」）
- **劣势**：可 ⇒ 引入了"人工回执"这一非真实世界来源，需明确它**能证明什么、不能证明什么**
- **风险**：若**不标来源** ⇒ 人工回执与真实回执混同 ⇒ **校准权重被污染**（这是最实质的风险）｜若**不可** ⇒ 维持"未显化"状态，且无解
- **机会**：标 `source="human"` 后，回执来源成为一个**可枚举字段**，将来接真实 WorldAdapter 时可平滑替换
- **建议**：**可，但必须标 `source="human"`，且不参与校准权重**（只解除"未显化"状态，**不证明"显化有效"**）。补在 **L6 契约层**，**不动 `SILA` 行89 原文**
- **等待决策**：可（标 `source="human"`）/ 不可

## Q8 · 三引擎选取依据：物态 / 其他　`P0`

- **所属稿**：问题3 补齐稿 §3.2（行241–248）

- **选项**：**物态**（依 `GENE_LIBRARY` 行61 四档）／ 其他（储备、能量池等）
- **评估**：物态判据是**底图里唯一已有的、可直接引用的分档依据**（「入/出 >1.2 能量态；>1.05 气态；≥0.8 液态；<0.8 固态」），且与三引擎语义**天然对应**（固态↔线性平稳消耗／液态气态↔斐波那契历史递推／能量态↔指数临界相变）
- **优势**：有底图依据、不新增算子、确定性可复现、与既有口径（跨平台摘要 `4251318995`）不冲突

- **建议**：**用物态**。拟补条文：固态→线性／液态→斐波那契／气态→斐波那契／能量态→指数
