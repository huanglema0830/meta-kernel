## 三、★ 检验协议：把自检结果**编码成整屏颜色**

内核在入口处跑自检，然后**按结果刷整屏**：

| 颜色 | 含义 |
|---|---|
| **绿** `#00FF00` | 引导成功 **且** 自检全过 |
| **红** `#FF0000` | 自检失败 |
| 其它（黑/引导器画面） | 未进入内核 / 无帧缓冲 / panic ⇒ **一律判失败** |

**为什么这样设计**：一条断言（"截屏采样点 == 绿"）**同时**证明两件事 ——
① **引导器真的加载并进入了内核入口**；② **2.1 迁出的内核子集在裸机上真的算对了**。
比"截屏里有东西"这类弱断言强得多（对应 OBS-001：验收标准必须能回答"看什么数字/什么文件"）。

**自检覆盖**（全部与**字面真值**对照，裸机无 `std`）：
- `fmath`：`sqrt(2)`、`exp(1)`、`ln(e)`、`powi(2,10)` —— 顺带覆盖 2.1 交付的 4/7 个超越函数
- **L4 戒律判据**：温和场域 → `Pass`；偏离场域 → **必须拒绝**（**反向断言，防判据空转**）
- **四戒律风险判定**：正常输入 → `Cleared`；**触及他者 → 必须 `Refused(NotHarm)`**（不害红线）

### 6.2 ★ 首跑为什么红（真根因，已修，**非猜测**）

| 项 | 内容 |
|---|---|
| 现象 | `boot-image` 的"构建可引导镜像"步骤 `exit=101` |
| **真根因** | 拉日志逐行看 → **`error[E0463]: can't find crate for 'core'`** + `the x86_64-unknown-none target may not be installed`。报错发生在编译 `bootloader_api`（为裸机目标编译）时 |
| **为什么会漏** | 本机早在 **2.1** 就执行过 `rustup target add x86_64-unknown-none`（stable）⇒ **本机 target 已存在，掩盖了这个缺口** |
| 性质 | **R14 同族**："**本机绿 ≠ CI 绿**"（差异来自**环境既有状态**，不是代码） |
| **修法** | 不信"下次记得"：步骤改名为"…+ **裸机 target**"，显式 `rustup target add x86_64-unknown-none --toolchain nightly`，**并加显式断言**（`rustup target list --installed` 必须含它，否则 `::error` 退出） |

> **教训（可复用）**：新增一条工具链时，**"工具链" ≠ "工具链 + 组件 + target"**。
> 本机因为历史操作而"看起来齐了"，CI 才是**干净环境**的真相 —— 故 **CI 步骤里要把三件事都写全**
> （component ×2 + target ×1），且**每项都配一条断言**。
