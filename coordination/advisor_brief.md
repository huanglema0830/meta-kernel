## 三、最近讨论结论（时间倒序，最多 5 条）

1. **2026-09-16 晚**（机制 + 决策）
   - **R2 命名被纠正**：长期叫"SNI 摩擦"，实测**不是 SNI 拦截**，而是 **TCP 连接建立阶段的间歇性超时**（≈5%，与 **TLS 重协商**关联，Windows Schannel 路径）。
   - **对策**：切 **SSH over 443**（通道实测可达）——key 已生成，**待用户添加公钥**后一键切换（D19）。
   - **通用工作流**已独立成文件（八步场域演化，框架公开/算法保密），登记为第 11 项机制。
2. **2026-09-16 下午**（机制简化 + 门禁）
   - 机制**从"过度设计"简化为"能跑的最小集"**：CHARTER 改为**自包含**（前八节只读它就有全图）、活相机制**三文件合一**、新增 **C10 动作约束**、新增**启动回执**。
   - **"把诊断性步骤升为门禁"本身是最有效的探针**：验收④ 升为门禁后首跑即红，红出的正是被掩盖已久的宿主级缺陷（R17）。
   - 修掉三个真实缺陷：**R16**（门禁判据无词边界→误报变量名）、**R17**（宿主帧率门线无环境感知）、**R18**（独立 crate 的 3 个测试长期必红，因 CI 从不跑它）。
3. **2026-09-16 上午**（阶段二子任务1 收尾）
   - **CI 首次全绿**，且 `host-windows` job 上**真实开窗 + 从 surface 上屏纹理回读**通过（runner 无 GPU 落 Dx12 WARP）。
   - 为此修掉 **R12–R15**：本地"伪装 libgcc"不可复现（改语义映射）、GitHub `shell: bash` 自带 `-e` 导致断言哑失败、**Dx12 下 shader 编译失败**（真实缺陷，Windows 默认后端）、WARP 被误判为硬件。
4. **2026-09-16 早晨**（机制总纲）
   - 建立 `coordination/` 全套：CHARTER（总入口）/BASELINE/CONSTRAINTS/TEMPLATES/ROADMAP + instructions/reports/discussions 归档机制。
   - 确立**开工先读 + 启动回执**、**报告结束四步归档**、**优先级 P0–P4 与无响应推进**、**断裂接续话术**。
5. **2026-09-15 前后**（宿主真实运行）
   - **R1 解除**：宿主首次真实端到端运行（真实开窗 + 输入 URL + 取源码 + 上屏回读 PASS）。
   - 澄清 R4：**不是"缺 dlltool"，是 PATH 未含 llvm-mingw `bin`**——已固化为 CI 步骤。

- **技术主线**：阶段二子任务2 —— **元内核自举**。第一里程碑是"**能在 QEMU 里跑起来并按 DRM/KMS 输出场域画面**"。
