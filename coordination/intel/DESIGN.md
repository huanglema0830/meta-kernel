# INTEL · 外部信息情报机制（设计稿）

> **本稿性质：设计稿（只出稿）**。2026-09-21 产出，**未写入 `CHARTER.md`／`TEMPLATES.md`**；
> **机制编号登记留待次日授权**（本轮指令 §二.3 明示）。
> **落点**：`coordination/intel/DESIGN.md`（本文件）＋ `coordination/intel/INDEX.md`（总表）＋ `coordination/intel/INTEL-00N.md`（条目）。

## 〇、一句话

**把「外部世界发生的事」变成「本项目的动作」。**

采集 → 归档 → 触发 → 实施：**不采集＝无输入；不归档＝记不住；不触发＝白记；不实施＝空转。**

> **立法理由**：本项目已有机制覆盖「**内部**状态怎么维持」（机制 1–2、21–27），但**没有任何机制管「外部信息进来之后怎么办」**。
> 外部信息目前只有两条去路：① 写进当轮报告（**随报告沉底**）；② 留在对话里（**随对话消失**）。两条都**没有复核时点、没有触发条件**。
> ⇒ **INTEL 补的正是这一段**：给外部信息一个**带状态、带触发条件、带复核日期**的**容器**。

## 一、机制定位

| 项 | 内容 |
|---|---|
| **定位** | **外部信息情报机制** —— 采集 → 归档 → 触发 → 实施 |
| **输入** | 外部世界的事实（政策文件／竞品动态／技术风险／生态变化）＋ 本项目自身状态（阶段／里程碑／编号体系） |
| **输出** | ① `INDEX.md` 总表 ② `INTEL-00N.md` 条目 ③ **每轮报告中的「INTEL 状态表」** ④ 触发时的**准备稿** |
| **不在本机制内** | ❌ **不做自动爬取**（采集仍由人／当轮指令带入）；❌ **不自动实施**（实施＝对外动作，属 C10）；❌ **不替代 `advisor_brief.md`**（那份管**顾问侧**滚动摘要，本份管**外部情报**） |

## 二、三必填项（★ 核心 —— 机制必须绑到动作）

> **认知来源**（机制专家）：**机制不是靠"写规则"起作用，是靠"把规则绑到具体动作+触发+判定"起作用。**
> ⇒ 本机制**只写这三项**；三项之外的一切都是附注。

### 2.1 动作（**必须**，不是"可以"）

| 时点 | 动作（逐步，缺一不可） |
|---|---|
| **每轮开工时** | **① 读 `coordination/intel/INDEX.md`**（全表，不跳读） |
| | **② 检查每条的触发条件**（对照当前阶段／里程碑／事件） |
| | **③ 列出本轮触发的 INTEL**（含编号＋触发的判据依据） |
| | **④ 若该条状态为「待准备」⇒ 出准备稿**（落 `coordination/intel/prep/INTEL-00N_prep_<日期>.md`） |
| | **⑤ 报告含「INTEL 状态表」**（全部条目：编号／状态／触发条件／本轮是否触发／本轮动作） |

> **为什么把「读 INDEX」写成动作而不是原则**：原则（"应关注外部信息"）**无法自查**；动作（"每轮开工读 INDEX"）**可以在报告里被对照检查**——没写状态表＝没读。

### 2.2 触发（**三类**，每条必须归入其中一类）

| 类型 | 定义 | 判据写法（**须可判定**） | 例 |
|---|---|---|---|
| **时间触发** | 到某个**具体日期** | **写明 `YYYY-MM-DD`** | `下次复核 2026-12-21` |
| **事件触发** | 某个**可观测的内部事件**发生 | 写明事件名（须是本项目**可被确认**的事件） | `L7–L10 落地后` |
| **组合触发** | **多个条件同时满足** | 用 `＋` 连接，**全部满足才算触发** | `企业注册完成 ＋ 阶段三启动` |

> ⚠️ **禁止写法**（**空转**，R83 同族）：「条件满足时」「适当时候」「后续关注」——
> **不可判定的触发条件 ＝ 没有触发条件** ⇒ 该条**不得入表**（或必须降级为「已归档·无触发」）。

### 2.3 判定（**4 条可检查判据**）

| # | 判据 | 检查对象 | 触发违规的情形 |
|---|---|---|---|
| **J1** | **报告必须含「INTEL 状态表」** | 每轮报告 | 报告无状态表 ⇒ **违规**（＝本轮未执行动作 ⑤） |
| **J2** | **触发条件满足但状态未变 ⇒ 违规** | 每轮状态表 | 某条触发条件**已满足**，而状态**仍停在原值**、且**本轮动作栏为空** ⇒ **违规** |
| **J3** | **状态为「待准备」但无准备稿 ⇒ 违规** | `coordination/intel/prep/` | 表中状态 ＝ 待准备，而 `prep/` 下**无对应准备稿** ⇒ **违规** |
| **J4** | **状态为「准备中」但无具体行动 ⇒ 违规** | 每轮状态表 | 状态 ＝ 准备中，而**本轮动作栏只写"继续推进／在准备"**（**无可核验产物或时点**） ⇒ **违规** |

> **四条判据的共同点**：**全部落在"报告里能看见的东西"上**（状态表／动作栏／`prep/` 目录）。
> ⇒ **不需要新脚本**即可自查（**先人工承载，后议机器化** —— 与机制 26 同一路径）。
> **机器化的候选**：J1／J3 是**纯结构检查**（表存在性／文件存在性），可最先机器化；J2／J4 需语义判断，**暂人工**。

## 三、归档格式（**9 字段，缺一不可**）

| # | 字段 | 要求 | 反例（**不得写**） |
|---|---|---|---|
| 1 | **编号** | `INTEL-00N`，**只增不改、不复用** | — |
| 2 | **来源** | **URL 或明确定位**（"某网站"不算）；**核验状态须写明** | "网上看到" |
| 3 | **采集日期** | `YYYY-MM-DD` | "最近" |
| 4 | **内容摘要** | **≤3 句**，只写**事实**，不写**推论** | 把"我认为这很重要"写进摘要 |
| 5 | **与本项目的相关性** | **须写明短期／中期／长期** ＋ 依据 | "有关" |
| 6 | **可用性判断** | 高／中／低 ＋ **一句话理由** | 只写"高" |
| 7 | **状态** | 见 §四 **五态** 之一 | 自造状态名 |
| 8 | **触发条件** | 见 §2.2（**须可判定**） | "条件满足时" |
| 9 | **下次复核** | **日期 或 明确事件** | "有空时" |

## 四、状态流转（**五态，单向**）

```
观察中 ──触发条件满足──▶ 待准备 ──出准备稿──▶ 准备中 ──实施完成──▶ 已实施 ──结项──▶ 已归档
   ▲                                                                                    │
   └────────────────── 复核后判定"仍相关、需重新触发"（须写明理由，不静默回退）──────────┘
```

| 状态 | 含义 | 进入条件 | 下一态 | 允许停留轮数 |
|---|---|---|---|---|
| **观察中** | 已归档，触发条件**尚未满足** | 归档即进入 | 待准备 | 不限（**但须有「下次复核」**） |
| **待准备** | 触发条件**已满足**，尚未出准备稿 | J2 触发 | 准备中 | **1 轮**（超 1 轮无准备稿 ⇒ J3 违规） |
| **准备中** | 准备稿已出，正在形成可执行方案 | 准备稿落盘 | 已实施 | **3 轮**（超 3 轮须在动作栏写明阻塞原因） |
| **已实施** | 动作已落地（**记明落点**） | 实施完成 | 已归档 | **1 轮**（下一轮即归档） |
| **已归档** | 结项，**不再触发** | 结项 | ——（终态） | —— |

> **★ 单向性的意义**：状态**只会向前**（或按图上唯一的回头路径**写明理由**回退）。
> ⇒ **状态不变**这件事本身**就是信号**（J2 抓的正是"该动没动"）。
> ⚠️ **禁止**：把状态**直接**从「观察中」跳到「已实施」（**跳过"待准备／准备中"＝绕开 J3／J4 两条判据**）。

## 六、示例状态表（★ 以现有两条情报为示例 —— 即本轮归档的 `INTEL-001`／`INTEL-002`）

| 编号 | 状态 | 触发条件 | 本轮是否触发 | 本轮动作 |
|---|---|---|---|---|
| **INTEL-001** | 观察中 | 组合触发：企业注册完成 ＋ 阶段三启动 | ✗ 未触发（两条件均未满足：阶段定位＝**阶段二 · 2.4**） | 无（下一轮重新检查） |
| **INTEL-002** | 观察中 | 事件触发：L7–L10 落地后 | ✗ 未触发（**L7 设计完成、L8–L10 冻结中**） | 无（下一轮重新检查） |

> **★ 本表示例的自我检验**：两条**均未触发** ⇒ 按 **J2**，状态**保持「观察中」是正确的**（不算违规）；
> 若某轮**谎报"已触发"却不改状态**，或**已触发却仍写"观察中"且动作栏为空** ⇒ **J2 命中**。
> ⇒ **"全未触发"也是合法状态**（**不制造动作、不空转**）—— 这一点必须在报告里**明写**，否则会诱发"为了好看而硬触"。

## 七、与既有机制的关系（**不重复、不顶替**）

| 既有 | 关系 |
|---|---|
| **机制 18／C13**（顾问阅读指令） | **载体关系**：INTEL 状态表放在**报告正文**内，**不占第 0 行**；第 0 行**仍归 C13 专用** |
| **T-037**（复扫类改触发式） | **同构**：都属"**把动作绑定到可观测条件**"；T-037 管**内部复扫**，本机制管**外部情报** —— **同一模式的第二个实例** |
| **T-038**（CI 结论落笔门控） | **同族**：T-038 绑的是"**push 后的时点**"，本机制绑的是"**每轮开工的动作**" |
| **机制 26**（能力矩阵） | **同路径**：**先立表、后议机器化**；INTEL 亦**先人工自查 J1–J4**，不自建脚本 |
| **机制 16／20**（资产盘点／术语映射） | **须避让**：情报若涉及外部术语，**换壳仍走 `TERMS.md`**，本机制**不另立命名** |
| **`advisor_brief.md`** | **分工**：`advisor_brief` ＝ **顾问侧上下文恢复**（内部）；`INDEX.md` ＝ **外部情报台账**（外部）。**互不替代** |
