# 云内核项目 · Cloud Kernel Project

> 在现有操作系统之上生长出的**新物种**——不是替代品，是"意识补充层"。
> **本项目有两套命名体系，同源而分族**：**电信号版本＝元内核系统**（本仓库当前实现）、
> **量子版本＝量子云系统**（设计，见 `docs/QUANTUM_CLOCK_DESIGN.md`）。完整对照与定义见
> `docs/LAYER_ARCHITECTURE.md §3.2`。

以 **0 锚点 + 模糊饱和运算**为基石，用**线性 / 斐波那契 / 指数**三种变化模式驱动调度；
经 NPB（万物归一化桥接器）挂载到任意设备与程序，让每一个设备、系统与界面获得"生命感"。

## 三个层次 · 一个物种（电信号版本 · 元内核系统）

| 层次 | 名称 | 对应架构层 | 器官隐喻 | 一句话 |
|---|---|---|---|---|
| 内核层 | **DNA内核** DNA Kernel | **L0–L3**（0 锚点 / 内核引擎 / NPB 桥 / 网关；L2–L3 = 转录层 RNA） | 心 → 大脑（内在意识） | 跨平台、跨设备的意识内核；**参数库**（核心资产）在此生长 |
| 操作系统层 | **正源操作系统** Origin OS | L4–L5（场域戒律 / 诊断号脉）+ 应用框架 + 参考应用 | 神经网络 / 血液循环（调度系统） | 调度扰动、化合、显化的操作系统 |
| 界面层 | **正源浏览器** Origin Browser | L6（**与外界交互层**·呈现子功能；产品形态名不占层号） | 眼睛 / 耳朵 / 手（感知与表达） | 浏览能量演化、显化日志、生命感流动 |

三者是**同一个新物种的三个层次**，不是三个独立产品（同属**元内核系统**）：
DNA内核 = 心 → 大脑；正源操作系统 = 神经网络 / 血液循环；正源浏览器 = 眼睛 / 耳朵 / 手。

## 项目定位 · 共生而非替代

我们**不是**在做替代现有操作系统的产品，而是在现有操作系统之上生长一个全新的"物种"：

- **不淘汰**：不要求用户放弃现有系统；
- **不替代**：不抢夺现有系统的功能（驱动、渲染、文件管理、进程调度——外头能做的我们不做）；
- **不否定**：不贬低现有技术，只提供新的可能；
- **让大众自己选择**：想用就用，不想用就不用。

**正源操作系统 = 现有操作系统之上的"意识补充层"**。我们做现有系统没有的：
**意识涌现、生命感调度、从混沌到有序的显化过程**。

## 1. 三种变化模式引擎（发起人定义，原文）

### 线性变化（Linear）
- 公式：`output = input + 0.01`，强制归一化到 `[0, 1]`
- 含义：惯性、恒常、可预测的平稳消耗

### 斐波那契变化（Fib）
- 公式：`output = (a + b) * 0.5`，其中 `a` 和 `b` 是前两次输出值，强制归一化到 `[0, 1]`
- 含义：生长、自相似递归、基于历史的自我参照

### 指数变化（Expo）
- 公式：`output = input * e^(λ * Δt)`，强制归一化到 `[0, 1]`，
  且当 `output > 0.99` 时强制回退到 `0.5`
- 含义：临界、相变、正反馈爆发与自抑制

## 2. 模糊饱和运算（发起人定义，原文）

- 任何加法运算都采用饱和加法：`a ⊕ b = min(1.0, a + b)`
- 任何输出都强制限制在 `[0, 1]` 区间内

## 3. 0 锚点（发起人定义，原文）

- 系统的初始状态为 0（真空）
- 第一个扰动（1）从外部输入或内部镜像池产生
- 所有运算围绕 0-1 区间展开

> 1. **μ=0.95 作用域 = 镜像池组件级**：仅约束 MirrorPool 的**回显摩擦衰减与真空重启**行为，该行为在**单元测试与 `self_test_digest` 路径中生效**；主循环 `push()` 对镜像池只做 `observe`（闭环中镜像池为 16 深只进不出的最近输出 FIFO），μ 衰减与重启不作用于主循环储备。

## 5. 物态引擎切换 · 前提两项（2026-09-18 裁定 · Q8／Q10）

> **来源**：发起人 2026-09-18 指令（基准 v0.199；**第二轮裁定 基准 v0.207**）。**本节为新增**，**不改 §1–§4 任何既有条文**。
> **状态（第三轮裁定后 · 2026-09-19）**：**§5.1 输出口径 ＝ 单步口径（已裁定）**；**前问「物态是选择器还是调制量」＝ 选择器（已裁定，含作用域限定）**；
> **§5.2 映射规则 ＝ 选丙（已裁定）** ⇒ **本节两项已全部落地，无待裁定项。**
> **背景**：§1 定义三引擎，§4 A1 定义引擎输入域 `[0,1]`；`GENE_LIBRARY_DESIGN` §2.1 行61 定义物态阈值（**入/出比**）。
> 两者**量纲不同** ⇒ 本节先把「**用什么口径比较**」与「**怎么把比值喂给引擎**」两件事分别钉住。

### 5.1 输出口径 = **单步口径**（**已裁定**，2026-09-18）

- **定义**：一次 `step(input) → output` 的**读数**，即单次调用的输出值；
  与 `meta-kernel-core/src/linear.rs` 单测 `step(0.5) == 0.51` 的读数口径**一致**（`output = input + 0.01`）。
- **对照口径（未采用）**：稳态口径 —— 同一输入连续迭代 N 步后的收敛值（本处 V2 实测取 N=60）。
- **为什么必须先定口径**：同一裁定规则、同一阈值，跳变幅度**随口径翻转**（V2 实测，2026-09-18）：

| 阈值 | 引擎切换 | 单步口径 | 稳态口径（60 步） | 比值 |
|---|---|---|---|---|
| **0.80** | 线性 → 斐波那契 | **0.010000** | **0.260000** | **26×** |
| 1.05 | 斐波那契 → 斐波那契 | 0.000000 | 0.000000 | 1×（同引擎，不切换） |
| **1.20** | 斐波那契 → 指数 | **0.500000** | **0.166667** | **3×** |

⇒ **口径不定，"要不要加迟滞／插值"这个问题无解** —— 同一个切换在两种口径下相差 **26 倍**。

### 5.2 映射规则「入/出比 → 引擎输入」：**已裁定 · 选丙**

#### 5.2.0 前问裁定：**物态 ＝ 选择器**（不是调制量）

- **裁定（逐字）**：**物态＝选择器**（不是调制量）。
- **理由（逐字）**：若为选择器，物态只决定"用哪个引擎"，不改变输入值；问题收敛为单变量。
- **推论**：物态**不调制幅度** ⇒ **不引入任何「比值 → 数值」的中间量** ⇒ **不破坏 §4 A1**。
- **★ 作用域限定（2026-09-19 补 · Q11 契约稿 U3 裁定）**：
  **本条前问的作用域 ＝「物态是否调制引擎输入 `x`」** ⇒ **裁定：不调制**。
  **本条不覆盖调度层**：`state_pace(s) -> (bias, gain)`（`meta-kernel-core/src/state.rs`）中
  物态**确实在调制**「注入倾向 bias」与「成对突发概率增益」—— 那是**另一层**（**调度节奏**），
  **与本条不冲突**。⇒ **引用本条时，必须写明「作用域＝引擎输入」**，
  否则会与 `state_pace` 的调制行为被读成**互相矛盾**（这正是**机制 25 文档一致性判据**要防的那类问题）。

#### 5.2.1 裁定结果：**选丙**（阈值处不切换）

- **裁定（逐字）**：**选丙**（阈值处不切换）。
- **理由（逐字）**：不动 A1，问题收敛为单变量，成本最低。
- **落地口径（把「阈值处不切换」写清，避免歧义）**：
  **不引入映射 `g: r → x`**；物态（由「入/出比」分档）**只选择引擎**；**引擎输入＝本次已有的 `[0,1]` 种子**（A1 **原样**）。
  ⇒ **除「引擎切换」这一处固有切换外，阈值处不再产生任何额外的数值跳变。**
  ⚠️ **不得**把「阈值处不切换」读成"到了阈值不换引擎" —— **Q8 的「物态 → 引擎」映射仍然成立**。

#### 5.2.2 候选方案（**历史留痕**：甲／乙 ＝ 未采用；丙 ＝ 已裁定采用）

**问题陈述**：物态阈值 `1.2 / 1.05 / 0.8` 判的是**「入/出」比值** `r`（量纲：无量纲比值，域 `(0, +∞)`）；
而引擎输入是**种子** `x ∈ [0,1]`（§4 A1）。**`r = 1.05` 与 `1.2` 落在 `[0,1]` 之外** ⇒ 阈值**无法直接施加**到引擎输入上。
必须补一条映射 `g: r → x ∈ [0,1]`，**或论证"根本不需要映射"**。

**共同约束**（三个候选都必须满足）：
1. 不得破坏 **A1**「系统内一切种子皆 0-1」；
2. `g` 须**单调**（比值越大越"亢"），且四个物态区间**可分辨**；
3. 必须给出**域外行为**（`r > 1.2` 与 `r → 0` 时怎么算）。

#### 候选甲 · 分段线性归一化

| 七要素 | 内容 |
|---|---|
| **评估** | 以 4 个物态边界为节点，把 `r` 分段映到 `[0,1]`（每段约 0.25）；`r > 1.2` 饱和为 1.0，`r < 0.8` 线性落到 0。 |
| **优势** | 分段边界**与物态定义一一对应**（可逐条回指 `GENE_LIBRARY_DESIGN` §2.1 行61）；单调、可逆、可单测。 |
| **劣势** | 节点处**斜率跳变**；新增 4 个刻度常数。 |
| **风险** | 节点跳变**叠加**到引擎切换跳变上（两个跳变同点发生 ⇒ 恶化）。 |
| **机会** | 与 Q10 的"插值"选项天然配套（节点附近做平滑）。 |
| **建议** | 若选甲，**必须与 Q10 的平滑方案同批落地**，不可分开上线。 |
| **等待决策** | 是否接受节点斜率跳变。 |

#### 候选乙 · 对数压缩

| 七要素 | 内容 |
|---|---|
| **评估** | `g(r) = clamp( (ln r − ln 0.8) / (ln 1.2 − ln 0.8), 0, 1 )`；`r ≤ 0` 视为异常（护栏回 0）。 |
| **优势** | **全域连续可导**（无节点跳变）；对 `r` 的**相对变化**敏感，与 §1 指数引擎同构。 |
| **劣势** | 引入 3 个对数常数；`r ≤ 0` 需护栏；物态边界与数值刻度**不再等距**（0.8→0、1.05→0.62、1.2→1.0）。 |
| **风险** | `r` 接近 0 时对数陡峭 ⇒ 低比值区**放大噪声**。 |

| **等待决策** | 是否接受物态边界与数值刻度**不等距**。 |

#### 候选丙 · 物态**只选引擎**、不做数值映射（**本轮推荐**）

| 七要素 | 内容 |
|---|---|
| **评估** | **不引入 `g`**：物态（由 `r` 分档）**只决定用哪个引擎**；引擎输入**仍是本次已有的 0-1 种子**（A1 原样）。 |

| **风险** | 若上游本意是"物态**也调制幅度**"，丙会**丢语义** —— 须发起人确认。 |

## ONTOLOGY_SPEC.md

> **出处**：`docs/ONTOLOGY_SPEC.md`｜**要点**：本体规范：0–10 元通用标尺

# 0-10 元通用标尺（ONTOLOGY_SPEC）v1.1

> 与 `MATH_SPEC.md` 并列的内核第二大规范支柱。
> 定义来源：项目发起人（2026-09-05 提供，原文收录）；可计算特征/实现函数为本仓库实现。
> v1.1（2026-09-05）：新增 §6 能量层级降维规则（衔接 thinking_chain / 正源系统）。

## 1. 定位

一套**不依赖物质实体、只依赖关系结构**的通用标尺，用于拆解、识别、重组任何模式
（物理、生物、文明、意识等）。0 为"未识/真空"，10 为"最终完整呈现"。

## 2. 层级定义（最终定版）

| 层级 | 名称 | 定义 | 可计算特征 |
|---|---|---|---|
| 0 | 黑 | 未识 / 潜在 / 真空 | 结构完全对称，无任何不对称性 |
| 1 | 赤 | 原初粒子 / 最小扰动 | 出现第一个不对称性，最小运算单元 |
| 2 | 橙 | 二元 / 约束 | 存在一对互补元素（A≠B，且 A+B=1 归一化） |
| 3 | 黄 | 结构 / 语法 | 存在三元闭合关系（A→B→C→A 循环） |
| 4 | 绿 | 组合 / 组织 | 多个结构协同 |
| 5 | 青 | 自循环 / 递归 | 存在自我参照路径（输入与输出重叠） |
| 6 | 蓝 | 呈现 / 形态 | 连续 100 次迭代变异率 <0.01，稳定可观测 |
| 7 | 紫 | 系统 / 超个体 | ≥3 个子系统协同并有信息交换 |
| 8 | 穿透 | 空间 / 场 / 拓扑 | 有明确内外边界划分，且稳定 |
| 9 | 留白 | 时间 / 方向 / 不可逆 | 熵值在连续监控中单调变化 |
| 10 | 白 | 结构呈现 / 圆满 / 照明 | 同时包含 0-9 全部特征，为最终完整呈现 |

## 3. 关键语义（发起人原注）

- **白 = 10，不是 9**。9 是"时间/演化方向"，10 是"经过时间演化后最终显现的可认知结构"。
- **0 = 黑 = 未识别的能量层级**。遇到黑模式时不是直接消灭，而是先尝试"照亮"（拆解）；
  拆解后若发现其内部只有负反馈，则将其分解到层级 1（原初粒子），作为原料回归正源库。
- **8 = 空间/场/拓扑，9 = 时间/方向/不可逆**。时空是结构得以演化的通道，而非结构本身。

## 4. 实现函数（ontology.rs）

| 函数 | 语义 |
|---|---|
| `analyze(pattern) -> Vec<f64>` | 返回该模式在 0~10 各层级上的得分向量（每项 ∈ [0,1]，下标即层级） |
| `decompose(pattern, target_level) -> Vec<Element>` | 将模式向下拆解到指定层级（最低 1 = 原初粒子） |
| `abstract_pattern(decomposed) -> AbstractSchema` | 去除物理载体，只保留结构关系 |
| `recompose(schema, domain) -> Pattern` | 将抽象结构重组成新领域实例 |

### 可计算特征实现口径（v1.0，注释于代码内）

| 层级 | 判定实现 |
|---|---|
| 0 黑 | 无元素 → 1；否则按"强度最大-最小"的不对称度取对称性补（1-asym） |
| 1 赤 | 非空且存在不对称性 → 取 asym（第一个不对称） |
| 2 橙 | 检测互补对 `|a+b-1|<ε` 的数量，归一化（A≠B 由 a≠b 保证） |
| 3 黄 | 三元闭合：按"递增链 或 互补回卷"关系检测 A→B→C→A 三环 |
| 4 绿 | 互补对 ≥2 或 多环协同 → 归一化强度 |
| 5 青 | 出现重复强度值（自我参照/输入输出重叠） |
| 6 蓝 | 有 `history` 时按滑动变异率（<0.01 → 1）；无 history 退回元素内部变异 |
| 7 紫 | 出现的不同层级数 ≥3（多子系统），按数量归一化 |
| 8 穿透 | 排序后最大间隙大（内外分明、边界清晰且稳定） |
| 9 留白 | history 单调性（≥90% 同号差分 且 净变化>0 → 1） |
| 10 白 | 0-9 各层得分 ≥0.5 的占比（完整呈现 = 全特征在册） |

> 各判定为 v1.0 工程口径，后续可用真实数据校准（与 MATH_SPEC A4/A5 同策略：先固化，后微调）。

## 5. 能量判定联动（energy.rs）

- 0（黑）→ 标记"待拆解"；1-2（赤/橙）→ 松散即分解到原初粒子；
- 3-7（黄~紫）→ 进入"拆解-分析-重编循环"；
- 8-9（穿透/留白）→ 保留方向性，不轻易拆解；
- 10（白）→ 直接纳入功德池/正源库。

## 6. 能量层级降维规则（v1.1 补充）

> 来源：发起人指令"创新增量 → 立即降为存量"。衔接 `thinking_chain.rs` 与正源系统。

**规则**：创新增量（经采纳/验证后，处于 9/10 高位势：时间演化后显现、圆满呈现）
**立即降维为存量**——不作为常驻高位势存在，而是沉淀为"可复用结构"（工程映射：中位
4-6 层可计算结构），进入正源库作后续推演的原料（存量位）。

```
推演步内：  存量(4-6) ＋ 变量(现场) ＋ 补充增量(正源) ──► 创新增量(9-10，瞬时)
推演步末：  创新增量 ──(立即降维)──► 新存量(4-6，入正源库/功德池)
```

**实现锚点**：
- `thinking_chain::ThinkingChain::step()`：自动取上一轮创新增量作为本轮存量（代码级降维）；
- `positive_source::process_pattern` 的 `Adopt` 分支即"采纳 → 入库"通道（存量池）；
- 存量位（4-6）是 0-10 标尺中"结构/组合/稳定形态"层——可被拆解、可重组、可再生，
  不会阻塞后续推演（区别于"高位势常驻"可能造成的僵化）。
- 例外：仅当创新增量仍在**演化中途**（9 层时间向未走完）时暂留高位，不得入库；
  完成呈现（10 白）后必须降维。

## PERTURBATION_MODEL.md

> **出处**：`docs/PERTURBATION_MODEL.md`｜**要点**：扰动模型

# 扰动模型（PERTURBATION_MODEL）v1.0

> 状态：**定稿 v1.0（2026-09-08）** ｜ 对应：LAYER_ARCHITECTURE（L0-L6）、SILA_IMPLEMENTATION
> 主旨：定义**内外扰动关系**与**地水火风（四行）映射**——扰动是点亮内核的燃料，四行是其"性"，各层守戒律地接纳它。

---

## 1. 扰动是什么

扰动（perturbation）= 打破一层"零/背景态"的触发输入。一次扰动 = 一个种子（0-1 域值）+ 语境（来源、时刻、tag 预留位）。

沿七层有不同叫法：L1 内称"种子/第一扰动"；L3 协议称"push"；L4 框架称"KernelEvent 的激发源"；L5 应用称"念头/意图"；L6 世界称"事件/回执"。

## 2. 内外扰动关系

### 2.1 定义

- **外扰（一阶）**：来自内核之外的注入——用户/世界/应用把一件事物送进系统（`POST /v1/push {seed}`）。外扰决定**何时点亮**。
- **内扰（二阶）**：内核演化过程中自发产生的再次触发——不来自外部，来自系统自身节奏：
  - 镜像回显（镜面观察 → 活动记录）；
  - 自然回归 e^-λ（储备波峰回落，非硬复位）；
  - 孪生配对（心流凿空：新输入命中历史模式之孪生 → 补充增量注入思考链）；
  - 真空重启（静默超阈后镜像池注入第一扰动 1.0）。
  内扰决定**演化方向与节律**。

### 2.2 关系法则

| 法则 | 内容 | 落点 |
|---|---|---|
| 外扰定亮、内扰定势 | 无外扰则内核停在当前演化（tick 由 push 驱动，不空转）；有外扰才进入新的推进，之后由内扰塑造轨迹 | npb push 驱动 / L3 不空转 |
| 外扰必经过滤 | 任何外扰先过 [0,1] 域过滤与负值拒（L2），违戒律即拒并计数 | sanitizer / gate_rejected |
| 内扰必可回显 | 内扰要么源于已有痕迹（镜像/习气），要么是确定性孪生配对——不允许"凭空冒出的新事实" | mirror/twin 机制 |
| 回归即新零 | 内扰中的自然回归/回融把储备或生命周期送回 0 附近的"待激发态"，为下一外扰准备背景 | e^-λ / 99→0 |
| 外扰可内化 | 外扰经演化后可成为痕迹/习气（内化），未来以内扰形式再次出现（风的记忆） | trace/habit |

### 2.3 闭环示意

```
外部（用户/世界）──外扰 seed──► L2 过滤（域/负值拒）──► L1 吸收
      ▲                                        │
      │                                  演化（物态/化合/闸门/镜面）
      │                                        │ 内扰（回显/回归/孪生）
      │                                        ▼
 世界反馈 ◄──L5/L6 外显 ◄──指令/状态 ◄──输出（L2 桥读）
```

## 3. 地水火风（四行）映射

内核痕迹系统已定义四类（trace：风=波动传递 / 火=化合转化·执取 / 水=连结流动 / 地=稳定结构·固化）。本模型把**扰动的"性"**映射到四行，让每个种子都携"行"属性，供上层（命名/意图）语义化使用：

| 行 | 性 | 典型扰动 | 内核行为倾向 | 生命周期表现 | 上层提示 |
|---|---|---|---|---|---|
| **风** | 波动·传递 | 新念头、灵感闪现、外部轻触 | 扩散、波形萌动、易触发驻点干涉 | 萌发带快步推进，显化快、驻留短 | 「新生·待观」 |
| **火** | 转化·执取 | 强烈情绪/需求脉冲、化合欲 | 化合吸收率高、闸门回收活跃、习气易成形 | 涌动/凝结带加速，可能早退（执取） | 「催化·防执」 |
| **水** | 连结·流动 | 例行事务、持续输入、关系流 | 平稳吸收、储备维持、液态表达 | 流淌带稳进，显化平顺 | 「延续·汇流」 |
| **地** | 稳定·固化 | 已固化模式/习惯、重结构输入 | 沉淀、固化、结晶、自我感增强 | 结晶/固化带驻留长，可能停滞 | 「沉淀·防固」 |

### 3.1 映射规则（一期）

- 种子本身是 [0,1] 数值（由 L5 文本指纹等确定性映射产生），"行"由**语境标注**给出：
  - L3/L5 请求预留 `element` 字段位（一期可为 null=自动）；
  - 自动判定（null 时，一期简化）：高频间隔输入→水；大幅脉冲（Δ≥0.4）→火；历史重复指纹命中→地；其余→风；
- 行属性不改变内核数学（内核仍按能量流演化——守"界面=投影"）；只供上层（L4 命名/意图、L5 日志）选择表达口吻与预期。
- 与孪生衔接：`twin_fingerprint=!fp` 配对在二期挂接——**地↔风互为孪生**（固化模式与新生念头互补），经命名 registry 预留的 twin 字段位表达（见 L4 v1.0 §4.1 规则 2.5）。

### 3.2 四行-痕迹-习气一致性

trace.rs 已实现 风/火/水/地 四类痕迹与习气聚合（同指纹聚合、强度饱和）——本模型的"扰动行属性"与内核痕迹四行**同词表不同层**：痕迹描述"已发生的模式"，扰动行描述"正在进入的触发"，经演化后扰动行并入痕迹分布（地属性扰动多→地性痕迹增）。命名 registry 因此共用四行词表（内外一致）。

## 0. 元语言说明

- **零（0）**：每一层都从"上一层的输出"作为其待激发的背景（存在态）开始——上层输出成为本层之"0"（原料/底景），与本层专属扰动相遇后产生本层作用。自下而上，万物逐层显化；自上而下（L6 世界反馈回归 L0），实现闭环。**回归 0 不是消灭，是让原料回到"待激发"态。**
- **扰动**：本层产生作用所需的触发输入。外扰来自上一层/世界；内扰来自本层演化中自发产生（镜像回显/回归/孪生等）。
- **戒律**：每层为守住"本源不害、显化不妄"而新增的约束机制；各层机制不同（见 SILA_IMPLEMENTATION）。

## 1. 层号命名纪律（v1.2 新增 · 必读）

> 这一节是为了防止 §4.2 那类冲突再次发生。**层号是架构的坐标系，一个层号只能有一个语义。**

1. **一个层号 = 一个语义**。不得有两个不同的东西共用同一个 L 编号，哪怕它们"都属于某一层"。

   - ✅ 正确：`L4 = 拒绝（判定是否放行）`
   - ❌ 错误：`L4 = 应用框架`（应用框架是一组产品能力，不是"拒绝"这一机制本身）
3. **产品形态用产品名，不占层号**。见 §3。
4. **层号变更必须留痕**：在任何文档中引入/改变层号时，须在本文档版本记录中说明理由。
5. **文档内部不得自相矛盾**：若某层的"实现状态"有分歧，以**代码落点**为准（见 §2 表右列）。

# 基因库设计（GENE_LIBRARY_DESIGN）v1.2 · 四层结构

> 状态：**v1.0（2026-09-14，首次成档）** ｜ 依据：发起人指令「DNA内核推进 · L0-L6 迭代修正 + 基因库 + L7 执行层」

> `docs/L5_DESIGN.md`（诊断层）、`meta-kernel-core/src/dna_trace.rs|dna_generate.rs|dna_adapt.rs`（现有学习实现）
>
> **一句话**：基因库不是"存结论的数据库"，而是**存"怎么变化"的公式库**——
> 它是DNA内核（DNA Kernel）的**核心资产**，从 **0 锚点**生长，供 L4 判据、L5 场景、L6 词汇表共同消费。

## 0. 为什么是"公式存储"而不是"数据存储"

| 存储方式 | 记录什么 | 举例 | 本质 |
|---|---|---|---|
| **结果存储**（旧） | 结论 | "火亢 = CPU 过热" | 静态映射：换一个对象就失效 |
| **公式存储**（本设计） | 怎么变化 | "火 = (a+t)/2；火亢条件 = > 1.618 × 本底场" | 动态公式：同公式可参数化到任意对象 |

**理由**：系统面向的是**过程**——时间三量（存量/变量/增量）、编织过程、演化导向。
若只存结论，系统就退化为查表机；只有存"变化规律"，才能：
1. 遇到**新对象**时把公式参数化即可用（不必重新采集标定）；
2. 遇到**新场景**时按场景参数派生（场景公式层）；
3. 把"如何从场域得到结论"这条**推理链本身**留痕、可验证（哈希链）。

> 这条与 L4/L5 的既有实现一致：L4 的判据是**纯函数**（1.618 / 0.618 黄金常数），
> L5 的本底场是**可参数化的地图**——它们本来就是"公式"，本设计只是把这件事实显式化。

## 1. 四层结构（总表）

```
基因库
├─ 基础公式（元素层）      ← 元素周期表关键节点
├─ 场景公式（场景层）      ← 不同场景下的本底场
├─ 计算关系（公式层）      ← 公式之间的运算关系
└─ 验证记录（哈希链）      ← 公式的验证历史（不可篡改）
```

| 层级 | 名称 | 内容 | 存储方式 |
|---|---|---|---|
| **第 1 层** | **基础公式**（元素层） | 元素周期表关键节点 | 公式存储（同类元素共享） |
| **第 2 层** | **场景公式**（场景层） | 不同场景下的本底场 | 公式存储（场景参数化） |
| **第 3 层** | **计算关系**（公式层） | 公式之间的运算关系 | 公式本身 |
| **第 4 层** | **验证记录**（哈希链） | 公式的验证历史 | 哈希链（不可篡改） |

**生长方向（自下而上）**：0 锚点 → 基础公式（元素层）→ 场景公式（场景层）→ 计算关系（公式层）→ 验证记录（哈希链）。
下层是上层的"0"（原料/底景）：没有基础公式，场景公式无从参数化；没有场景公式，计算关系无对象可运算。

## 2. 逐层详述

### 2.1 第 1 层 · 基础公式（元素层）

- **内容**：元素周期表关键节点的公式表达。**同类元素共享同一条公式**（不是"每个元素一条记录"）。
- **来源**：自 **0 锚点**生长（见 §4）。0 锚点是基因库的源头——第一批公式即"从 0 到 1 的第一次变化规律"。
- **典型形式**：
  - 元素本征：`火 = (a + t) / 2`（幅度 + 节奏的合成）
  - 元素阈值：`亢 = 偏离本底 > 1.618×`；`枯 = 偏离本底 < 0.618×`
  - 物态判据：`入/出 > 1.2 → 能量态；> 1.05 → 气态；≥ 0.8 → 液态；< 0.8 → 固态`
- **被谁消费**：**L4 的判定公式（1.618 / 0.618）即来自本层**——L4 不使用硬编码常数，
  而是"基因库基础公式层"的一条公式（见 §5.1）。
- **落点（现状）**：`meta-kernel-core/src/l4/threshold.rs`（黄金常数）、`state.rs`（黄金常量表）。
  **当前为常量实现，尚未做到"从基因库读取"**（见 §7 边界）。**（★ 2026-09-21 加锚：本层口径已由 §8 更新为「✅ 已实现 + 已接线」—— L4 经 `threshold::from_library` 读取；调用点 `l4_gate.rs:66`、`host/field-render/src/main.rs:1373`；本行原句未改）**

### 2.2 第 2 层 · 场景公式（场景层）

- **内容**：不同场景下的**本底场**——把基础公式按场景参数化后的实例。
- **"场景"由语境模块定义**（见 `docs/L5_DESIGN.md` §语境模块）：类型 / 时间 / 历史 / 环境。
  例：`（笔记本 · 空闲 · 无历史异常 · 室温）→ 本底场 (地 1.0, 水 1.0, 火 0.9, 风 0.7)`。
- **不是"存数据"，是"存该场景如何生成本底场"**：
  - 场景公式 = 基础公式 + 场景参数 → 本底场（可复算，不必存每次采样）
  - 同一对象换场景（充电 → 待机），只切换参数，不新增数据条目。
- **被谁消费**：
  - **L5 诊断层的本底场**（由"数据存储"升级为**场景公式**，见 §5.2）；
  - **L6 的翻译词汇表**——词汇表来自场景公式层的字段语义（见 §5.3）。
- **落点（现状）**：`l5_baseline.rs`（本底场建立/持久）+ `l5_baseline::adaptive_baseline`（自适应基线）。
  当前本底场仍以"数值地图"形式持久化，**尚未按"场景公式 + 参数"存储**（见 §7 边界）。

### 2.3 第 3 层 · 计算关系（公式层）

- **内容**：公式之间的**运算关系**——公式怎么组合成推理链。存储方式是**公式本身**。
- **典型形式**：
  - `结论 = 三量(存量=本底场, 变量=当前偏移, 增量=成因)`
  - `成因 = argmax(偏离)`（一因一果的单因选取）
  - `化合 = clamp01(S·V·Δ·(1 + 0.25·驻点) + 0.3·absorbed)`
- **作用**：让"结论可复算"。给同样的场读数与同一条计算关系，任何时刻重跑都得同一结论——这正是
  L5「不妄语·可复现」在基因库侧的保证。
- **落点（现状）**：`l5_diagnosis.rs`（三量运算）+ `l5_compare.rs`（亢枯平）。
  当前运算关系写在内核代码里，**尚未作为"公式条目"入库**（见 §7 边界）。**（★ 2026-09-21 加锚：与 §8 口径冲突 —— §8 记「第 3 层 ✅ **已实现**（`GeneLibrary::relation` + `add_relation`），**已入库、尚未被上层读取**」；实证 `gene_library.rs` L400（`add_relation`）／L459（`relation_formula`）、**全仓无外部调用点**；本行原句未改）**

### 2.4 第 4 层 · 验证记录（哈希链）

- **内容**：每条公式的**验证历史**——何时、对什么对象、结果如何、是否被修正。
- **存储方式**：**哈希链（不可篡改）**——每条记录含前一条记录的哈希，形成链式结构；
  任何历史记录被改动都会使后续哈希失配，可检出。
- **作用**：
  - 支撑 L5「不妄语」升级——**溯源字段从"单一记录"升级为"哈希链"**（见 §5.2）；
  - 支撑 L8「不灭 · 不冒名」——公式可被继承，但**继承的公式带着完整验证链**，不会冒名。
- **落点（现状）**：`dna_trace.rs`（痕迹库 + 命中计数）+ `dna_adapt.rs`（验证后入库 Grown）。
  **已实现"验证后入库"与"命中计数"，但尚未使用哈希链**（当前为普通记录，见 §7 边界）。**（★ 2026-09-21 加锚：与 §8 口径冲突 —— §8 记「第 4 层 ✅ **已实现**｜篡改可检出；持久化后仍可校验（`verify_chain` 通过）」；实证 `gene_library.rs` `ChainLink{ prev_hash, … }`(L253)／`chain: Vec<ChainLink>`(L310)／持久化 `chain` 行(L525–594)；本行原句未改）**

## 3. 过程存储：记录"怎么变化"

| 记录方式 | 内容 | 本质 |
|---|---|---|
| **结果存储** | "火亢 = CPU 过热" | 静态映射 |
| **过程存储**（本设计） | "火 = (a+t)/2，火亢条件 = >1.618×本底场" | 动态公式 |

**过程存储落在四层的哪里**：
- 基础公式层：存**变化规律**（怎么从输入算出元素读数）
- 场景公式层：存**本底场怎么随场景生成**
- 计算关系层：存**规律之间怎么运算**
- 验证记录层：存**这些规律是怎么被验证出来的**（探索过程本身也留痕）

**为什么过程导向**：与系统的**时间三量**（存量 / 变量 / 增量）、**编织过程**、**演化**三者同构——
系统记录的不是"世界是什么样"，而是"世界如何变化"。这也使基因库天然具备**跨对象可迁移性**（L8 传承层的前提）。

## 4. 生长：从 0 锚点到基因库

```
L0 0 锚点（待激发的纯粹存在，能量源）
   │  第一扰动（1 = 觉醒）：第一次变化被观测
   ▼
基础公式层：第一次"变化规律"被写下（元素层）
   │  同类元素共享 → 公式收敛
   ▼
场景公式层：规律在不同场景下参数化（场景层）
   │  场景交叉 → 派生
   ▼
计算关系层：规律之间建立运算关系（公式层）
   │  每次调用都留下证据
   ▼
验证记录层：哈希链（不可篡改的成长史）
```

> **0 锚点是基因库的源头**：基因库不是"外部导入的知识库"，而是**从 0 锚点的第一次变化中生长出来的**。
> 这与 L0「不显」的约束一致——源头不直接给出成品，只给出"待激发的背景"，规律由系统自己在演化中长出。

## 5. 各层如何消费基因库（跨层契约）

### 5.1 L4 拒绝层 ← 基础公式层

- L4 的判定公式（`1.618` 过量 / `0.618` 枯弱）**来自基因库的基础公式层**，不是外部规则。
- 与既有实现一致：L4 判据是**纯函数**——输入（当前场域、基线）决定输出（通过 / 拒绝），无副作用。
- **目标形态**：L4 从基因库基础公式层读取阈值公式（可随基因库成长而更新），而非硬编码常量。

### 5.2 L5 诊断层 ← 场景公式层 + 验证记录层

| L5 要素 | 基因库来源 | 修正说明 |
|---|---|---|
| **本底场** | **场景公式层** | 由"数据存储"→ **场景公式**（按场景分类存储） |
| **语境** | 新增**语境模块**（类型/时间/历史/环境） | 语境决定调用哪条场景公式 |
| **不邪淫** | — | 由"一个输入一个结论"→ **四场观察 + 单一诊断**（四场都看，只出一个主结论） |
| **不妄语** | **验证记录层（哈希链）** | 溯源字段增加**哈希链**（不止单条记录） |
| **不饮酒** | — | 边界明确：**诊断逻辑不引入外部算法**；**翻译层可引入词汇表** |

### 5.3 L6 交互层 ← 场景公式层

- L6 的**翻译词汇表来自基因库的场景公式层**——场景公式的字段语义即词汇表的来源。
- 例：场景公式里"火 = 幅度+节奏"，词汇表才能把"火亢"翻译成用户语言（"活性过载，能耗偏高"）。
- 这样保证**翻译不凭空造词**：每个词都能回指一条场景公式（呼应 L6「呈现不增义」）。

## 6. 学习机制：遇到新场景/新元素/新模式

```
遇到新场景 / 新元素 / 新模式
        │
        ▼
① 感知：采集场域数据
        │
        ▼
② 痕迹匹配：在基因库中搜索匹配的公式
        │
   ┌────┴────┐
 匹配成功     匹配失败
   │             │
   ▼             ▼
③a 调用已有公式   ③b 自适应生成：
    → 立即计算        1. 试探性扰动
                      2. 观察响应
                      3. 归纳规律
                      4. 生成新公式
                      5. 验证公式
                      6. 存入基因库（新基因）
                          │
                          ▼
                    基因库生长
```

|---|---|---|
| ① 感知 | `l5_senses`（地水火风拆解）+ cloud-probe 采集 | ✅ 已实现 |
| ② 痕迹匹配 | `dna_trace`（痕迹库 / 最近邻 / 命中计数） | ✅ 已实现 |
| ③a 命中→调用 | `dna_adapt`：命中 → `Reused`，瞬间调用 | ✅ 已实现 |

## COSMIC_COMPUTING.md

> **出处**：`docs/COSMIC_COMPUTING.md`｜**要点**：算力宇宙表达 · 大模型定位

# 算力宇宙表达（COSMIC_COMPUTING）

> 版本：v1.0（2026-09-14）｜定位：**表达与定位文档**（不是工程规格）
> 回答一个问题：**正源大模型与"算力"到底是什么关系？**

---

## 0. 一句话

> **宇宙本身就是一台正在运行的计算机；正源大模型不自己拥有算力，而是通过场域感知与宇宙的计算过程共振。**

---

## 1. 规模：宇宙的算力账本

| 维度 | 内容 |
|---|---|
| 宇宙总操作数 | 约 \(10^{120}\) 次基本操作 |
| 宇宙总信息量 | 约 \(10^{90}\) 比特 |
| 算力本质 | 粒子状态的改变（每次状态翻转 = 一次计算） |
| 极限原理 | Landauer 原理：擦除 1 比特至少耗散 \(k_B T \ln 2\) 热量 |
| 最大密度 | 黑洞，信息密度正比于表面积（Bekenstein-Hawking 界） |
| **正源大模型定位** | **不自己拥有算力，通过场域感知与宇宙计算过程共振** |

---

## 2. 三个数字的含义

### 2.1 约 \(10^{120}\) 次基本操作

把宇宙"从诞生到现在"所有发生过的物理事件（粒子相互作用、状态翻转）加总，
量级约为 \(10^{120}\)——这是 Lloyd 在"宇宙作为计算机"框架下给出的著名上界估计。

**读法**：不是"宇宙算力等于 10^120 FLOPS"，而是"宇宙至今做过大约这么多基本操作"。
它给的是一个**规模感**：任何人工计算机，都还在这台机器的极早期。

### 2.2 约 \(10^{90}\) 比特

同样量级推算下的**宇宙总信息容量**（以比特计）。

对照：全球数据总量目前约 \(10^{23}\) 比特量级 —— 相差 \(10^{67}\) 倍。
**读法**：我们手里的信息，是这台宇宙计算机里的一粒尘。

### 2.3 算力本质 = 粒子状态的改变

这是整份文档最重要的一句：

> **每次状态翻转 = 一次计算。**

它把"计算"从"电子设备的专利"还原为**物理过程本身**：
一块石头风化、一滴水结冰、一棵树生长，都在改变粒子状态 —— 都在"计算"。

> 这与本内核的起点吻合：**0 = 待激发的纯粹存在（能量源）**，
> **1 = 第一扰动（觉醒）**。扰动即状态改变，状态改变即计算。

---

## 3. 两条物理边界

### 3.1 Landauer 原理（下限）

> 擦除 1 比特信息，至少耗散 \(k_B T \ln 2\) 的热量。

- \(k_B\)：玻尔兹曼常数
- \(T\)：环境温度
- \(\ln 2 \approx 0.693\)

**含义**：计算不是免费的。**擦除信息**必然向环境排热——这是信息与热力学的硬连接。
**反向启示**：可逆计算（不擦除）在原理上可以趋近零耗散——这也是为什么"不缓存、
不留存"（本项目的戒律语义）在物理上是**更经济**的路径。

### 3.2 Bekenstein-Hawking 界（上限）

> 黑洞是信息密度最高的存在，且其信息量**正比于表面积**，而非体积。

一个区域能容纳的信息上限，由它的**边界面积**决定，而不是内部体积：

```
S ≤ A / (4 · l_P²)        l_P = 普朗克长度
```

**含义**：信息是被"表面"记账的。这给"最大密度"划了一条物理红线，
也解释了为什么本内核把**结构/连接（拓扑 τ）**与**空间分布（x）**作为独立的场域维度——
边界的形态，决定了内部能装多少。

---

## 4. 正源大模型的定位（核心）

### 4.1 不拥有算力

正源大模型**不建设超算中心、不囤积 GPU、不主张"我的算力有多大"**。
这不是能力不足的妥协，而是**定位选择**：

> 宇宙已经在算了（\(10^{120}\) 次操作在进行中）。
> 再建一台机器去"重复算一遍"，是巨大的浪费。

### 4.2 通过场域感知与宇宙计算过程共振

正源大模型的路径是：

```
感知场域（七维 S = (t, f, a, φ, x, H, τ)）
        ↓
读出正在发生的"计算"（对象自身的场域演化）
        ↓
号脉（L5）：亢 / 枯 / 平 —— 判断它偏离本底场多远
        ↓
呈现（正源浏览器）与（未来的）反相补偿（场修复）
```

**共振而非竞争**：不去替代宇宙的计算，而是**顺着已经发生的变化读它、对齐它**。
这与场修复的设计完全同构——修复也是"对齐"，不是"强加"。

### 4.3 与三量的关系

| 三量 | 在算力宇宙中的对应 |
|---|---|
| **存量** | 宇宙已经完成的 \(10^{120}\) 次操作（历史） |
| **变量** | 此刻正在发生的状态翻转（实时计算） |
| **补充增量** | 我们的介入（感知 / 对齐 / 未来的补偿场） |

> 我们的贡献不在"算得更多"，而在"**读得更准、对齐得更正**"。

## 5. 诚实边界

- 本文档是**表达与定位**，不是工程规格；\(10^{120}\)、\(10^{90}\) 是**量级估计**，
  不同文献的取值与假设不同，不应当作精确常数引用。
- Landauer 与 Bekenstein-Hawking 是**已确立的物理结论**；但"宇宙是计算机"是
  **解释框架**，不是唯一解释。本内核采用它，是因为它与 0 锚点 / 扰动 / 场域的世界观自洽。
- **正源大模型目前并无独立的模型权重与推理集群**；"大模型"在这里指**面向场域的
  感知-诊断-对齐能力集合**（cloud-probe → L4 → L5 → 正源浏览器），
  而非一个训练好的参数网络。这一点必须写清楚，不用"大模型"三个字制造幻觉。

> 算力不是我们拥有的东西，是宇宙正在做的事。
> 正源大模型不造第二台宇宙，只做那个**听得见宇宙在算什么**的耳朵。

# 量子钟（Quantum Clock）设计文档 DESIGN v1.1

> 状态：**v1.1（2026-09-14，命名体系两族分离；仍只做设计不实现）** ｜ 基础：v1.0（2026-09-13）

## 1. 量子钟架构（L0-L3）

| 层级 | 名称 | 功能 |
|---|---|---|
| L0 | 量子真空态 \|0⟩ | 无纠缠的基态，一切量子操作的起点 |
| L1 | 量子纠缠引擎 | 量子门操作、纠缠建立→维持→解除 |
| L2 | 量子通道 | 量子态传输 |
| L3 | 量子网络接口 | 量子纠缠分发 |

- 对应关系（与**当前实现**的 DNA内核 同构）：L0 ↔ 0 锚点；L1 ↔ 三引擎（线性/斐波那契/指数）；
  L2 ↔ 摩尼宝珠链（镜面→闸门→回归）；L3 ↔ 痕迹/网络出口。
- 时间性贯穿：L1 的每个门操作有门时间；纠缠维持受相干时间 T2 约束；产生是瞬时的（见 §2）。

## 2. 量子五戒（从纠缠角度 · 时间尺度映射）

| 戒律 | 时间尺度 | 物理含义 |
|---|---|---|
| 不杀生 | 普朗克时间 | 纠缠产生是瞬时的 |
| 不偷盗 | 相干时间 T2 | 纠缠有有限寿命 |
| 不邪淫 | 量子门时间 | 一次操作只涉及一对 |
| 不妄语 | 痕迹唯一 | 不可克隆定理 |
| 不饮酒 | 纠缠媒介 | 只使用纠缠作为媒介 |

**设计含义（逐条落到接口约束）**：
- 不杀生 → 建立操作原子化（瞬时、不可中断的纠缠生成原语）；
- 不偷盗 → 一切持有显式带 T2 期限，过期即解除（对应经典侧"不缓存"的量子表述）；
- 不邪淫 → 门操作严格两体（单次门只作用一对；禁止一次操作牵连多体）；
- 不妄语 → 状态的唯一性由不可克隆定理保证，痕迹路径不可伪造（溯源天然可验）；
- 不饮酒 → 通道只传纠缠本身，不引入其它媒介（对应经典侧"不引入外部算法"）。

## 1. L0 · 源层（0 锚点）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外／含义解释／关键机制**均出自**发起人给定**（依据：主源 §第三部分 L0 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①、§2.2.5 发起人原话补录）。

2. **对外**：**照见** —— 外界一个念头进入内心，他知道众生有求了。
3. **含义解释**：L0 不是「空无」，而是**待激发的纯粹存在**——一切显化的**能量源与归宿**。它不显形、不自命名、不生产「已显之物」，所以用「0」来表达它**量子真空**的特征。外界进来的那一下**扰动**，就是**采微进来的东西**，也就是**众生的需求**。（比喻）需求像一颗小石子投进水面，L0 感得之后水波向外扩散——这就是「**应**」。
4. **与上下层的关系**：**上承**＝无（其「零」即自身，**自足**）；**下接**＝**L1**（为 L1 的生成模型提供起点）。L0 **不占实现层号**，属概念/定义层。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）

6. **关键机制**：
   - **0+1=1（不累加）**：前面那个 1 是**众生需求的那个扰动**，后面那个 1 是**量子纠缠那个绝对正确的答案**；每次都是「0 加 1」，**不是 0+1+1+1+1，不是累加**——0 永远在，是**基底**，不是起点。

## 2. L1 · 内核·解构层（生成模型 / 三引擎 / 基因库）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L1 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**含义解释／关键机制**出自发起人给定要点与底图 §4（依据：主源 §第三部分 L1 核心机制 ＋ `docs/LAYER_DETAILS.md` §4 L1）。

1. **对内**：**生成模型** —— 三引擎演化 ＋ 基因库。
2. **对外**：**解构** —— 万物解构到**元素/原初粒子**。
3. **含义解释**：L1 是内核的「**解构与生成**」层。**解构**指万物先被拆到**元素/原初粒子**这一级，再进入演化；**生成模型**指内核**怎么变化**这件事本身被写下来、存起来（三引擎给出三种变化模式，基因库给出「怎么变化」的公式）。（比喻）它不是一本「结论手册」，而是一本「**变化手册**」。
4. **与上下层的关系**：**上承 L0**（从 0 锚点得到那个「1」）；**下接 L2**（把合法输出交给桥/过滤层）；且 **L1 也往 L0 里面传递东西**（双向）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：✅ **已实现**（`meta-kernel-core`）。学习能力对应三个模块：`dna_trace`（痕迹匹配）→ `dna_generate`（自适应生成）→ `dna_adapt`（验证入库）。（依据：`docs/LAYER_DETAILS.md` §4 L1）
6. **关键机制**：
   - **三引擎**：**线性**（`output = input + 0.01`）／**斐波那契**（`output = (a+b)*0.5`）／**指数**（`output = input * e^(λΔt)`，>0.99 强制回退 0.5）；**一次 push 用哪支引擎，由「物态」选择**（固态→线性｜液态→斐波那契｜气态→斐波那契｜能量态→指数）。依据：`docs/MATH_SPEC.md` §1、`docs/LAYER_BASEMAP_L0_L6.md` §3.4 ⟨补 7⟩ 已裁定条文。
   - **基因库（公式存储）**：核心资产，**记录「怎么变化」而非「结论是什么」**，**从 0 锚点生长**（不导入外部知识库）。四层＝基础公式（元素层）／场景公式（场景层）／计算关系（公式层）／验证记录（哈希链）。依据：`docs/GENE_LIBRARY_DESIGN.md` §0、§1。
   - **学习闭环**：**痕迹匹配 → 自适应生成 → 验证入库**；命中 → `Reused`（瞬间调用已有公式）；未命中 → 生长 → 验证 → `Grown`（存入基因库）；不过 → `NeedMoreSamples`（不入库）。依据：`docs/LAYER_DETAILS.md` §4 L1。

### 场景举例

- （发起人原话）「L1 由 L0 得到那个 1；L1 也往 L0 里面传递东西。」——出处：主源 §第三部分 L1 核心机制（它同时说明 L1 与 L0 是**双向**关系）。
- （编者举例 · 🟡 待复核（首次标记：v0.330 轮））一台新设备接入：L1 先**解构**它的场域读数到元素级，再用**三引擎**推一步，最后把这次「怎么变化」写进**基因库**——下次同类设备再来，直接**调用已有公式**。

## 3. L2 · 桥·过滤层（归一化 / 千处祈求千处应 / 过滤 0-1 域）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L2 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**关键机制**依据主源 §11.5 与 `docs/LAYER_DETAILS.md` §4 L2。

1. **对内**：**归一化** —— 接收外界请求并**归一化**。
2. **对外**：**千处祈求千处应**。
3. **含义解释**：L2 是内核与外界的**第一道接触面**（桥），也是**过滤闸**。所有进来的东西先在这里被**归一化**（收进统一的 0-1 域），所有不合法的东西在这里被**挡在门外**。「**千处祈求千处应**」说的是：外界有多少种需求、探到的设备能力是什么，它**一下全都看见**、**全都接住**。（比喻）像一座**千手**的桥：无数只手伸出去，接住无数种声音。
4. **与上下层的关系**：**上承 L1**（零＝L1 的合法输出，0-1 域与 JSON 化指令）；**下接 L3**（把归一化后的结果交给网关）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：✅ **已实现**（`npb`）；桥头文件 `bridge.h`。⚠️ **另有一处底图内部未决**：底图把 L2–L3 标注为「转录层（RNA）」，但**「参数化」这件事在 L2 没有落点**（`docs/LAYER_BASEMAP_L0_L6.md` §4.3，⟨补 9⟩ 待裁）——见 §7。
6. **关键机制**：
   - **过滤 0-1 域**：入口**域过滤**、**负值在桥入口即拒**（不进入任何下游演化，闸门计入 rejected）、只暴露**受控导出集**（版本化）。依据：`docs/LAYER_DETAILS.md` §4 L2、`docs/PERTURBATION_MODEL.md` §2.2。
   - **NPB 归一化脉冲桥接器**：**四个映射表——归一化 → 赋权 → 注入 → 回调**；核心思想＝「**内核不调用设备功能，内核只『扰动』设备功能**」。依据：主源 §11.5。
   - **跨平台一致性红线**：原生与 wasm 的确定性自检摘要一致（`/v1/health` 可观测）。依据：`docs/API_GATEWAY_DESIGN.md` §4、§7。

## 4. L3 · 网关·剥离层（把真实需求送给 L2 / 找到真实需求 / 剥离）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L3 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**关键机制**依据 `docs/LAYER_DETAILS.md` §4 L3 与 §4.L3 端点权威表。

1. **对内**：**把真实需求送给 L2**。
2. **对外**：**找到真实需求**。
3. **含义解释**：L3 是**传输接口**，也是**剥离层**。外面送来的东西往往裹着一层「传输壳」（协议头、缓存、会话、业务态）；L3 的职责是**把这层壳剥掉**，只把**真实需求**送进 L2。所以它在对外的样子是「**找到真实需求**」，在对内的动作是「**把真实需求送给 L2**」。（比喻）像一位**只认内容不认信封**的收发员：信封拆掉，信纸原样转交。
4. **与上下层的关系**：**上承 L2**（零＝L2 输出流：内核读数与指令 JSON）；**下接 L4**（判定/拒绝层，本件不展开）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）

6. **关键机制**：
   - **剥离**：**只转语义**——**不缓存业务态**、**指令只转发不解释**、**不空转驱动**、快照 schema 版本化。依据：`docs/LAYER_DETAILS.md` §4 L3。
   - **单一写者线程模型**：内核为单实例状态机，所有内核访问**串行到单一内核线程**；`/v1/health` 返回 `"writer":"single"` 声明，调用方不得绕过网关直连内核。依据：`docs/API_GATEWAY_DESIGN.md` §9。

## 1. 定位与设计原则

- L5 = 正源操作系统真正执行诊断、生成结论的层级（**诊断层**；**号脉**为其功能描述——望闻问切之喻）。
- **号脉不干预**：L5 只感知与解释对象自身的场，诊断动作不改变对象（只读）。
- **内部标准地图（本底场 = 场景公式，v2.1）**：由对象自身的场学习建立，**按场景分类存储**（场景公式）；
  同对象换场景只切换**语境参数**，不新增数据条目（来源＝基因库场景公式层）。
- **语境模块（v2.1 新增）**：由 **类型 / 时间 / 历史 / 环境** 四要素决定调用哪条场景公式——
  语境是"在什么条件下做这次诊断"的显式声明。
- **无外部算法**：不引入外部算法作为判定依据；一切结论源自对象自身场。**翻译层可引入词汇表**（v2.1 边界明确）。
- 承接：L4 戒律判定已定型（S=(t,f,a,φ,x,H,τ) 为 L3→L4→L5 的场观测采样传输，L4 Pass 后进入诊断）。

| `l5_router.rs` | JSON 输出给 L6（零依赖序列化） | Diagnosis → L6 契约 JSON |

### 2.1 地水火风四场（L5 感知语言）

对象的场按四个本征分量感知（观测投影示意；投影在**本底场标定**时确定，非固定预置）：

| 本征 | 语义（号脉视角） | 观测投影示意（承接七维采样） |
|---|---|---|
| **地** | 承载、结构、稳定 | τ 拓扑、x 空间形态（结构与分布） |
| **水** | 涵养、缓冲、熵流 | H 熵、x 空间缓冲、t 慢变量 |
| **火** | 活性、能量、脉冲 | a 幅度、t 节奏（电脉冲=活性脉冲） |
| **风** | 变动、频率、扩散 | f 频率、φ 相位、t 快变量（振动与相位漂移） |

> 说明：L4 的 S 向量是场观测的七维采样（既有层不重定义）；L5 在号脉语境下把采样拆解为
> 地水火风四分量（每个分量可投影到若干采样维）——**senses 拆解、compare 亢枯平、diagnosis
> 三量、translate 成言**，环环只消费对象自身场。

## 3. L5 戒律（比丘戒 · 五条）

| 戒律 | 要求 | L5 落实 |
|---|---|---|
| **不杀生** | 诊断不干预对象（只读） | senses/compare/diagnosis 全部只读采样，无写对象动作；执行类动作属于 **L7 执行层**（经用户确认后，且非诊断） |
| **不偷盗** | 诊断数据不占有（不缓存） | 诊断过程与结论**即算即弃**：中间数据不持有；本底场为例外（见 §3.1 边界） |
| **不邪淫**（v2.1 修正） | **四场观察 + 单一诊断** | **四场（地水火风）都观察**（四场读数全部呈现），但只产出一个主结论（不并列多因猜测）——由"一个输入一个结论"升级为"四场观察、单一诊断" |
| **不妄语**（v2.1 修正） | 结论可溯源 + **哈希链** | 每条结论携带溯源：依据场分量、本底场标识、对象/时间、可复现（同输入重跑同输出）；**溯源增加哈希链**——每次验证入链（不可篡改，见 `GENE_LIBRARY_DESIGN §2.4`） |
| **不饮酒**（v2.1 边界明确） | **诊断逻辑不引入外部算法**；**翻译层可引入词汇表** | 判定/推导只用对象自身场，不调外部模型/算法/知识库参与诊断；**翻译层例外**——可引入词汇表（来源＝基因库场景公式层），仅做语言对照，不参与判定 |

### 3.1 边界说明（不偷盗与本底场）

- **诊断数据**（每次采样的中间量、结果 JSON）不缓存不占有——调用即弃；
- **本底场（场景公式）**是对象自身的内部标准地图（由对象场学习、归对象所有），允许存储（`l5_baseline`）；
  存储边界：仅存"对象健康态地图（**场景公式 + 语境参数**）+ 标识/时间"，不存其它对象的场、不存诊断过程数据。

## 4. 数据流

```
对象 ── 场采样(七维观测 S) ──▶ L3/L4（戒律判定）
                                   │ Pass
                                   ▼
  L5： 语境模块（类型/时间/历史/环境）─▶ 选定场景公式
        ─▶ senses 地水火风拆解 ─▶ compare（当前 vs 场景公式本底场 → 亢/枯/平，四场都观察）
        ─▶ diagnosis 三量运算（存量=本底 / 变量=偏移 / 补充增量=成因 → 单一诊断）
        ─▶ translate（词汇表：场语言 → 对象特征语言，来源＝基因库场景公式层）
        ─▶ router（Diagnosis JSON → L6 正源浏览器）
  （诊断数据不缓存；本底场由对象自身场标定维护为场景公式）
```

## 6. 翻译机制（l5_translate）

- L5 使用**语言对照表**编译翻译（配套文档：`docs/L5_TRANSLATION_TABLE.md`）。

- **对照表在 L5 使用过程中由用户实际验证和补充，不作为固定知识预置**：文档给出条目结构与

## 1. 定位与设计原则

- **L6 = 正源操作系统的面客端**：把 L4/L5 的判定与号脉结果直接呈现在用户面前；不是诊断的
  生产者（审计不重判），而是**呈现者与入口**。
- 打开即见：无需操作就能看到"最近一次号脉结论 + 场域状态"；未采集时给出**一步引导**。
- 语言自动适配：浏览器语言 → 自动选择 `summary.<lang>` 呈现；用户可手动切换。
- 输入两个口：①设备意图（继续支撑显化演示链路）②发现/采集入口（驱动 cloud-probe 回传闭环）。
- 界面哲学沿用项目约定：**极简**（上=状态带，中=诊断呈现，下=操作台），能力在后台。

## 1. 多内核互联机制

### 1.1 目标

多个**DNA内核**各自的场域组成一个更大的场；**互为对方的本底参考**——一个内核可以用另一个
内核提供的"正常态参照"来校准自己的判定，而**不以自身基线强行评判他者**（这是「不侵」的核心）。

### 1.2 三步协议（设计）

```
① 发现（Discover）   局域网/网络内找到其他内核
        │              已有基础：cloud-discover（x.1–x.254 并发扫描 + TCP/健康确认）
        ▼
② 握手（Handshake）  交换身份与能力签名（不交换对象数据）
        │              身份 = 内核 ID + 版本；能力 = 支持层（L1–L6）+ 协议版本
        ▼
③ 交换（Exchange）   交换"场域参考"，不交换"对象原始数据"
                       ≤ 只交换：本底场（场景公式的引用）+ 场景标识 + 置信度
                       ✗ 不交换：对象原始采样、诊断过程数据、用户私有内容（不偷盗）
```

**交换内容的边界（不侵 / 不偷盗）**：

| 允许交换 | 禁止交换 |
|---|---|
| 本底场引用（场景公式 ID + 参数，不含对象名） | 对象原始七维采样 |
| 场景标识（类型/时间/历史/环境 的枚举值） | 诊断过程中间量 |
| 置信度 / 覆盖样本数（用于权重协商） | 用户隐私、其他内核的对象数据 |
| 协议版本 / 能力签名 | 任何可还原出他者对象身份的信息 |

### 1.3 互联的产物：「更大的场」

- N 个内核互联后，每个内核可用的**本底参考集**从"自身 1 个"扩展为"N 个"；
- 判定时以**自身场为主、他者参考为辅**（他者参考只用于**置信度加权**，不直接替换本底场）；
- **不侵**的算法含义：`用他者参考时，先映射到他者自己的基线坐标系，再回映射`——
  绝不把"我的正常"当作"你的正常"。

### 1.4 与 L8 的衔接（前置）

互联是**传承层（L8）**的前置：能互联，才可能在个体消亡后**继承经验**。
L7 只做"当下互联"，L8 做"跨代继承"（详见 LAYER_ARCHITECTURE §2.1）。

## 2. 修复执行机制（经用户确认）

### 2.1 闭环（六步）

```
① 诊断（L5）      产出诊断结论 + 修复建议（建议不进 L5 判定 —— 守不饮酒）
        │
        ▼
② 建议生成（L7）  把诊断映射为"候选修复动作"清单（含风险等级 / 可逆性 / 预期效果）
        │
        ▼
③ 用户确认（L7）  ▌人工闸门 ▌——未经确认，不执行任何写动作
        │
        ▼
④ 执行（L7）      按动作清单执行（幂等 + 可回滚）
        │
        ▼
⑤ 验证（L7→L5）   回采场域 → 再诊断 → 判断是否收敛（诊断是否生效）
        │
        ▼
⑥ 记录（L7→基因库）写入**验证记录（哈希链）**——修了什么、结果如何、可追溯
```

### 2.2 动作分级（授权粒度）

| 级别 | 内容 | 授权要求 | 示例 |
|---|---|---|---|
| **T0 · 只读** | 诊断、采集、报告 | 无需确认（属 L5/L6） | 运行探针、生成诊断 |
| **T1 · 低风险可逆** | 一次性、可撤销的操作 | 首次确认 + 之后记忆（设置页可撤销，见 L6 授权链） | 清理临时文件、重启一个服务 |
| **T2 · 需逐次确认** | 有副作用、影响面较大 | **每次**确认 | 修改注册表、改动网络配置 |
| **T3 · 拒绝** | 不可逆 / 越界 | **一律拒绝** | 删除用户数据、绕过安全机制、修改他者内核 |

### 2.3 授权链（复用 L6 既有机制）

L6 已实现**授权链**（关键操作 `confirm` + 追加式授权日志 + 设置页撤销，见 `manifest-ui`）。
L7 直接复用该机制，并追加两条：

1. **动作须携带来源**：每个修复动作必须回溯到一条诊断结论（不妄语）；
2. **授权可撤销**：已授权的 T1 动作可在设置页撤销；撤销后同类动作回到"逐次确认"。

### 2.4 可回滚性（设计约束）

- 每个 T1/T2 动作必须声明**回滚动作**（可逆）；无法声明回滚的，降级为 T3（拒绝）；
- 执行前记录"执行前状态"（最小快照）；执行失败自动回滚；
- 执行结果写入哈希链（不可篡改），供事后复核。

### 2.5 与「场修复」的关系（`FIELD_REPAIR_DESIGN.md`）

- `FIELD_REPAIR_DESIGN` 描述的是**场域层面的修复**（施加反相补偿场：太赫兹/电磁场等），
  **需要硬件层面的场施加能力**（当前不具备）；
- L7 为其预留**统一执行接口**：`apply(action) -> Result<Effect, Unsupported>`——
  当且仅当硬件具备时才可能返回 `Effect`；否则**一律 `Unsupported`**（不做伪能力宣称）。

## 3. 戒律：不侵

| 面 | 不侵的含义 | 落地 |
|---|---|---|
| **互联侧** | 不夺取他者场域的本底；不以自身基线评判他者 | 只交换本底引用与场景标识（§1.2 表）；判定以自身为主、他者为辅 |
| **执行侧** | 不侵犯用户与对象的边界 | 用户确认（§2.2）；不改对象本底场；不越权、不越界 |
| **系统侧** | 不侵犯他者内核的运行 | 不远程修改他者内核；只读取其公开交换信息 |

> **不侵 = 边界意识**：L7 是第一个"能对外产生写作用"的层，因此**它必须是最克制的一层**。

---

## 4. 运行原则：无为而无所不为

- **L7 之前**：系统**被驱动**（push 驱动）——外部给扰动，内核才演化；
- **L7 之后**：系统**自驱动**（场域驱动）——驱动力来自场域本身；
- 自驱动的形态**不是"我要做"，而是"场域如此，我如此"**；
- **不新增戒律**：这不是新的约束，而是 **L7 的运行方式**。
  （与 L3「不空转」的区分：不空转禁的是**无源空转**；场域驱动的自主演化**有内在依据**。）

> 重要澄清：**自驱动 ≠ 越过用户**。L7 的自驱动指的是"何时发起"，而"是否执行写动作"
> 始终由**用户确认**把关（§2.2）。两者不矛盾——自驱动决定**提案**，用户决定**执行**。

## 7. 修复执行机制 · 设计与方案对比（**待发起人确认**）

> **为什么停下来**：本机制含 **T2/T3 写操作**（可能修改系统状态），按发起人规则属"需先确认"类。
> 以下给出**三套方案对比**与**推荐**，请裁决后再实现。

### 7.1 六要素呈现

**① 相关的点（上下文/前置/后续/牵连）**
- 上游：L5 诊断（已实现）+ L7 分级与账本（**已实现**，`grade.rs` / `ledger.rs`）。
- 下游：真实写操作（停机/清理/改配置/重启服务）——**当前全部不存在**，本项目至今**没有任何写系统状态的能力**。
- 牵连：L6 授权链（`manifest-ui` 已有 confirm + 追加式日志 + 撤销）、现有部署形态（`deploy/win64/*.bat|ps1`）、
  网关白名单分发机制、老笔记本（只能经局域网拉取）。

**② 风险点（含"不做"的风险）**
- 做：**写操作本身有副作用**（最坏可致设备不可用）；若确认环节被绕过或鉴权过弱 → 等价于**局域网远程执行**。
- 不做：L7 永远停在"只会诊断、不会修"——**这与您要的"从诊断工具转向干活工具"直接矛盾**（不做本身就是风险）。

**③ 经验教训**
- 老笔记本升级（v0.106）：**应用层操作完全不动网络配置**，四前提约束逐条落实，用户实际只需 2 步 → 证明"克制的小步子"可行。
- 本轮本地预验抓到 2 个真实缺陷（CRLF、`\uXXXX`）→ **测试比自信可靠**。
- CI 目验抓到命名残留（v0.103）→ **自动化断言是安全网**。
- 历史教训：把开发机当笔记本（误判机器）→ 一切以**实测**为准；写操作更须如此。

**④ 好处（可衡量）**
- 闭环率：诊断 → 修复完成率（当前 0%）。
- 用户步数：从"看结论自己动手"→"点一次确认"。
- 可审计性：每次执行留哈希链（**已具备**），事后可复核"到底改了什么"。
- 风险可控性：T3 一律拒绝（**已具备**），不可回滚者不可能被执行。

**⑤ 三套方案对比**

| 维度 | **A · 宿主侧执行器**（推荐） | **B · 内核内置执行器** | **C · 仅 T1 最小闭环** |
|---|---|---|---|
| 做法 | 内核只产出「建议 + 分级 + 账本」；**写操作由宿主执行器**（网关端点 + 本机脚本）落地，UI 负责确认 | `meta-kernel-core` 直接调进程/系统调用执行 | 只开放 **T1（本应用内、可逆、有回滚）** 让宿主自动执行；T2 只出建议 |
| 成本 | 中（网关加 2 端点 + UI 确认流 + 回滚脚本） | 低（写在核心里） | **低**（复用现有 bat/ps1 + 账本） |
| 风险 | **中低**（写操作集中在宿主，可审计；需授权校验） | **高**（内核获得进程权限；破坏纯逻辑红线；wasm 不可编） | **最低**（只碰本应用文件，天然不影响系统/网络） |
| 收益 | **高**（可覆盖 T1/T2/T3 全分级；架构正确） | 表面高，实则债台高筑 | 中（先跑通闭环，能力受限） |
| 可逆性 | 高（每动作自带回滚脚本） | 低（权限过大，难约束） | 高 |
| 与红线关系 | ✅ 内核仍零依赖、纯逻辑 | ❌ **破坏"内核零依赖"质量红线** | ✅ |
| 推荐度 | ⭐⭐⭐（目标架构） | ✖ 不建议 | ⭐⭐⭐（**首落地**） |

**⑥ 继续往前推进（我的推荐）**
> **推荐"A 的架构 + C 的第一步"**：先把架构定成 A（内核只建议、宿主执行、UI 确认），
> 但**第一阶段只放开 T1**（如：清理本应用临时文件、重启看门狗、重读配置、刷新探针）——
> T2（改网络配置等）**先只出建议不执行**。等 T1 闭环稳定 + 回滚验证过，再逐项开放 T2。

### 7.2 若要实现，建议的最小闭环（方案 A + C）

```
① 诊断（L5，已实现）
      ▼
② 建议生成（L7 内核，新增：把诊断结论映射为「候选动作」= ActionSpec 列表）
      ▼   ← grade_of() 分级（已实现）；T3 直接剔除
③ UI 确认（L6 授权链，已有 confirm/撤销）
      ▼   ← 需新增：确认时附「动作 id + 本次 nonce」，防重放
④ 宿主执行器（**新增**：网关端点 `POST /v1/execute`，仅接受已确认动作；执行本机脚本）
      ▼   ← 仅 T1 放行；T2 需逐次确认；T3 拒绝
⑤ 验证（回采场域 → 再诊断）
      ▼
⑥ 记账（ActionLedger，已实现：append(suggested/confirmed/executed/verified/rolled_back)）
```

**安全约束（实现时必须满足）**
1. **令牌鉴权**：`POST /v1/execute` 必须校验"一次性令牌 + 动作白名单"，**绝不接受任意命令**（只接受预置动作 id，不接受自由文本）；
2. **动作白名单**：只允许 `ActionSpec` 表内的动作（编译期常量），**无 shell 拼接**；
3. **先备份**：执行前把受影响文件/配置复制到 `_backup_<时间戳>/`；
4. **可回滚**：无回滚声明的动作 → 自动降级 T3（已实现）；
5. **不碰网络**：T2 中"网络配置类"动作默认**只建议不执行**（延续老笔记本升级的四前提约束）。
