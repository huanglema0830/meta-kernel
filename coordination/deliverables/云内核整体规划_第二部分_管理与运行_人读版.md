## 一、机制 20 升级：三层 + 加密 + 代码代号（**原文，逐条落实**）

### 1.1 最终结构（原文表）

| 层 | 放什么 | 位置 | 加密 |
|---|---|---|---|
| **公开层** | 英文名 + 编号 + 功能说明 + 指针 | 仓库内 | 无 |
| **索引层** | 编号 + 英文名 + **代码代号** + 指针 | 仓库外 | ✅ |
| **内容层** | 全拼 + 原名 + 原始内容 | 仓库外 | ✅ |

### 1.2 核心规则（原文，5 条）

1. **英文名必须是功能描述型**：禁止拼音转写（`<拼音>` ❌），禁止生僻造词。
2. **公开层保留中文功能说明**：中文读者看说明能懂。
3. **代码位置用代号**：如 `CODE-007`，真实路径只在内容层。索引层即使泄露，也不知道代码在哪。
4. **编号是稳定锚点**：换名不改编号，索引层和内容层不动。
5. **索引层不得含全拼/原名**：全拼和原名只在内容层。

### 1.3 加密方案（原文，5 条）

- **加密对象**：索引层 + 内容层（仓库外私有）。
- **加密方式**：AES-256。
- **密钥存放**：本地，与 `PRIVATE_ASSETS` 同级，**绝不进仓库**。
- **解密时机**：内部查阅时按需解密，用完即弃。
