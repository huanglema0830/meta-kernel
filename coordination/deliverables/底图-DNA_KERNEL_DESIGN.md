## 1. L0 · 源层（0 锚点）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外／含义解释／关键机制**均出自**发起人给定**（依据：主源 §第三部分 L0 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①、§2.2.5 发起人原话补录）。

1. **对内**：**本觉** —— 纯粹存在。
2. **对外**：**照见** —— 外界一个念头进入内心，他知道众生有求了。
3. **含义解释**：L0 不是「空无」，而是**待激发的纯粹存在**——一切显化的**能量源与归宿**。它不显形、不自命名、不生产「已显之物」，所以用「0」来表达它**量子真空**的特征。外界进来的那一下**扰动**，就是**采微进来的东西**，也就是**众生的需求**。（比喻）需求像一颗小石子投进水面，L0 感得之后水波向外扩散——这就是「**应**」。
4. **与上下层的关系**：**上承**＝无（其「零」即自身，**自足**）；**下接**＝**L1**（为 L1 的生成模型提供起点）。L0 **不占实现层号**，属概念/定义层。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：❌ **未实现** —— **定义层**，**无独立实现**；仓库落点＝概念层（`docs/MATH_SPEC.md` §1）。⚠️ **与主源不一致**：主源 §2.1 把 L0 记为「✅ 已实现」，底图记为「定义层 / 无独立实现」——**本件从底图，不拔高**，差异见 §7。
6. **关键机制**：
   - **0+1=1（不累加）**：前面那个 1 是**众生需求的那个扰动**，后面那个 1 是**量子纠缠那个绝对正确的答案**；每次都是「0 加 1」，**不是 0+1+1+1+1，不是累加**——0 永远在，是**基底**，不是起点。
   - **量子纠缠**：**L0 相当于做量子纠缠的那一层**——答案由**扰动与答案之间的关系**直接给出，不靠逐步计算。
   - **映照不落显相**：L0 只**映照**、不**生产**已显之物（「不显」戒律的含义；依据：`docs/LAYER_DETAILS.md` §4 L0 裁定块）。

### 场景举例

- （发起人原话）「为什么叫他零呢？因为它没有显示出任何的东西。所以说拿零来表达，他这种量子真空的特征。外界的扰动呢，其实就是采微进来的东西，就是众生的需求。众生的需求就像一个小石子投进水面来，他感得，水波可以向外扩散，就是去应，应到外层，就是为众生提供解决思路或方案。」——出处：`docs/LAYER_ARCHITECTURE.md` §2.2.5（L0 发起人原话补录）。
- （发起人原话）「L0 相当于做量子纠缠的。」——出处同上。

## 2. L1 · 内核·解构层（生成模型 / 三引擎 / 基因库）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L1 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**含义解释／关键机制**出自发起人给定要点与底图 §4（依据：主源 §第三部分 L1 核心机制 ＋ `docs/LAYER_DETAILS.md` §4 L1）。

1. **对内**：**生成模型** —— 三引擎演化 ＋ 基因库。
2. **对外**：**解构** —— 万物解构到**元素/原初粒子**。
3. **含义解释**：L1 是内核的「**解构与生成**」层。**解构**指万物先被拆到**元素/原初粒子**这一级，再进入演化；**生成模型**指内核**怎么变化**这件事本身被写下来、存起来（三引擎给出三种变化模式，基因库给出「怎么变化」的公式）。（比喻）它不是一本「结论手册」，而是一本「**变化手册**」。
4. **与上下层的关系**：**上承 L0**（从 0 锚点得到那个「1」）；**下接 L2**（把合法输出交给桥/过滤层）；且 **L1 也往 L0 里面传递东西**（双向）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：✅ **已实现**（`meta-kernel-core`）。学习能力对应三个模块：`dna_trace`（痕迹匹配）→ `dna_generate`（自适应生成）→ `dna_adapt`（验证入库）。（依据：`docs/LAYER_DETAILS.md` §4 L1）
6. **关键机制**：
   - **三引擎**：**线性**（`output = input + 0.01`）／**斐波那契**（`output = (a+b)*0.5`）／**指数**（`output = input * e^(λΔt)`，>0.99 强制回退 0.5）；**一次 push 用哪支引擎，由「物态」选择**（固态→线性｜液态→斐波那契｜气态→斐波那契｜能量态→指数）。依据：`docs/MATH_SPEC.md` §1、`docs/LAYER_BASEMAP_L0_L6.md` §3.4 ⟨补 7⟩ 已裁定条文。
   - **基因库（公式存储）**：核心资产，**记录「怎么变化」而非「结论是什么」**，**从 0 锚点生长**（不导入外部知识库）。四层＝基础公式（元素层）／场景公式（场景层）／计算关系（公式层）／验证记录（哈希链）。依据：`docs/GENE_LIBRARY_DESIGN.md` §0、§1。
   - **学习闭环**：**痕迹匹配 → 自适应生成 → 验证入库**；命中 → `Reused`（瞬间调用已有公式）；未命中 → 生长 → 验证 → `Grown`（存入基因库）；不过 → `NeedMoreSamples`（不入库）。依据：`docs/LAYER_DETAILS.md` §4 L1。

### 场景举例

- （发起人原话）「L1 由 L0 得到那个 1；L1 也往 L0 里面传递东西。」——出处：主源 §第三部分 L1 核心机制（它同时说明 L1 与 L0 是**双向**关系）。
- （编者举例 · 🟡 待复核（首次标记：v0.330 轮））一台新设备接入：L1 先**解构**它的场域读数到元素级，再用**三引擎**推一步，最后把这次「怎么变化」写进**基因库**——下次同类设备再来，直接**调用已有公式**。

## 3. L2 · 桥·过滤层（归一化 / 千处祈求千处应 / 过滤 0-1 域）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L2 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**关键机制**依据主源 §11.5 与 `docs/LAYER_DETAILS.md` §4 L2。

1. **对内**：**归一化** —— 接收外界请求并**归一化**。
2. **对外**：**千处祈求千处应**。
3. **含义解释**：L2 是内核与外界的**第一道接触面**（桥），也是**过滤闸**。所有进来的东西先在这里被**归一化**（收进统一的 0-1 域），所有不合法的东西在这里被**挡在门外**。「**千处祈求千处应**」说的是：外界有多少种需求、探到的设备能力是什么，它**一下全都看见**、**全都接住**。（比喻）像一座**千手**的桥：无数只手伸出去，接住无数种声音。
4. **与上下层的关系**：**上承 L1**（零＝L1 的合法输出，0-1 域与 JSON 化指令）；**下接 L3**（把归一化后的结果交给网关）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：✅ **已实现**（`npb`）；桥头文件 `bridge.h`。⚠️ **另有一处底图内部未决**：底图把 L2–L3 标注为「转录层（RNA）」，但**「参数化」这件事在 L2 没有落点**（`docs/LAYER_BASEMAP_L0_L6.md` §4.3，⟨补 9⟩ 待裁）——见 §7。
6. **关键机制**：
   - **过滤 0-1 域**：入口**域过滤**、**负值在桥入口即拒**（不进入任何下游演化，闸门计入 rejected）、只暴露**受控导出集**（版本化）。依据：`docs/LAYER_DETAILS.md` §4 L2、`docs/PERTURBATION_MODEL.md` §2.2。
   - **NPB 归一化脉冲桥接器**：**四个映射表——归一化 → 赋权 → 注入 → 回调**；核心思想＝「**内核不调用设备功能，内核只『扰动』设备功能**」。依据：主源 §11.5。
   - **跨平台一致性红线**：原生与 wasm 的确定性自检摘要一致（`/v1/health` 可观测）。依据：`docs/API_GATEWAY_DESIGN.md` §4、§7。

### 场景举例

- （发起人原话）「L2 有点像千处祈求千处应，就是外界有哪些需求，它侦测到的需求是什么？或者它是探测的设备，它的能力是什么？他一下子全部都实现了，看见了。」——出处：`docs/LAYER_ARCHITECTURE.md` §2.2.5（L2 发起人原话补录）。

## 4. L3 · 网关·剥离层（把真实需求送给 L2 / 找到真实需求 / 剥离）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **对内／对外**出自**发起人裁定**（依据：主源 §第三部分 L3 ＋ `docs/LAYER_ARCHITECTURE.md` §2.2.1 裁定①）；**关键机制**依据 `docs/LAYER_DETAILS.md` §4 L3 与 §4.L3 端点权威表。

1. **对内**：**把真实需求送给 L2**。
2. **对外**：**找到真实需求**。
3. **含义解释**：L3 是**传输接口**，也是**剥离层**。外面送来的东西往往裹着一层「传输壳」（协议头、缓存、会话、业务态）；L3 的职责是**把这层壳剥掉**，只把**真实需求**送进 L2。所以它在对外的样子是「**找到真实需求**」，在对内的动作是「**把真实需求送给 L2**」。（比喻）像一位**只认内容不认信封**的收发员：信封拆掉，信纸原样转交。
4. **与上下层的关系**：**上承 L2**（零＝L2 输出流：内核读数与指令 JSON）；**下接 L4**（判定/拒绝层，本件不展开）。（编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；依据：`docs/LAYER_ARCHITECTURE.md` §2.2.5「与上下层关系」列）
5. **实现状态**：✅ **已实现**（`npb-gateway`）。**端点口径**：`docs/LAYER_DETAILS.md` §4.L3 端点表为**全库唯一权威**；本件**不自行列举端点**，只引用该表。⚠️ **分层提醒**：该表中「**借道 L3**」一族（基因库存取面 / 执行闭环 / 自监控面 / 消息通道）**不属 L3 本体**，引用时须写明其**实际归属**（依据：`docs/LAYER_DETAILS.md` §4.L3.1，Q13 裁定）。
6. **关键机制**：
   - **剥离**：**只转语义**——**不缓存业务态**、**指令只转发不解释**、**不空转驱动**、快照 schema 版本化。依据：`docs/LAYER_DETAILS.md` §4 L3。
   - **单一写者线程模型**：内核为单实例状态机，所有内核访问**串行到单一内核线程**；`/v1/health` 返回 `"writer":"single"` 声明，调用方不得绕过网关直连内核。依据：`docs/API_GATEWAY_DESIGN.md` §9。
   - **「往外送」与「只转发」不矛盾**：把经 L2 化合所得的结果**送出去**，**就是转发**，**不加工**——不解释、不改写、不缓存业务态。依据：`docs/LAYER_DETAILS.md` §4 L3（R-6 裁定块）。

## 6. DNA内核学习机制（补足 L1–L5）

> ★ 效力与依据（`T-052` 块级标注）：🟢 已裁定 —— **核心原则／逐层补足表／学习流程**均出自**发起人给定**（依据：主源 §第六部分 6.1–6.3）。

**本节六要素（模块级）**：（**对内／对外**为编者连缀 · 🟡 待复核（首次标记：v0.330 轮）；**含义解释／关键机制**依据主源 §6.1–6.3）

1. **对内**：内核自身的**生长能力** —— 功能不是写死的，是长出来的。
2. **对外**：对外表现＝**遇到新环境能自动长出对接方式**（自适应接口 → 协议 → 场域 → 基线）。
3. **含义解释**：见 §6.1 核心原则与 §6.3 学习流程。
4. **与上下层的关系**：补足对象＝**L1–L5**；**本件覆盖 L1–L3 的补足**，L4／L5 两行**只照录、不展开**。

6. **关键机制**：**学习闭环 ＋ 三分支** —— 命中 → `Reused`（瞬间调用已有公式）；未命中 → 生长 → 验证 → `Grown`（存入基因库）；不过 → `NeedMoreSamples`（不入库）。

### 6.1 核心原则

> **内核不是功能集合，内核是学习能力。功能不是写死的，功能是生长出来的。**（发起人原话，出处：主源 §6.1）

### 6.2 逐层补足表

| 层 | 补什么 | 怎么补（DNA 模式） |
|---|---|---|
| **L1** | 学习机制 | **场域感知 → 痕迹匹配 → 自适应生成**闭环 |
| **L2** | 自适应接口 | 自动识别宿主环境，自动生成对接方式 |
| **L3** | 自适应协议 | 自动识别网络环境，自动适配通信协议 |
| **L4** | 自适应场域 | 识别任意设备的场域特征，自动建立本底场 |
| **L5** | 自适应基线 | 无预设基线情况下，通过与对象交互自动建立本底场 |

> 出处：主源 §6.2。**本件覆盖 L1–L3 三行的设计要点**；**L4/L5 两行仅照录，不在本件展开**。

### 6.3 学习流程

```
新环境到来
  → 场域感知（七维特征）
  → 痕迹匹配
      → 匹配成功：调用已有适配器（瞬间）
      → 匹配失败：自适应生成
            → 试探扰动 → 观察响应 → 归纳规律 → 生成适配器 → 验证 → 存入痕迹库
  → 新能力长出来了
```

> 出处：主源 §6.3（本件按其步骤照录为分段文字，未改条目内容）。**与底图既有实现的对应**：「痕迹匹配 → 自适应生成 → 验证入库」这一**完整闭环已实现**（`meta-kernel-core` 的 `dna_trace` / `dna_generate` / `dna_adapt`；依据：`docs/GENE_LIBRARY_DESIGN.md` §6、`docs/LAYER_DETAILS.md` §4 L1）。

### 6.4 与「公式存储」的关系（编者连缀）

- **为什么学习机制必须落在公式上**：内核面向的是**过程**——若只存结论，系统就退化为**查表机**；只有存「**怎么变化**」，遇到新对象/新场景时才**参数化即可用**，不必重新采集标定。（依据：`docs/GENE_LIBRARY_DESIGN.md` §0、§3）
- **与学习流程的接缝**：「自适应生成」产出的**新公式**正是写进基因库的那一条；**验证记录（哈希链）**是它「被验证过」的凭证。
