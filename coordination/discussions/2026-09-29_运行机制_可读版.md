# 云内核 · 运行机制（**大白话版**）

（`云内核-C3-038` §二 · 2026-09-29 · 配套《整体规划 第二部分：管理与运行（详尽版）》）

> **它是什么**：工程版运行机制的**人话版**。工程版讲的是"文件在哪、命令是什么、编号是多少"；这一版只讲**一件事：这个项目靠哪些规矩在跑、谁在守着这些规矩、守得灵不灵**。
> **给谁看**：想先搞懂"这套项目怎么管自己"的人。**读完这一版，再去看工程版查条文原文。**
> **和工程版什么关系**：**内容一一对应，章节顺序一致**。**两版冲突时，以工程版为准**（工程版贴着条文与实测）。
> **这一版不写什么**：不写文件路径、不写脚本名、不写命令、不写编号表。要查这些，去工程版。
> **★ 数字怎么看**：本版所有数字（规矩几条、约束几条、自动检查几支、告警几条）**都是某一时刻的快照**。真值一律**以现跑出来的为准**，工程版第十章末有"数字怎么取"的专节。

## 0 一句话先把全貌立住

**这个项目不是靠"人记着"在跑，是靠"写下来的规矩 ＋ 自动检查"在跑。规矩分硬的和软的，检查分成"提醒"和"必须改"两种，而所有规矩都有一个共同目的：不让"以为做对了"冒充"真的做对了"。**

## 1 三十二条规矩（按"管什么"分组）

| 这组管什么 | 里面是哪几条 |
|---|---|
| **现在是什么、不能碰什么** | 基准（唯一权威状态描述）、约束（硬规矩不能破） |
| **怎么说话、格式能不能改** | 模板（指令与报告的必带项）、模板活相（先试用再生效） |
| **往哪走、先做哪件** | 路线图、优先级（不用颜色，只分档） |
| **人不回话／对话断了怎么办** | 无响应推进（超时转清单，不停摆）、断裂接续（读最新状态即可恢复） |
| **留痕与安全边界** | 归档（指令／报告／讨论全部留档）、危险代码白名单（**当前为空＝一条都不放行**） |
| **怎么把活干出来、怎么不让信息出事** | 八步方法、顾问简报、顾问接续包、决策七要素、保密四级别、私有资产盘点、拆分（骨架与实现分离） |
| **怎么确认对方真读完了** | 全景阅读指令（输出第一行必放固定文本，对方按九步执行） |
| **没人的时候怎么继续推进** | 夜间自动化（按时段分档，双通道，默认不推送） |
| **对外该叫什么名字** | 术语三层映射（编号是稳定锚点，换名不改号） |
| **这件事该由谁干** | 执行体归属（需要"感知／动作"的交给外部或宿主；纯"算"的才能进内核） |
| **我读的是不是底图本身** | 源一致性（脚手架不得顶替底图） |
| **夜间这条约束管不管我** | 夜间时段例外（只管无人监督的自动化；用户在场不受限） |
| **文档列的接口，和代码里真有的是不是同一套** | 端点表一致性 |
| **文档说的状态，和机器实测的是不是同一套** | 文档一致性 |
| **这条"绿"是在哪一层取的** | 能力矩阵（本机／自动构建／模拟真机／真机，四层，**跨层引用无效**） |
| **版本号这个数从哪来** | 版本号口径（一次提交一个号，不手写） |
| **这份方法从哪进、跑哪几步** | 八步方法的"调用层"（所有动作从入口进） |
| **外部动静什么时候该变成动作** | 情报机制（采集 → 归档 → 触发 → 实施，五态单向流转） |
| **记忆应该先读多少** | 记忆三层（会话开始只读最薄的一层） |

> ★ **三十二条不是三十二张纸**：它们都写在项目的治理文件里，其中"源一致性""端点表""文档一致性"这三条**已经在自动流水线里跑起来了**。

## 2 二十一条硬约束（分"死规矩"和"活规矩"）

### 2.1 八条死规矩（不可破）

| # | 一句话 | 破了会怎样 |
|---|---|---|
| 1 | 内核**不许借外部轮子**；外层可以 | 依赖膨胀、体积变大、审计困难 |
| 2 | 版本号**永远自动取**，不许手写 | 版本混乱、无法追溯 |
| 3 | **不许用危险手法取巧**（本身无例外；真有需要走专门的边界规矩） | 隐患散落，事故难定位 |
| 4 | **改之前先出清单，确认后再动** | 不可逆损失 |
| 5 | **没做完的必须老实标出来**（分四类：本机跑过／流水线跑过／真机跑过／没验证） | 声称完成实际没完成 |
| 6 | 每次都要报**四种量**（家底／当下偏离／介入／峰值） | 信息丢失、无法复盘 |
| 7 | **不许用流水线代替真机验证** | 核心目标从来没被真正验证过 |
| 8 | 硬约束**可以新增**（提议 → 用户确认 → 生效） | 规矩固化失效 |

### 2.2 十三条活规矩（提议 → 试用三轮 → 生效或废弃）

| # | 一句话 | 为什么立它 |
|---|---|---|
| 9 | 危险手法的**合规形态**：集中放、写清理由、登记白名单 | 不给合规形态，第 3 条会被顶死（要么破规矩、要么做不了） |
| 10 | **不可逆／对外可见的动作，必须用户点头**（发布、换后端、公开可见……） | 事后收不回来 |
| 11 | 给决策**必须给全七要素**（评估／优势／劣势／风险／机会／建议／等待决策） | 防止给建议的人替用户做决定 |
| 12 | **四级别保密**；最高一级**绝不外传** | 防泄密 |
| 13 | 输出第一行必放**阅读指令**，对方按九步执行 | 防止漏读、选择性阅读 |
| 14 | 夜间分时段；**默认不推送** | 利用低成本时段又不停摆 |
| 15 | **编号表编辑纪律**：改前取数、改后复算、差值须对得上 | 已复发过 5 次"追加却替换了既有行"⇒ **会静默丢行** |
| 16 | 凡断言"不存在"，**必须给四要素**（检索式／范围／命中数／阳性对照） | 曾有一轮只查一份就下"全库"结论，把前一轮的三条结论推翻 |
| 17 | 诚信类指控**必须列全 ＋ 双方原文各引一行**；举证不足就降级为"存疑" | 冤枉底图＝**不可逆污染** |
| 18 | 自动检查的**自检必须和真跑同源** | 曾出现"自检全绿、真跑判红"的假绿 |
| 19 | **同一个机器事实只许有一种算法** | 曾有两个检查对同一事实算出相反结论 |
| 20 | **流水线结论不入库**（只记日报；仓库侧只放复核命令） | 提交→触发→写结论→再提交，**没有不动点** |
| 21 | 版本号口径唯一（不许以"夜间／只出稿"为由排除某次提交） | 曾出现持续十四条的一致偏移 |

> ★ **第 20 条特别值得记住**：它不是"懒得记"，是**结构性无限**——每记一次就再生一个待记的。**所以仓库里只放"怎么查"的命令，不放结论本身。**

## 3 对外名字（十四个术语）

对外只用**编号 ＋ 英文名 ＋ 一句话中文说明**。英文名必须是**描述功能**的（不许拼音、不许生僻词）。

> ★★ **编号是稳定锚点：换名不改号。** 这样即使对外改了叫法，内部追溯也不会断。

十四项里，前五项已经进入"换名字试点"（把原名换成功能描述型英文名，编号不变）；后九项**仍在对外层，按对外层写法引用即可**。

其中最后一项（八步方法论）与两条规矩挂钩：一条管它的**本体**，一条管**所有动作必须从入口进**。

## 4 一天的节奏，以及谁干什么

### 4.1 三个时段

| 时段 | 规则 |
|---|---|
| **09:00–21:00 前台** | 用户在场，指令正常执行；推送须**当轮明示** |
| **21:00–23:00 过渡** | 先出"今夜清单"，这段时间可以调清单 |
| **23:00–08:00 全自动** | **只跑不需要人点头的活**，默认**不推送** |

**夜间走两条通道**：需要人判断的活走平台定时任务；纯机器的活（检查、扫描、构建）走自动流水线。

> ⚠️ **默认不推送**：夜间产出次日由用户一句话放行。另有例外规矩：**用户在场的指令会话不受夜间时段限制**。

### 4.2 三方分工

| 角色 | 干什么 |
|---|---|
| **发起人（用户）** | 审成果、答问题、明示放行 |
| **执行方** | 自主执行、出报告、跑检查 |
| **外部顾问** | 审方案、出接续包、给下一步指令 |

**收工四步**：① 跑完全部检查 → ② 出当轮报告 → ③ 更新台账与记忆 → ④ 提交，等推送明示。

## 5 报告十四项，和阅读指令九步

**报告十四项**（第 0 项是字面第一行）：
0 阅读指令｜① 保密标记｜② 全景状态卡｜③ 任务（含读了底图哪几份哪几行）｜④ 状态｜⑤ 验收对照（每条标准都要有实测结果）｜⑥ 未完成项｜⑦ 真实缺陷｜⑧ 四种量｜⑨ 边界说明（四类）｜⑩ 决策七要素｜⑪ 待裁清单｜⑫ 下一步建议｜⑬ 启动回执。

**阅读指令九步**：① 全读不跳读 → ② 核状态卡 → ③ 核保密标记 → ④ 核验收对照 → ⑤ 核边界说明 → ⑥ 核四量 → ⑦ 核决策七要素 → ⑧ 出审核结论（通过／部分通过／驳回）＋ 下一步指令 → ⑨ **用自己的话复述"用户这次真正要的是什么"**，据此复核第 ⑧ 步是不是对准了目标。**复述不出来，就是没读到位。**

## 6 记忆三层（防止一上来就读太多）

| 层 | 大小 | 职责 | 什么时候读 |
|---|---|---|---|
| **调用层** | 很小（不到 1 KB） | 最核心的几条铁律 ＋ 指针 | **会话开始必读** |
| **索引层** | 中等（不到 4 KB） | 分类索引（编号 ＋ 一句话 ＋ 指向） | 按需 |
| **内容层** | 不限 | 条文原文（**只增不改**） | 按需 |

> ⚠️ **效力的边界**：这一条的自动检查**只在本机全检**，在自动流水线上会降级为提醒——因为**工作区记忆不在仓库里**。这是"本机绿不等于到处绿"那条教训的直接后果。

## 7 自动检查：十九支，以及两条铁纪律

### 7.1 先推送，再动文件

> **推送之后，必须等流水线显示"跑完了"，并且逐个任务看过三态，才动文件。** 拿到"可以改了"的信号才进入编写阶段。

### 7.2 十九支自动检查

**现状（快照）**：**十九支，全部都进了自动流水线**。其中**十一支是"只提醒"**——退出码永远为 0，不拦人；**这些提醒的数量必须另外去读输出**，不能只看"通过"。

| 检查什么 | 状态 |
|---|---|
| 硬约束里的"不存在"断言与诚信指控，有没有给证据 | **只提醒** |
| 对话链的可见级别 | **只提醒** |
| 文档说的状态和机器实测是否一致 | 判红（必须改） |
| 效力列（已裁定／待裁定）有没有过期 | **只提醒** |
| 接口表和代码是否同一套 | 判红 |
| 公开层不许写真路径 | **只提醒** |
| 编号表有没有静默丢行 | **只提醒** |
| 指令件该有的项全不全 | **只提醒** |
| 检查本身有没有缺口（防止"有判定、没动作"） | **只提醒** |
| 内核纯度（有没有偷借外部轮子／危险手法） | 判红 |
| 记忆三层 | **只提醒** |
| 迁移的封闭性与保真度 | 判红 |
| 指针门禁（骨架与实现是否真的分离） | 判红 |
| 输出第一行阅读指令 | 判红 |
| 报告结构 | **只提醒** |
| 底图回写五段流水线留痕 | **只提醒** |
| 源一致性（读的是不是底图本身） | 判红 |
| 轮次号 | **只提醒** |

**一条命令跑全部**（列出命令用 `--list`，自检用 `--selftest`——具体命令去工程版查）。

### 7.3 流水线结论不入库

① 只记日报；② 仓库侧**只放复核命令**；③ **不为"记一次流水线结果"再提交一次**。

> ★★ **最容易被漏的一条**：**"通过"不等于"提醒为零"。** 十一支只提醒的检查，**必须逐支读输出**——只看总退出码会把提醒全漏掉。这条是**真吃过亏**才写下来的。

## 8 保密四级别，与"换名字"

| 级别 | 含义 | 怎么处置 |
|---|---|---|
| **公开** | 可直接给 | 直接给 |
| **半公开** | 抽象后可用 | 抽象后给 |
| **保密** | 屏蔽后可用 | 屏蔽后给 |
| **机密** | **绝不出现** | **绝不外传** |

**换名字怎么换**：对外层（编号＋英文名＋说明）→ 索引层（加代码代号，**不许含原名**）→ 内容层（原名，仓库外加密）。**编号是稳定锚点。**

> ⚠️ **不可逆**：密钥丢了 ＝ 私有层永久读不出来。**删明文必须用户放行。**

**骨架与实现分离**：骨架层（公开，写"做什么"）／实现层（仓库外，写"怎么做"）**物理分开**。私有文件夹是**仓库根目录的兄弟目录**，靠结构隔离，**不靠忽略清单**。

## 9 后加的两条规矩

### 9.1 对话链可见性（第三十一条）

**一句话**：按"接收方是内部还是外部"给每条对话链定可见级别，并规定**产出物逐件分级**（直接拷／可拷／屏蔽后拷／绝不拷）。

**为什么**：跨链内容外发时容易**整篇给出去**——原来有分级，但缺一个"链级"的总登记。

### 9.2 夜跑与自动化的分界（第三十二条，含红线）

**一句话**：**"需不需要人点头"是唯一分界线。**

- **夜跑** ＝ 下过指令之后的运行，**可以先出草稿，白天再来确认**。
- **自动化** ＝ **完全不需要决策、不需要认可**的，才做自动化。

> ★★ **红线**：**凡是会改仓库状态的，必须走夜跑（出草稿等确认），不许自动化。**

**"改仓库状态"怎么算**：只要写进了被版本管理的文件就算（含提交、流水线配置、治理件、底图，**也含往报告和讨论目录里写**）；**只写仓库外的记忆文件不算**。**这条红线优先于其它一切特征。**

**执行三步**：① 先判"改不改仓库状态"（改 ⇒ 恒为夜跑）→ ② 不改 ⇒ 再判"需不需要人点头" → ③ 归类进当轮报告；**要调整归类须用户裁定**。

**与相邻规矩的分工**：夜间规矩管**时段**与**默认不推送**；时段例外规矩管**这条约束管不管我**；本规矩在来源之上**再辨"要不要人点头"**。

**追溯适用**：立规之前那些没经白天确认的自动提交，**须补白天确认**。

## 11 数字怎么取（避免"以为没变其实变了"）

| 想知道 | 去哪取真值 |
|---|---|
| 规矩有几条 | 治理文件里的机制表 |
| 硬约束有几条 | 约束文件（编号只增不改） |
| 对外术语有几条 | 术语文件 |
| 自动检查有几支、几支只提醒、提醒几条 | **跑一次全量检查，并逐支读输出** |
| 检查进没进流水线 | 在流水线配置里查得到该检查名，才算"进了" |
| 版本号 | 一条命令现取（不许手写、不许推算） |
| 流水线结果 | **按"不入库"规矩：只记日报，仓库侧只放复核命令** |

> ★★ **最重要的一条**：**文档里写的数字会滞后**（曾出现"文档写十一支，实测十九支"）。所以**凡是要拿来做判断的数字，一律现跑现取**；文档里的数字只当**那个时点的快照**看。
