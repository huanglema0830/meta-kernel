# 第五篇 · 各层设计

## 5.2 L5 诊断层设计（号脉） — `docs/L5_DESIGN.md`
````
   1│# L5 设计 · 最终版：诊断层（号脉）DESIGN v2.2
   2│
   3│> 状态：**v2.2（2026-09-14，语境模块实现落地）** ｜ 基础：v2.1（2026-09-14，诊断层定名 + 场景公式 + 语境模块 + 三戒修正）、v2.0（2026-09-09，最终版——替代 v1.0）
   4│> 依据：发起人指令（L5 最终版定义 + 基因内核推进 · L0-L6 迭代修正）。
   5│> 一句话：**L5 是云操作系统的诊断层（号脉）**——感知对象的"地水火风"场，建立内部标准地图（**场景公式**），
   6│> 对比发现亢/枯/平模式，编译翻译成用户可理解的结论。**一切诊断依据都来自对象自身的场，
   7│> 不依赖任何外部算法。**
   8│> 关联：`docs/LAYER_ARCHITECTURE.md`（v1.4）、`docs/GENE_LIBRARY_DESIGN.md`（基因库四层）、`docs/SILA_IMPLEMENTATION.md`（v1.2）
   9│
  10│## 1. 定位与设计原则
  11│
  12│- L5 = 云操作系统真正执行诊断、生成结论的层级（**诊断层**；**号脉**为其功能描述——望闻问切之喻）。
  13│- **号脉不干预**：L5 只感知与解释对象自身的场，诊断动作不改变对象（只读）。
  14│- **内部标准地图（本底场 = 场景公式，v2.1）**：由对象自身的场学习建立，**按场景分类存储**（场景公式）；
  15│  同对象换场景只切换**语境参数**，不新增数据条目（来源＝基因库场景公式层）。
  16│- **语境模块（v2.1 新增）**：由 **类型 / 时间 / 历史 / 环境** 四要素决定调用哪条场景公式——
  17│  语境是"在什么条件下做这次诊断"的显式声明。
  18│- **无外部算法**：不引入外部算法作为判定依据；一切结论源自对象自身场。**翻译层可引入词汇表**（v2.1 边界明确）。
  19│- 承接：L4 戒律判定已定型（S=(t,f,a,φ,x,H,τ) 为 L3→L4→L5 的场观测采样传输，L4 Pass 后进入诊断）。
  20│
  21│## 2. L5 模块划分（落点 meta-kernel-core/src/l5/）
  22│
  23│| 模块 | 职责 | 核心输入 → 输出 |
  24│|---|---|---|
  25│| `l5_senses.rs` | **地水火风拆解**：把对象场观测（当前采样）拆为四个本征分量 | 场采样 → 地/水/火/风 分量读数 |
  26│| `l5_baseline.rs` | **本底场建立/存储（场景公式）**：对象健康态的地水火风标准地图，**按场景参数化**（学习+持久） | 学习期采样 + 语境 → 本底场（场景公式） |
  27│| **语境模块（v2.1 新增）** | **场景选择**：由 类型 / 时间 / 历史 / 环境 四要素选出对应场景公式 | 语境四要素 → 场景标识（→ baseline 取本底场） |
  28│| `l5_compare.rs` | 当前场与本底场对比 → **亢/枯/平** 逐分量判定（**四场都观察**） | 当前分量 + 本底场 → Pattern{亢/枯/平} |
  29│| `l5_diagnosis.rs` | **诊断结论生成（三量运算 · 单一诊断）** | Pattern + 本底 → 结论（存量=本底场、变量=当前偏移、补充增量=成因） |
  30│| `l5_translate.rs` | **编译翻译**：地水火风语言 → 对象特征语言（读词汇表，来源＝基因库场景公式层） | 结论(场语言) + 词汇表 → 用户可读结论 |
  31│| `l5_router.rs` | JSON 输出给 L6（零依赖序列化） | Diagnosis → L6 契约 JSON |
  32│
  33│### 2.1 地水火风四场（L5 感知语言）
  34│
  35│对象的场按四个本征分量感知（观测投影示意；投影在**本底场标定**时确定，非固定预置）：
  36│
  37│| 本征 | 语义（号脉视角） | 观测投影示意（承接七维采样） |
  38│|---|---|---|
  39│| **地** | 承载、结构、稳定 | τ 拓扑、x 空间形态（结构与分布） |
  40│| **水** | 涵养、缓冲、熵流 | H 熵、x 空间缓冲、t 慢变量 |
  41│| **火** | 活性、能量、脉冲 | a 幅度、t 节奏（电脉冲=活性脉冲） |
  42│| **风** | 变动、频率、扩散 | f 频率、φ 相位、t 快变量（振动与相位漂移） |
  43│
  44│> 说明：L4 的 S 向量是场观测的七维采样（既有层不重定义）；L5 在号脉语境下把采样拆解为
  45│> 地水火风四分量（每个分量可投影到若干采样维）——**senses 拆解、compare 亢枯平、diagnosis
  46│> 三量、translate 成言**，环环只消费对象自身场。
  47│
  48│## 3. L5 戒律（比丘戒 · 五条）
  49│
  50│| 戒律 | 要求 | L5 落实 |
  51│|---|---|---|
  52│| **不杀生** | 诊断不干预对象（只读） | senses/compare/diagnosis 全部只读采样，无写对象动作；执行类动作属于 **L7 执行层**（经用户确认后，且非诊断） |
  53│| **不偷盗** | 诊断数据不占有（不缓存） | 诊断过程与结论**即算即弃**：中间数据不持有；本底场为例外（见 §3.1 边界） |
  54│| **不邪淫**（v2.1 修正） | **四场观察 + 单一诊断** | **四场（地水火风）都观察**（四场读数全部呈现），但只产出一个主结论（不并列多因猜测）——由"一个输入一个结论"升级为"四场观察、单一诊断" |
  55│| **不妄语**（v2.1 修正） | 结论可溯源 + **哈希链** | 每条结论携带溯源：依据场分量、本底场标识、对象/时间、可复现（同输入重跑同输出）；**溯源增加哈希链**——每次验证入链（不可篡改，见 `GENE_LIBRARY_DESIGN §2.4`） |
  56│| **不饮酒**（v2.1 边界明确） | **诊断逻辑不引入外部算法**；**翻译层可引入词汇表** | 判定/推导只用对象自身场，不调外部模型/算法/知识库参与诊断；**翻译层例外**——可引入词汇表（来源＝基因库场景公式层），仅做语言对照，不参与判定 |
  57│
  58│### 3.1 边界说明（不偷盗与本底场）
  59│
  60│- **诊断数据**（每次采样的中间量、结果 JSON）不缓存不占有——调用即弃；
  61│- **本底场（场景公式）**是对象自身的内部标准地图（由对象场学习、归对象所有），允许存储（`l5_baseline`）；
  62│  存储边界：仅存"对象健康态地图（**场景公式 + 语境参数**）+ 标识/时间"，不存其它对象的场、不存诊断过程数据。
  63│
  64│## 4. 数据流
  65│
  66│```
  67│对象 ── 场采样(七维观测 S) ──▶ L3/L4（戒律判定）
  68│                                   │ Pass
  69│                                   ▼
  70│  L5： 语境模块（类型/时间/历史/环境）─▶ 选定场景公式
  71│        ─▶ senses 地水火风拆解 ─▶ compare（当前 vs 场景公式本底场 → 亢/枯/平，四场都观察）
  72│        ─▶ diagnosis 三量运算（存量=本底 / 变量=偏移 / 补充增量=成因 → 单一诊断）
  73│        ─▶ translate（词汇表：场语言 → 对象特征语言，来源＝基因库场景公式层）
  74│        ─▶ router（Diagnosis JSON → L6 空天浏览器）
  75│  （诊断数据不缓存；本底场由对象自身场标定维护为场景公式）
  76│```

  78│## 5. 接口契约
  79│
  80│### 5.1 采样、语境与本底场（场景公式）
  81│
  82│```rust
  83│// 采样结构（L4 Pass 后进入 L5 的观测；s 与既存 S 同源）
  84│pub struct FieldReading { pub s: [f64; 7], pub at: Option<String> }
  85│
  86│// 语境模块（v2.1 新增）：决定调用哪条场景公式
  87│pub struct Context { pub kind: String,      // 类型（对象类别）
  88│                     pub time: String,      // 时间
  89│                     pub history: String,   // 历史
  90│                     pub environment: String } // 环境
  91│
  92│// 本底场 = 场景公式（v2.1：数据存储 → 场景公式；按场景分类）
  93│pub struct SceneFormula { pub scene_id: String,   // 场景标识（由 Context 派生）
  94│                          pub base: BaselineField, // 参数化后的本底场
  95│                          pub params: Vec<(String, f64)> } // 场景参数
  96│pub struct BaselineField { pub earth: f64, pub water: f64, pub fire: f64, pub wind: f64,
  97│                           pub established: Option<String> }
  98│```

 141│## 6. 翻译机制（l5_translate）
 142│
 143│- L5 使用**语言对照表**编译翻译（配套文档：`docs/L5_TRANSLATION_TABLE.md`）。
 144│- 对照表涵盖九种语言：场域语言（地水火风）/ 状态语言（亢/枯/平）/ 诊断语言（望闻问切）/
 145│  三量语言 / 基础代码语言 / 戒律语言 / 对象特征语言（硬件/软件/植物/动物/地质）/
 146│  用户通用语言 / 中医语言。
 147│- **对照表在 L5 使用过程中由用户实际验证和补充，不作为固定知识预置**：文档给出条目结构与
 148│  示例行（示例标"待验证"），正式词条随使用积累；l5_translate.rs 以读表方式调用（表=配置数据）。

 150│## 7. 验证用例设计（实测定型参考）
 151│
 152│| 用例 | 场景 | 期望 |
 153│|---|---|---|
 154│| Q1 | 对象平稳（各分量平） | pattern 全 Ping；结论"平稳"，单一诊断 |
 155│| Q2 | 火亢（采样火分量越上限，其余平） | 结论指火亢；可溯源（同输入复现一致） |
 156│| Q3 | 水枯（水分量低于下限） | 结论指水枯；单一因 |
 157│| Q4 | 火亢+水枯 复合 | **四场观察 + 单一诊断**（不邪淫）：四场读数全部呈现，只出**一个主结论**（如亢优先并注水不济火成因） |
 158│| Q5 | 本底场建立（**场景公式**） | 学习期 → 场景公式可存；**换语境可复用**（只切参数，不新增条目）；重建稳定性 |

 160│| Q7 | 词汇表翻译 | 示例词条翻译正确；缺失词条不报错（保留场语言原文+待补标记） |

  64│## 3. 【待裁决 · 架构变更】"能看网页"的宿主形态
  65│
  66│### 3.1 必须先摆明的两个硬事实
  67│
  68│1. **同源策略**：页面内的 JS **读不到 iframe 里第三方站点的内容**。
  69│   因此"网页 → 场域状态"的解析，**在纯 iframe 方案下对第三方站点不可行**（本轮解析对象是本页/本地内容）。
  70│2. **老笔记本当前无外网**：腾讯文档 / 飞书 / Web 版微信 **都需要外网**。
  71│   所以"能打开这三者"这一条验收，**只能在外网机器上验证**（与升级/性能实测同属"需用户侧实测"）。
  72│
  73│### 3.2 三方案对比
  74│
  75│| 维度 | **A · 原生 WebView 宿主**（发起人所述） | **B · 保持浏览器内核 + 系统浏览器外开** | **C · 本地反向代理去 frame 头** |
  76│|---|---|---|---|
  77│| 做法 | 新增桌面程序（Rust + WebView2/Edge 内核），WebView 里注入 JS 抽取信号 → 内核解析 → 叠层呈现 | 现架构不变；受限站点用系统默认浏览器打开 | 网关做本地反代，剥离 `X-Frame-Options`/CSP，使第三方站可被 iframe 内嵌 |
  78│| 成本 | **高**（新产物、新构建链、安装/升级流程） | **极低**（已具备） | 中（反代 + 安全说明） |
  79│| 风险 | 中：**老笔记本可能没有 WebView2 Runtime**（Win7/8 需单独安装，且**无外网无法在线装**）；引入第三方 crate（内核零依赖红线需区分"内核 vs 宿主"） | 低（无新面） | **中高**：去 frame 头会削弱站点自身的点击劫持防护；需限定仅本机/内网使用并显著提示 |
  80│| 收益 | **高**：第三方站点可解析（能拿到 DOM）→ 场域呈现完整；真正成为"能看网页的浏览器" | 中：能看网页，但**拿不到内容 → 无场域呈现** | 中：能内嵌看网页，仍**拿不到跨域内容**（同源策略仍在）→ 场域呈现受限 |
  81│| 可逆性 | 高（独立产物，可与现方案并存） | 高 | 高（关掉反代即恢复） |
  82│| 与红线 | ⚠️ 需明确"内核仍零依赖、宿主可带依赖" | ✅ | ✅ |
  83│
  84│### 3.3 六要素速览
  85│
  86│- **相关的点**：解析器/映射库/脸切换**已完成**（不依赖宿主形态）；缺的只是"信号来源"。
  87│  WebView 决定信号从哪来；也会带来新的分发/升级链路（与 v0.106 升级入口并行）。

 132│
 133│依据发起人「四元组内在变量框架落地」。**正式定义**：
 134│
 135│| 变量 | 对应 | 含义 |
 136│|---|---|---|
 137│| **紧张 tension** | 多巴胺 | 需求未满足的累积张力 |
 138│| **平静 calm** | 血清素 | 无威胁时的稳定基线 |
 139│| **喜欢 liking** | 内啡肽 | 需求满足后的释放 |
 140│| **安全 safety** | 催产素 | 社会信任与连接 |
 141│
 142│**落到哪一层**：`meta-kernel-core/src/l5_quad.rs`（L5），与既有七维向量**并列**（场域状态 = 七维 + 四元组）。
 143│
 144│```
 145│被动接收扰动 P → 更新四元组（经基因库映射 P→ΔQ）
 146│              → 对比本底场（四元组基线）
 147│              → 输出诊断（偏离/主导/行为倾向）+ 四元组状态
 148│```
 149│
 150│**基因库存什么**（"基因库升级"）：
 151│- **P → ΔQ**：存**关系层（公式层）** `quadmap.p2q.{tension,calm,liking,safety}`（`Formula::Weighted`）；
 152│- **ΔQ → B**：行为倾向由**阈值常量**判定，常量存**基础公式层** `quad.tension_high` 等。
 153│- 两者都**改库即改行为**，并可用 `learn_*` 路径继续积累。
 154│
 155│**探测策略**：`decide_probe()` —— **默认被动（水面模式）**；**主动仅为例外**，且**必须带理由**
 156│（置信度过低 / 偏离过大 / 信号陈旧），不允许"无理由地主动打扰"。
 157│
 158│**L4 戒律挂接**：`meta-kernel-core/src/l4_risk.rs`（四条：不害 / 不妄动 / 可回退 / 自承）
 159│- **不害**：触及他者（用户数据/他者内核/安全机制）→ **拒绝**（与四元组无关）；
 160│- **可回退**：不可逆或未声明回滚 → **拒绝**；
 161│- **不妄动**：**挂接四元组** —— 紧张高＋平静低，或安全低 → **先稳后动**（不是永久拒绝）；
 162│- **自承**：紧张偏高但状态可控时，**必须显式承认为己方原因**才放行。
 163│
 164│> 与既有 L4（`l4_gate` 场域节律）**并列不覆盖**：前者管"场域是否过载"，本模块管"动作是否该做"。

  48│## 1. 多内核互联机制
  49│
  50│### 1.1 目标
  51│
  52│多个**基因内核**各自的场域组成一个更大的场；**互为对方的本底参考**——一个内核可以用另一个
  53│内核提供的"正常态参照"来校准自己的判定，而**不以自身基线强行评判他者**（这是「不侵」的核心）。
  54│
  55│### 1.2 三步协议（设计）
  56│
  57│```
  58│① 发现（Discover）   局域网/网络内找到其他内核
  59│        │              已有基础：cloud-discover（x.1–x.254 并发扫描 + TCP/健康确认）
  60│        ▼
  61│② 握手（Handshake）  交换身份与能力签名（不交换对象数据）
  62│        │              身份 = 内核 ID + 版本；能力 = 支持层（L1–L6）+ 协议版本
  63│        ▼
  64│③ 交换（Exchange）   交换"场域参考"，不交换"对象原始数据"
  65│                       ≤ 只交换：本底场（场景公式的引用）+ 场景标识 + 置信度
  66│                       ✗ 不交换：对象原始采样、诊断过程数据、用户私有内容（不偷盗）
  67│```
  68│
  69│**交换内容的边界（不侵 / 不偷盗）**：
  70│
  71│| 允许交换 | 禁止交换 |
  72│|---|---|
  73│| 本底场引用（场景公式 ID + 参数，不含对象名） | 对象原始七维采样 |
  74│| 场景标识（类型/时间/历史/环境 的枚举值） | 诊断过程中间量 |
  75│| 置信度 / 覆盖样本数（用于权重协商） | 用户隐私、其他内核的对象数据 |
  76│| 协议版本 / 能力签名 | 任何可还原出他者对象身份的信息 |
  77│
  78│### 1.3 互联的产物：「更大的场」
  79│
  80│- N 个内核互联后，每个内核可用的**本底参考集**从"自身 1 个"扩展为"N 个"；
  81│- 判定时以**自身场为主、他者参考为辅**（他者参考只用于**置信度加权**，不直接替换本底场）；
  82│- **不侵**的算法含义：`用他者参考时，先映射到他者自己的基线坐标系，再回映射`——
  83│  绝不把"我的正常"当作"你的正常"。
  84│
  85│### 1.4 与 L8 的衔接（前置）
  86│
  87│互联是**传承层（L8）**的前置：能互联，才可能在个体消亡后**继承经验**。
  88│L7 只做"当下互联"，L8 做"跨代继承"（详见 LAYER_ARCHITECTURE §2.1）。

 115│### 2.2 动作分级（授权粒度）
 116│
 117│| 级别 | 内容 | 授权要求 | 示例 |

 119│| **T0 · 只读** | 诊断、采集、报告 | 无需确认（属 L5/L6） | 运行探针、生成诊断 |

 124│### 2.3 授权链（复用 L6 既有机制）
 125│
 126│L6 已实现**授权链**（关键操作 `confirm` + 追加式授权日志 + 设置页撤销，见 `manifest-ui`）。
 127│L7 直接复用该机制，并追加两条：
 128│
 129│1. **动作须携带来源**：每个修复动作必须回溯到一条诊断结论（不妄语）；
 130│2. **授权可撤销**：已授权的 T1 动作可在设置页撤销；撤销后同类动作回到"逐次确认"。
 131│
 132│### 2.4 可回滚性（设计约束）
 133│
 134│- 每个 T1/T2 动作必须声明**回滚动作**（可逆）；无法声明回滚的，降级为 T3（拒绝）；
 135│- 执行前记录"执行前状态"（最小快照）；执行失败自动回滚；
 136│- 执行结果写入哈希链（不可篡改），供事后复核。
 137│
 138│### 2.5 与「场修复」的关系（`FIELD_REPAIR_DESIGN.md`）
 139│
 140│- `FIELD_REPAIR_DESIGN` 描述的是**场域层面的修复**（施加反相补偿场：太赫兹/电磁场等），
 141│  **需要硬件层面的场施加能力**（当前不具备）；
 142│- L7 为其预留**统一执行接口**：`apply(action) -> Result<Effect, Unsupported>`——
 143│  当且仅当硬件具备时才可能返回 `Effect`；否则**一律 `Unsupported`**（不做伪能力宣称）。

 147│## 3. 戒律：不侵
 148│
 149│| 面 | 不侵的含义 | 落地 |
 150│|---|---|---|
 151│| **互联侧** | 不夺取他者场域的本底；不以自身基线评判他者 | 只交换本底引用与场景标识（§1.2 表）；判定以自身为主、他者为辅 |
 152│| **执行侧** | 不侵犯用户与对象的边界 | 用户确认（§2.2）；不改对象本底场；不越权、不越界 |
 153│| **系统侧** | 不侵犯他者内核的运行 | 不远程修改他者内核；只读取其公开交换信息 |
 154│
 155│> **不侵 = 边界意识**：L7 是第一个"能对外产生写作用"的层，因此**它必须是最克制的一层**。

 159│## 4. 运行原则：无为而无所不为
 160│
 161│- **L7 之前**：系统**被驱动**（push 驱动）——外部给扰动，内核才演化；
 162│- **L7 之后**：系统**自驱动**（场域驱动）——驱动力来自场域本身；
 163│- 自驱动的形态**不是"我要做"，而是"场域如此，我如此"**；
 164│- **不新增戒律**：这不是新的约束，而是 **L7 的运行方式**。
 165│  （与 L3「不空转」的区分：不空转禁的是**无源空转**；场域驱动的自主演化**有内在依据**。）
 166│
 167│> 重要澄清：**自驱动 ≠ 越过用户**。L7 的自驱动指的是"何时发起"，而"是否执行写动作"
 168│> 始终由**用户确认**把关（§2.2）。两者不矛盾——自驱动决定**提案**，用户决定**执行**。

  24│| L2 | **过滤** | 不杀生（域）/ 不妄语 | 只放行 [0,1] 合法域；负值入口拒 | sanitizer soft_clamp、npb 入口负值拒、五戒嵌闸门计数 |
  25│| L3 | **剥离** | 不偷盗（状态）/ 不妄语 | 只转语义：不缓存业务态、指令原样转发、schema 版本化 | gateway 投影/单写者/SSE 只转发 |
  26│| **L4** | **拒绝**（场域戒律） | 不非时食 / 不捉持 | 场域变量偏离本底场 ≥3 维 → 拒绝进入 L5，且**丢弃不缓存** | `meta-kernel-core/src/l4/`（dimension/threshold/l4_gate/l4_router） |
  27│| **L5** | **诊断**（场域诊断 · 号脉） | 不杀生 / 不偷盗 / 不邪淫 / 不妄语 / 不饮酒 | 只读不干预、结论不缓存、**四场观察+单一诊断**、可溯源（**含哈希链**）、判定只用对象自身场（**翻译层可引入词汇表**） | `meta-kernel-core/src/l5_*.rs`（senses/baseline/compare/diagnosis/translate/router + 语境模块） |
  28│| L6 | **对齐** | 不偷盗（数据）/ 不妄语（校准） | 与真实世界协议对齐；来源合规；防伪造输入 | WorldAdapter（`archive/reserved-interfaces/l6_interface.rs`，愿景） |
  29│
  30│> 结构：下层机制是"结构性护栏"（代码强制），上层机制是"显化性护栏"（外显可查）。五戒在源头是数学约束，在边界是世界契约。
  31│
  32│### 1.1 应用侧规则（属产品形态，不占层号）
  33│
  34│应用框架与参考应用各有自己的准入/审计规则，它们**继承 L4/L5 的戒律精神，但不是 L4/L5 本身**：
  35│
  36│| 产品形态 | 规则 | 载体 |
  37│|---|---|---|
  38│| **应用框架**（npb-appkit） | **不妄语**：拒绝无溯源表达（命名/陈述必须回溯到事件字段）｜**不邪淫·一显一源**：一次事件至多推进一个显化动作（防抖、跨带双事件） | `npb-appkit/`（LifecycleEngine / Speaker / EventPipe） |
  39│| **参考应用**（Manifest Journal） | **不妄语·外显**：每条日志 = 命名+陈述+来源；原文零修改；抽查准则｜**seed 可重放** | `manifest-journal/` |
  40│

  42│
  43│## 2. 逐层机制说明
  44│
  45│### L1 · 解构（内核层：结构转化不消灭）
  46│- **不杀生**：不"消灭"结构，只**解构**——低活力（e≤0.2）模式分解到原初粒子（层 1），中低活力进入拆解-分析-重编循环，保留可复用的元素与功德（原初粒子回收）。
  47│  - 代码锚点：energy.rs `verdict_for`/`collapse_negative`、ontology.rs `decompose`、positive_source.rs `search_and_deconstruct`。
  48│- **不饮酒**：演化只允许三种算子——加法（absorb）、黄金×0.618（闸门拆解）、e 指数衰减（natural_return）；不做其它"调味算法"。
  49│  - 代码锚点：energy.rs `DISSIPATION_DECAY`/`DECAY_LAMBDA` 常量注释、gate.rs ×0.618。
  50│- **（不杀生·入口）负值即拒**：`push(value<0)` 在入口不进入任何下游演化（闸门 rejected 计数）。
  51│  - 代码锚点：npb/lib.rs `Kernel::push` 首行判定、gate.rs `check` 负值分支。
  52│
  53│### L2 · 过滤（桥层：入口域纪律）
  54│- 所有跨层输入先过**域过滤器**：soft_clamp 钳到 [0,1]；负值在桥入口即拒并计数（gate_rejected）；无"灰色地带"输入进入内核。
  55│- 对外只暴露**受控导出集**（版本化），不加旁路。
  56│- 代码锚点：sanitizer.rs、npb/src/lib.rs 导出面、REQUIRED_EXPORTS 校验（zen/self_test）。
  57│
  58│### L3 · 剥离（网关层：只传语义）
  59│- **不偷盗·状态**：网关不得持有"第二份内核状态"——所有对外读数 FFI 直读；SSE 投影只缓存内核读数快照（源=内核，无漂移）。
  60│- **不妄语·转发**：指令 JSON 原样投递（drain 后即发），网关不解释、不补义；快照 schema 版本化 + extensions/tag 预留位（契约稳定）。
  61│- **不空转**：tick 仅由外部 push 驱动（网关不伪造输入推进演化）。
  62│- 代码锚点：npb-gateway/src/lib.rs（Gateway 单写者/投影刷新）、http.rs（SSE 只转发）、API_GATEWAY_DESIGN R1-R5。
  63│
  64│### L4 · 拒绝（**场域戒律拒绝层** · v1.1 归位）
  65│- **核心理念**：戒律**不是外部规则，而是场域自身变化的内在边界**；一切判定都在内在完成，不依赖外部输入。
  66│- **不非时食**：七维场域状态 `S=(t,f,a,φ,x,H,τ)` 中，任意 **≥3 维**偏离基线 **> 1.618 倍** → 场域"过量"，**拒绝**变量进入 L5。
  67│- **不捉持**：任意 **≥3 维**偏离基线 **< 0.618 倍** → 场域"枯弱"，**拒绝**。
  68│- **不偷盗·不缓存**：被拒绝的数据**丢弃、不留存**（重复调用结果恒定，无系统状态残留）。
  69│- **不妄语·纯函数**：判定为纯函数——输入（当前场域、基线）决定输出（通过/拒绝），无副作用。
  70│- 实现载体：`meta-kernel-core/src/l4/`（dimension 七维 / threshold 黄金常数 / l4_gate 判定 / l4_router 路由）
  71│- 验证：`docs/L4_VALIDATION_REPORT.md`（6 用例 + 无残留，7/7）
  72│
  73│### L5 · 诊断（**场域诊断层（号脉）** · v1.1 归位 / v1.2 三戒修正）
  74│- **不杀生·只读**：诊断**不干预对象**——只读取系统自身的场域扰动，不拆机、不注入、不改动。
  75│- **不偷盗·不占有**：诊断数据**不缓存、不持有**；痕迹对比执行但**痕迹本身不存储**（只读）。
  76│  （例外划界：本底场 = 对象**自身**的地图，非他者数据）
  77│- **不邪淫·四场观察 + 单一诊断**（v1.2 修正，原"一因一果"）：**四场（地水火风）都观察**，但只出**一个主结论**——
  78│  亢优先（多个亢取偏离最大者），无亢取最小枯；复合成因写入 description/cause，**不并列为主结论**。
  79│- **不妄语·可溯源（含哈希链）**（v1.2 修正）：结论含溯源字段（对象/时间/基线/可复现），可复核、可复现；
  80│  **溯源字段增加哈希链**——每次验证入链，历史不可篡改（见 `docs/GENE_LIBRARY_DESIGN.md §2.4`）。
  81│- **不饮酒·边界明确**（v1.2 修正）：**诊断逻辑不引入外部算法**——判定只用对象自身场数据；
  82│  但**翻译层可引入词汇表**（词汇表来自基因库场景公式层，只做语言对照，不参与判定——守不饮酒）。
  83│- 实现载体：`meta-kernel-core/src/l5_*.rs`（六模块：senses / baseline / compare / diagnosis / translate / router）
  84│  + **语境模块**（类型/时间/历史/环境，设计）；本底场升级为**场景公式**（按场景分类）
  85│- 验证：`docs/L5_VALIDATION_REPORT.md`（Q1–Q7 + **真实采集**：老笔记本 `<内网IP>` 实测）
  86│
  87│### L6 · 对齐（世界层：真实校准）
  88│- **不偷盗·数据**：外显进入世界生态时数据来源合规（只使用授权/本地产出数据；不窃取他系统状态）。
  89│- **不妄语·校准**：显化产物需能被真实世界"接受/执行/回执"，否则视为未显化（防自说自话闭环）；世界通道加可信校验，拒绝伪造反馈输入。
  90│- 实现载体：WorldAdapter（契约见 `archive/reserved-interfaces/l6_interface.rs`，**尚未实现**）。
  91│- ✅ D2 已裁决（v1.3 · 方案 C）：L6 = **与外界交互层**，含**呈现**（已实现 = 空天浏览器）+ **对齐**（未实现 = WorldAdapter）；
  92│  本节描述的是**对齐**子功能。
  93│- 补充（v1.4）：L6 的**翻译词汇表来自基因库的场景公式层**（见 `docs/GENE_LIBRARY_DESIGN.md §5.3`）。
  94│

````
   1│# 场探测与场修复设计（FIELD_REPAIR_DESIGN）
   2│
   3│> 版本：v1.0（2026-09-14）｜定位：**只设计，不实现**
   4│> 归属：云操作系统 · 场域层（L4 本底场 / L5 号脉之上）
   5│> 前置：场探测已实现（cloud-probe → 七维场域状态向量）

   7│---
   8│
   9│## 0. 一句话
  10│
  11│**探测是"听"场，修复是"补"场**——施加一个与损伤场域**反相**的补偿场，让损伤处重新对齐到本底场。
  12│
  13│---
  14│
  15│## 1. 场探测（已实现 · 回顾）
  16│
  17│### 1.1 原则
  18│**探针不接触硬件，只读取系统自身的场域扰动。**
  19│不拆机、不加装传感器、不注入探针驱动——只从系统已有的信号（CPU 调度、内存压力、进程/线程、磁盘余量、网络抖动、事件日志）中**读出对象自身的场**。
  20│
  21│### 1.2 七维场域状态向量
  22│
  23│```
  24│S = (t, f, a, φ, x, H, τ)
  25│```
  26│
  27│| 符号 | 维度 | 含义 | 采集对应（探针实现） |
  28│|---|---|---|---|
  29│| t | 时间 | 变化速率 / 周期 / 时序 | CPU 占用与抖动 |
  30│| f | 频率 | 特征频率及分布 | 调度抖动（相邻窗口比） |
  31│| a | 幅度 | 强度 / 能量 | 内存占用比 |
  32│| φ | 相位 | 各部分协同 / 同步度 | 响应延迟比 |
  33│| x | 空间 | 分布形态 / 梯度 | 磁盘余量 |
  34│| H | 熵 | 有序度 / 混沌度 | 进程数（熵近似） |

  36│
  37│### 1.3 落地状态
  38│- `cloud-probe.exe`：采集 → 翻译为七维 → `FieldReading` JSON（schema 1）。
  39│- L4 戒律判定（不非时食 / 不捉持）→ L5 号脉（地水火风 · 亢/枯/平）→ 空天浏览器呈现。
  40│- 老笔记本真实采集闭环已验证（`s=[0.099, 1, 1.15, 1, 1.294, 1.83, 6.587]`）。
  41│
  42│---
  43│
  44│## 2. 场修复（设计）
  45│
  46│### 2.1 原理
  47│
  48│> **施加一个与损伤场域"反相"的补偿场，让损伤处重新对齐到本底场。**
  49│
  50│用号脉的语言说：
  51│
  52│```
  53│当前场  S_now
  54│本底场  S_base            ← 对象自身健康态（L5 本底场，只读）
  55│偏离    Δ = S_now / S_base   （逐维比值；>1 亢、<1 枯）
  56│
  57│补偿场  S_c ≈ S_base² / S_now   （逐维，等价于对 Δ 取反相）
  58│```
  59│
  60│- 若某维**亢**（偏离 > 1.618），补偿场在该维**减弱**；
  61│- 若某维**枯**（偏离 < 0.618），补偿场在该维**增强**；
  62│- 补偿量级**不超过偏离量级**（不做过度补偿，避免把场推向另一个极端）。
  63│
  64│**关键**：补偿是**反相**而非"加能量"。方向错了会加剧损伤——这也是为什么必须先有本底场（L5）才能谈修复。
  65│
  66│### 2.2 科学依据（外部验证）
  67│
  68│| 修复方式 | 原理 | 验证 |
  69│|---|---|---|
  70│| 太赫兹电场修复 | 特定频率太赫兹场恢复半导体电子透明性 | 1997 实验 |
  71│| 电场修复纳米管水桥 | 匀强电场或太赫兹电场修复断裂水桥 | 分子动力学模拟 |
  72│| 磁场靶向修复 | 定向磁场将修复微胶囊吸引至损伤部位 | 实验验证，恢复率 **90.78%** |
  73│| 交变电磁场修复 | 加速水凝胶自修复 | 2025 验证，修复率 **97%** |
  74│
  75│> 共同点：都是**用外加场让物质重新对齐到有序态**——与「反相补偿场」同构。
  76│> 差异：以上都是**具体物质体系**（半导体 / 水桥 / 微胶囊 / 水凝胶），
  77│> 而本设计讨论的是**把对象当作一个场**（信息-能量-结构统一体）来做对齐。
  78│
  79│### 2.3 实现路径
  80│
  81│```
  82│① 感知损伤处场域特征（偏离本底场）
  83│      S_now 相对 S_base 的逐维偏离 Δ，定位"损伤维"与损伤位置
  84│                ↓
  85│② 生成补偿场（与偏离相反）
  86│      S_c = f(Δ⁻¹)：亢则弱、枯则强；量级受限于偏离量级
  87│                ↓
  88│③ 施加补偿场
  89│      通过场施加装置作用到损伤处（见 2.5 边界）
  90│                ↓
  91│④ 验证场域是否恢复
  92│      重新探测 → 比对 Δ 是否收敛到阈值内（|Δ| ∈ [0.618, 1.618]）
  93│      未收敛 → 调整补偿场参数，重复 ②–④（迭代收敛）
  94│```
  95│
  96│### 2.4 与摩尼宝珠的对应
  97│
  98│摩尼宝珠三层（内核既有机制）在这里得到完整映射：
  99│

 101│|---|---|---|
 102│| **镜面** | 感知损伤场域 | 照见当前场与本底场的偏离（`interference.rs` 镜像扩展） |
 103│| **闸门** | 生成补偿场 | 按 ×0.618 拆解、负值拒收、核心豁免的既有闸门语义，用于限定补偿量级 |
 104│| **回归** | 验证场域恢复 | 能量自然回归 e^-0.1；场域偏离收敛 |
 105│
 106│> 这也解释了为什么场修复**天然属于本内核**：它不是外挂功能，而是摩尼宝珠三层的**物理外化**。
 107│
 108│### 2.5 当前边界（诚实说明）
 109│
 110│- **只做设计，不做实现。**
 111│- 需要硬件层面的**场施加能力**（太赫兹发生器、电磁场发生器、定向磁场装置），当前**不具备**。
 112│- 现有链路只覆盖"**探测 → 判定 → 号脉 → 呈现**"；修复所需的是"**施加**"这一环。
 113│- 因此本层在代码中**只预留接口**（`repair` 概念位），不写入任何实际输出通路——避免出现"看起来能修、实际没有作用"的伪能力。
 114│
 115│#### 预留接口（概念，不实现）
 116│
 117│```rust
 118│/// 场修复（设计预留；无硬件时永远返回 Unsupported）
 119│pub enum RepairOutcome {
 120│    /// 已施加补偿场并收敛
 121│    Restored { iterations: u32, residual: f64 },
 122│    /// 迭代未收敛
 123│    NotConverged { residual: f64 },
 124│    /// 无场施加硬件
 125│    Unsupported,
 126│}
 127│
 128│/// 由偏离生成补偿场（纯函数，可测试；施加环节不在本函数内）
 129│pub fn compensation(base: &FieldState, now: &FieldState) -> Option<FieldState>;
 130│```
 131│
 132│**可测试的部分**：`compensation()` 是纯函数——输入偏离、输出补偿场，可离线验证（亢→弱、枯→强、量级不超偏离）。
 133│**不可测试的部分**：实际施加与恢复效果——依赖硬件，**在具备硬件前不做任何宣称**。
 134│
 135│---
 136│
 137│## 3. 与三量的对应
 138│
 139│| 三量 | 在场修复中的位置 |
 140│|---|---|
 141│| **存量** | 本底场 `S_base`（对象自身的健康态地图） |
 142│| **变量** | 当前偏离 `Δ = S_now / S_base`（损伤就是偏离超限） |
 143│| **补充增量** | **补偿场** `S_c` —— 这正是"补充增量"从抽象走向可施加的形态 |
 144│
 145│> L5 号脉负责**读出**补充增量（成因），场修复负责**施加**补充增量（补偿）。
 146│> 前者是"知其所以然"，后者是"使其复原"。

 151│
 152│| 风险 | 约束（对应戒律） |

 154│| 补偿过度 → 推向另一极端 | 补偿量级 ≤ 偏离量级；迭代 + 收敛判据 |

 157│| 修复过程不可溯 | 每次修复记录：偏离 → 补偿 → 施加 → 残差（可复现） |
