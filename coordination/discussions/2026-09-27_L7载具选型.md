## 〇、一句话

**A-1「存活」要求"持续运行 24h 不崩"**；而 **L7 当前没有自己的进程**（全仓仅 `npb` 与引导内核有 `bin`）⇒ **"选载具"＝决定"谁来承载这 24 小时"**。
★ **本轮实测的一个关键事实改变了三选项的代价对比**：**唯一现成的宿主 `host/field-render` 是 GUI 程序、且刻意不进 workspace、CI 不构建它** ⇒ **载-乙 的代价被显著高估过**。

## 一、① 三选项复核（**可行性 / 代价 / 风险**，事实均为本轮实测）

### 载-甲 · **仓库外脚本持续运行 L7**

| 维度 | 内容 |
|---|---|
| **做法** | 在**仓库外**写一个脚本（链接 `meta-kernel-core`），**循环驱动 L7**（如周期性 `append` ＋ 定期读数）并**把读数落盘到仓库外**留证目录 |
| **可行性** | ✅ **高** —— `lib` 已导出（`lib.rs` 第 61 行 `pub mod l7;`）、`ActionLedger` 读数接口**现成**（`len()`／`verify()`／`head()`）｜**与 `T-078` 的"仓库外留证"先例同法** |
| **代价** | 小-中：**需写一个仓库外脚本**（★ **新增会持续执行的动作 ⇒ 触 `C10`，须用户确认**）＋ **需定"被观测实体"** |
| **风险** | ★★ **语义偏离（最大风险）** —— 它测的是「**库被驱动时不崩**」，**不是「系统自持」**；`T-095` §七-① 已明写此风险 |
| **仓库内影响** | **零**（脚本与留证均在仓库外 ⇒ 按 `§二十四 24.4` **不算改仓库状态**、**不触红线**） |

### 载-乙 · **宿主执行器承载 L7**

| 维度 | 内容 |
|---|---|
| **做法** | 用现有宿主（`host/field-render` 或 `host/sky-browser`）承载 L7 运行 |
| ★ **本轮实测事实** | ① `host/field-render` ＝ **场域呈现器**（**wgpu 23 ＋ winit 0.30 ＋ egui**，**GUI 程序**，`main.rs` 有 `fn main()`）｜② ★ **它的 `Cargo.toml` 首行明写「刻意不并入根 workspace」**（理由：**wgpu/winit 会让 CI 的 Linux 构建失败**）｜③ ★ **它当前不引用 L7**（全仓 `grep l7::` 仅命中 `l7/` 自身与**裸机引导内核**的迁移断言） |
| **可行性** | ⚠️ **中-低** —— 需**改造宿主**（加 L7 驱动）＋ ★ **需无头化**（GUI 程序不能直接当 24h 守护进程） |
| **代价** | ★ **高**：改宿主代码（**触 `C10`**）＋ 无头化改造 ＋ ★ **它不在 CI 覆盖内**（⇒ 改动**无 CI 兜底**） |
| **风险** | ★ **引入外部驱动** ⇒ 与 A-1 定义「**无外部输入**下的维持」**可能冲突**（`T-093` 已列） |
| **仓库内影响** | ★ **中**（改宿源代码 ⇒ **真改仓库状态** ⇒ **须走夜跑确认**） |

### 载-丙 · **单测间断跑**（分钟级 · **已固化**）

| 维度 | 内容 |
|---|---|
| **做法** | `cargo test -p meta-kernel-core --lib l7::`（**`T-100` 已固化**：命令 ＋ 4 检查点 ＋ 37 passed 基线） |
| **可行性** | ✅ **已实测通过**（`C3-023`：**37 passed / 0 failed / 50.9 秒**） |
| **代价** | ★ **最低**（一条命令） |
| **风险** | ★★ **能力上限明确**：**间断观测不能证「连续 24h 不崩」** ⇒ 按 `T-095` §五分流，**最多只能得「待定」** |
| **仓库内影响** | **零**（`target/` 已被 `.gitignore` 忽略；实测工作区 0 行） |

## 二、② 推荐（**用户本轮允许推荐**）

### ★★ 推荐：**载-甲（仓库外脚本）** 作为 24h 观测载体，**载-丙作为开跑前的通道自检**

### 2.1 推荐理由（三条，逐条对齐 A-1 要件）

| # | 理由 | 对齐 |
|---|---|---|
| **1** | ★ **唯一能真正满足"持续运行 24h"的选项** —— 载-丙**能力上限只到"待定"**；载-乙需先做高代价改造 | A-1 的**时长要件** |
| **2** | ★ **零侵入仓库** —— 脚本与留证**均在仓库外** ⇒ 按 `§二十四 24.4` **不算改仓库状态**、**不触机制 32 红线**、**无需走夜跑确认**；★ **`T-078` 已给出同法先例**（补丁落仓库外同级目录，**已实证 1 夜**） | **机制 32 红线** ＋ **可逆性** |
| **3** | ★ **与已固化的载-丙形成"两级流程"** —— 载-丙验**通道**（37 passed）⇒ 载-甲跑**时长**（24h）⇒ 分工清晰、**互不替代** | `T-095` 的 **`P-2`／`P-6`** 前置 |

### 2.2 ★ 必须一并解决的前置（**否则载-甲也开不了跑**）

| # | 前置 | 说明 |
|---|---|---|
| **前置-1** | ★ **定义"被观测实体"** | 即 `T-095` 的 **`P-1`** —— **"什么叫 L7 在跑？"** 载-甲 的脚本驱动什么、读数取什么，**取决于此**。（**此问不决，任何载具都缺一环**） |
| **前置-2** | ★ **明确"脚本自身"是否触 `C10`** | 脚本**在仓库外**、**不改仓库状态**，但它是**"新增会持续执行的动作"** ⇒ ★ **建议仍按 `C10` 报用户确认**（**保守**） |
| **前置-3** | ★ **探针扰动幅度** | `T-095` §七-② 记：**现有 L7 代码中未发现独立心跳/探针机制** ⇒ 若 S3 需要"另一路存活证据"，**探针需新造**（复杂度取决于前置-1） |

### 2.3 ★ 为什么**不**推荐载-乙（如实列出，供你否决我的推荐）

- ★ **它不在 CI 覆盖内**（`Cargo.toml` 明写"刻意不并入根 workspace"） ⇒ **改了它无 CI 兜底**；
- ★ **它是 GUI 程序** ⇒ 24h 守护需**无头化改造**（**额外工作量 + 额外风险**）；
- ★ **它当前不引用 L7** ⇒ 等于**从零接入**；
- ★ **引入外部驱动** ⇒ 与 A-1 定义（**无外部输入**）**存在语义冲突**。

> ★ **但载-乙有一个长期优势（如实登记）**：它最接近"**系统真的在跑**"（而非"库被驱动"）⇒ ★ **建议将其留作将来"真实系统自持"的候选**（**待无头化问题解决后**）。
