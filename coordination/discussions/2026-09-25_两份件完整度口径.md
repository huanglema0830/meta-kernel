## 一、① 设计图（技术与产品）**完成标准**

### 1.1 逐层四要素（**L0–L10 每层必须齐备**）

| # | 要素                   | 判定问句            | 判定方式                               |
| - | -------------------- | --------------- | ---------------------------------- |
| 1 | **它是什么**（定义）         | 用一句话说清该层的本质     | 层节内存在定义句                           |
| 2 | **给谁供血**（输出到哪层）      | 该层产物交给哪一层／哪个消费者 | 层节内写明下游                            |
| 3 | **靠什么律在跑**（机制／约束编号）  | 该层受哪些机制／硬约束管辖   | 层节内**带编号**（机制 n／C n）               |
| 4 | **代码落点在哪**（可查的文件／模块） | 能否从该层**直接查到实现** | 给出**仓库内相对路径**（可 `git ls-files` 验证） |

### 1.2 外加：**规格映射层**（从设计推到代码的桥）

| 项           | 要求                                           |
| ----------- | -------------------------------------------- |
| **形式**      | 一张**层 → 实现落点 → 判据／验证通道**的表                   |
| **必须可核**    | 每条落点须为**仓库内真实路径**（本轮以 `git ls-files` 实测为准）   |
| **必须标缺口**   | 无落点的层**显式标注"未找到落点（实测）"**，不得留空                |
| **判据列**     | 该层对应的 `check_*.py` 与 CI job（若有）              |
| **★ 达成的标志** | 读者能**仅凭本件**定位到每一层的实现与验证入口 ⇒ **"设计图 → 代码"可达** |

### 1.3 判定表（"设计图是否做完"）

| 判定           | 条件                                                   |
| ------------ | ---------------------------------------------------- |
| **做完（D-完成）** | L0–L10 **每层四要素齐备** ＋ **规格映射层存在且落点可核**                |
| **未做完（D-半）** | 层节存在但**缺"代码落点"或"对应编号"**                              |
| **未做完（D-缺）** | 存在 ❓／△ 章节（如量子层仅 △、4 处 ❓）——**不影响"是否做完"的判定，但须在件内显式标注** |

## 二、② 运行机制（管理与运行）**完成标准**

| # | 标准                          | 判定方式（**机器可核**）                                              |
| - | --------------------------- | ----------------------------------------------------------- |
| 1 | **机制 31／32 全含**（含红线）        | 件内机制清单的**最大编号 == `CHARTER` 实测机制数**（当前 **32**）               |
| 2 | **判据 16 全同步**（编号、名称、是否入 CI） | 件内判据数 == `coordination/tools/check_*.py` **实测数**（当前 **16**） |
| 3 | **`T` 登记体系有独立章**            | 件内存在章节列出登记体系（现至 **`T-085`**，且**随轮增长**）                      |
| 4 | **固定相项数同步**                 | 与 `TEMPLATES §〇` 一致（当前 **指令十一必带**）                          |
| 5 | **C1–C21 全含**               | 件内 C 清单的最大编号 == `CONSTRAINTS` 实测（当前 **C21**）                |

**★ 关键设计取舍（写清）**：标准 1–5 中，**1／2／4／5 都是"件与权威源一致"型**，而权威源**会随轮增长** ⇒ 该件**天然会老化**。因此**完成标准里应含第六条**：

| #     | 标准             | 判定方式                                           |
| ----- | -------------- | ---------------------------------------------- |
| **6** | **件内标明"截至时点"** | 件首写明"截至 `count = N`；已知缺口 M 项" ⇒ **读者不会误当永久完整** |

## 三、判定用法（"什么叫做完"的操作化）

```text
设计图：D-完成  ⇔  L0–L10 四要素齐备 且 规格映射层落点可核
运行机制：M-完成 ⇔ 标准 1–5 全满足 且 标准 6（截至时点）已标
```

- **若只想"可交付"**（不求永久完整）：**D-完成 ＋ M-完成（含标准 6）** 即可输出，**缺口以"截至时点 ＋ 已知缺口"随件标注**。
- **若想"长期不漂"**：另需**自动抽取通道**（对应盘点稿选项 乙／D，**涉新增脚本 ⇒ `C10` 须用户确认**）——**本稿不预设**。
