## 二、机器化判据 · **候选设计**（本轮**只设计，不实现**）

> 命名（拟）：`check_external_changes.py`（**只告警**，`rc` 恒 0 —— 与现有"只告警类 8 项"同族）

### 2.1 判据一：**非计划改动检测**（提交前／CI 内）

| 项 | 设计 |
|---|---|
| **输入** | ① **快照**（上一步 `mtime` 快照，含 mtime ＋ 哈希）② **本轮"计划改动面"清单**（由当轮会话给出）③ 当前工作区状态 |
| **判定** | 若存在"**工作区已改 但不在计划改动面内**"的文件 ⇒ **告警**（列出路径 ＋ mtime ＋ 与快照的差异） |
| **输出** | `告警：n 项非计划改动`（逐项列） |
| **正反对照（自检）** | 正例：只有计划内文件被改 ⇒ 0 告警｜反例：注入一处未知改动 ⇒ 1 告警｜对照：空仓 ⇒ 0 告警 |
| **不判红的理由** | 与 `check_id_set_diff`／`check_report_structure` 同族 —— **"非计划改动"可能是合法的**（如你或平台做的），**判红会误伤** ⇒ **只告警 + 人工裁** |

### 2.2 判据二：**mtime 倒挂检测**（可选，轮初）

| 项 | 设计 |
|---|---|
| **判定** | 对"关键文件集合"，若某文件 **mtime 晚于 `HEAD` 的提交时间**，但**内容与 `HEAD` 一致** ⇒ **告警**（说明"被改后又被还原/被无内容改写"） |
| **价值** | 正是本轮 **`C3-020` 的盲区**（mtime 被覆盖 ⇒ 无法反推） |
| **限制** | git 不存 mtime ⇒ **需外部快照**（故判据二**强依赖机制①**） |

### 2.3 落地前置（**须用户确认**）

| # | 前置 | 说明 |
|---|---|---|
| 1 | **新增脚本** ⇒ **触 `C10`** | 是否允许新增 `coordination/tools/check_external_changes.py` |
| 2 | 是否入 CI | 入 CI ⇒ 增加一个**只告警**项（**噪声** ↑）／只在会话内跑（**不入库**） |
| 3 | 快照落点 | 仓库外（荐）／仓库内（**会改仓库状态**） |
