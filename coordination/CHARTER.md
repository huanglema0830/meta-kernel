# 云内核项目 · 宪章（CHARTER）

> **本文件是项目全部机制的「总入口」。**
> 每次对话开始，先读本文件（看全貌）→ 再按 §六 顺序读其余文件（看细节）。
> 目的：让三方（用户 / 顾问 / WorkBuddy）**每次会话都拿得到全图**，避免"分批下指令 → 只见局部 → 重复踩坑"。
> 本文件本身也是活的，变更规则见 §七。

## 一、项目定位

**一句话**：在现有操作系统之上生长的「**意识补充层**」——不替代、不淘汰现有系统。

- 项目总名 ＝ **云内核项目**。
- 本仓库 ＝ **元内核系统**（内核层／OS层／浏览器层／大模型四件套）。
- 项目根（唯一权威仓库）：`研发开发/tmp_a45_review/gh_clone2`。
- 版本号口径：**`git rev-list --count HEAD`**（自动生成，任何人不得手写"当前版本"，见 C2）。

## 二、命名体系

两族并行：**电信号**（当前实现）与 **量子**（设计）。

| 版本 | 系统名 | 内核层 | 操作系统层 | 浏览器层 | 大模型 |
|---|---|---|---|---|---|
| 电信号 | 元内核系统 | 基因内核 | 云操作系统 | 空天浏览器 | 云海大模型 |
| 量子 | 量子云系统 | 量子钟 | 正源操作系统 | 正源浏览器 | 采微大模型 |

- 统一输入法：**彩虹输入法**。
- 层号：L4＝场域戒律拒绝｜L5＝场域诊断｜L6＝与外界交互（呈现＝空天浏览器）｜**L7＝执行层**｜**L8–L10＝推演层（🔒冻结）**。
- ⚠️「元内核」只作**系统名**；**不触碰**「正源场域／正源库／正源系统」。
- 已废止：空海浏览器／云内核大模型／量子模式内核／DNA内核／号脉层。**产品形态名不占层号。**

## 三、三方角色

| 角色 | 职责 |
|---|---|
| **用户** | 决策、验证、传递（拿主意、看效果、在顾问与 WorkBuddy 之间传话） |
| **顾问** | 转译方向、审核方案、整理讨论（把用户意图转成可执行指令；审 WorkBuddy 的方案） |
| **WorkBuddy** | 执行、调研、报告（读全 coordination/ → 干活 → 按模板出报告 → 归档） |

协作纪律：
- **顾问下指令必须按指令模板**（§四·模板机制），一次说全，不挤牙膏。
- **WorkBuddy 出报告必须按报告模板**，未完成项与边界说明必须如实（C5）。
- **用户不需要记住任何机制细节**——机制在文件里，WorkBuddy 每轮自读。

## 四、全部机制清单

| # | 机制 | 文件位置 | 一句话说明 |
|---|---|---|---|
| 1 | 基准机制 | `BASELINE.md` | 项目当前状态的**唯一权威描述**，每版本更新（记「最后更新于 HEAD xxx」） |
| 2 | 约束机制 | `CONSTRAINTS.md` | 硬约束清单 C1–C9，不可破；破了必须在报告里说明 |
| 3 | 模板机制 | `TEMPLATES.md` | 指令模板（五话术/八必带）+ 报告模板（七话术/十一必带） |
| 4 | 模板活相机制 | `TEMPLATES_CHANGELOG.md` + `OBSERVATIONS.md` | 模板本体可提议、试用、调整、撤销；变更与观察各自落账 |
| 5 | 路线图机制 | `ROADMAP.md` | 三阶段总行动路线图 + 里程碑 + 设备梯队 |
| 6 | 优先级机制 | `TEMPLATES.md` §优先级 | P0–P4 分级；P3 无需决策可自主推进 |
| 7 | 无响应推进机制 | `TEMPLATES.md` §无响应 | P1/P2 超 4h 无响应 → 转 P3 清单，**不中断、不停摆** |
| 8 | 断裂接续机制 | `TEMPLATES.md` §接续 | 任何一方断裂后，读 coordination/ 最新状态即可快速恢复 |
| 9 | 归档机制 | `instructions/` `reports/` `discussions/` | 指令、报告、讨论**全部归档**，不靠对话记忆存活 |
| 10 | unsafe 白名单机制 | `unsafe_whitelist.txt` | C9 门禁白名单（当前为空＝不放行任何真实 unsafe） |

> **机制之间的关系**：1–2 定义「现在是什么、不能碰什么」；3–4 定义「怎么说话、说话格式能不能改」；
> 5–6 定义「往哪走、先做哪件」；7–8 定义「人不回话/对话断了怎么办」；9–10 定义「留痕与安全边界」。

## 五、硬规则速查（一句话版，全文见 `CONSTRAINTS.md`）

| 编号 | 规则 | 一句话 |
|---|---|---|
| C1 | 内核零依赖 | `meta-kernel-core` 不引任何外部 crate（宿主侧可带依赖） |
| C2 | 版本号自动生成 | 「当前版本」＝`git rev-list --count HEAD`；代码/配置/提交信息里不得手写 |
| C3 | 不用 unsafe 取巧代码 | C3 自身**无例外**；阶段二所需的边界型 unsafe 走 C9 |
| C4 | 改前先列清单 | 涉及代码改动，先出清单、确认后执行 |
| C5 | 诚实标注未完成项 | 报告须区分"本地跑过 / CI过 / 真实跑过 / 未验证" |
| C6 | 每次报告带三量台账 | 存量 / 变量 / 补充增量 / 创新增量 |
| C7 | 不用 CI 通过代替真实运行 | CI 只是构建门；关键功能必须真实环境验证 |
| C8 | 硬约束可扩充 | 调研中发现新约束可提议，用户确认后生效 |
| C9 | unsafe 边界形态 | 仅允许边界集中 + `// SAFETY:` 论证 + 禁 transmute + 白名单登记 |

**四条最容易被"打绿"绕过的纪律**（重点盯）：
1. **绝不靠调参/改阈值打绿**（断言必须打在真实语义上）。
2. **绝不用 CI 通过冒充真实运行**（C7）。
3. **绝不把未验证的说成已验证**（C5）。
4. **绝不手写当前版本号**（C2）。

## 六、启动引导（每次对话开始，按顺序读）

1. **`CHARTER.md`（本文件）** — 看全貌、看机制清单、看硬规则
2. `BASELINE.md` — 看当前状态（唯一权威）
3. `CONSTRAINTS.md` — 看约束全文（C1–C9）
4. `TEMPLATES.md` — 看模板（指令/报告/优先级/无响应/接续）
5. `ROADMAP.md` — 看路线（当前处于哪个阶段/子任务）
6. `instructions/` **最新文件** — 看本轮任务
7. `reports/` **最新文件** — 看最近报告（上轮结论与未完成项）

**报告结束时必须**（四步归档）：
1. 更新 `BASELINE.md`（版本变了就更新）；
2. 报告归档到 `reports/`；
3. 指令归档到 `instructions/`（如果本轮是指令触发的）；
4. 有讨论记录则归档到 `discussions/`。

**接续话术**（任何一方断裂时直接用）：
> 继续云内核项目。读 coordination/ 下的最新状态。
> 告诉我：当前到哪一步、下一步是什么、需要我决策什么。

## 七、变更机制（本宪章自己也是活的）

- **新增机制** → 写入 `TEMPLATES_CHANGELOG.md` → **试用 3 轮** → 正式加入本文件 §四。
- **调整机制** → 先在 `OBSERVATIONS.md` 记录观察（为什么不够用）→ 改 `TEMPLATES.md` → 在 CHANGELOG 登记。
- **撤销机制** → 在本文件标注「已废弃」→ **3 轮后移除**（不立刻删，避免误撤）。
- **约束变更** → 走 C8；C 编号**只增不改**（改了要留旧号说明，避免历史报告指错）。
- **本文件本身**：新增/撤销机制时同步更新 §四、§五、§六 三处，保持"总入口"不过期。
